# 活动抽奖模式需求基线

## Scope

在活动模板现有“开奖”模式之外，新增“抽奖”模式。目标交付仓库为 `backend` 和 `admin`，由 backend 提供用户端 app-api，admin 提供模板配置和期次管理界面。本期不修改 `miniapp`，也不负责客户端接入。

## Confirmed business rules

- 模式名称为“开奖”和“抽奖”，默认模式为“开奖”。
- “开奖”模式保留开奖时间，继续支持定时开奖和后台手动开奖。
- “抽奖”模式不需要开奖时间；用户报名成功且期次已开放报名后即可调用 app-api 即时抽奖。
- 即时抽奖接口以期次 `registrationOpen` 字段为唯一开放依据；报名起止时间仅用于前台展示及自动触发开放报名。
- 报名接口和抽奖接口分离，报名成功不会自动消耗抽奖次数。
- 每次抽奖消耗一次机会，并直接返回本次中奖或未中奖结果。
- `singleWinner=true` 时，已中奖用户仍可继续抽奖，但只能中奖一次；后续抽奖仍消耗次数并返回未中奖。
- 每个奖品在“抽奖”模式下配置百分比概率，精确到两位小数。
- 奖品概率合计不要求等于 100%，不足部分为未中奖概率，合计不得超过 100%。
- 奖品数量耗尽后仍允许抽奖；本次消耗次数并返回未中奖，不改投其他奖品。
- 抽奖请求需要客户端 `requestId`，相同用户、期次和请求号重试时返回第一次结果，不重复消耗次数或生成中奖记录。
- 中奖记录、兑奖、中奖通知和中奖公示沿用现有流程。

## Acceptance criteria

1. 新建模板默认显示“开奖”模式；历史模板和历史期次行为不变。
2. “抽奖”模式保存时不要求开奖时间，奖品概率校验正确；“开奖”模式继续校验开奖时间。
3. 生成期次后，模式、概率、奖品数量和奖品规则均从期次快照读取，模板后续修改不影响已生成期次。
4. 报名未开放、未报名、次数耗尽和非抽奖模式调用即时抽奖接口时，不消耗次数；报名起止时间不直接拦截即时抽奖。
5. 中奖、未中奖、库存耗尽和已达到单人中奖限制均返回可区分的成功结果及次数信息。
6. 并发请求不能超发库存或重复消耗次数；幂等重试返回原始结果。
7. “开奖”模式仍能由定时任务和后台接口正常完成统一开奖；“抽奖”模式不会被定时任务或后台开奖接口处理。
