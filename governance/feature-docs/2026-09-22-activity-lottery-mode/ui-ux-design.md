# 活动抽奖模式后台交互设计

## 1. 模板表单

### 抽奖模式

在活动模板基础信息中增加“活动模式”单选项：

- 开奖（默认）：报名结束后按开奖时间统一开奖。
- 抽奖：报名成功后，用户在报名窗口内即时抽奖。

切换模式时展示模式说明，避免运营人员将“开奖时间”误认为即时抽奖触发时间。

### 时间配置

- 开奖模式：显示并要求填写“开奖时间”，保留现有时间校验提示。
- 抽奖模式：隐藏“开奖时间”，显示说明“报名成功后即可抽奖，截止时间为报名结束时间”。

### 奖品配置

抽奖模式的奖品列表增加“中奖概率（%）”输入框，支持两位小数，并在列表底部实时显示：

- 已配置概率合计；
- 未中奖概率 `100% - 合计`；
- 概率超出 100% 时的阻断提示。

概率字段与奖品数量并列展示。库存数量仍表示该期最多生成的中奖记录数；概率不因库存剩余量自动变化。

开奖模式不要求填写概率，也不在表单中展示概率合计校验。

## 2. 期次列表和详情

- 增加模式标签“开奖”/“抽奖”。
- 抽奖模式不展示开奖时间和“手动开奖”按钮。
- 开奖模式保持现有“开奖”操作和开奖时间展示。
- 抽奖模式期次详情展示奖品概率、库存、已中奖数量和未中奖概率。

## 3. 结果展示约定

App 调用抽奖接口后：

- `WIN`：展示奖品名称、图片、领取说明和中奖记录入口。
- `NO_WIN`：展示未中奖提示和剩余抽奖次数；不展示内部概率、库存锁或错误堆栈。
- 网络超时：使用原 `requestId` 重试，不生成新的抽奖请求号。
- 抽奖次数耗尽：禁用抽奖按钮并刷新我的结果。

## 4. 表单校验提示

- “抽奖模式必须填写每个奖品的中奖概率”。
- “单个概率必须在 0% 至 100% 之间，最多两位小数”。
- “奖品概率合计不能超过 100%”。
- “抽奖模式不需要设置开奖时间”。
