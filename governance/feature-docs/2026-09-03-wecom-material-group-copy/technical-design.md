# 企业微信素材组复制技术设计

## 模块影响

- `backend`：素材组 Controller、Service、组 Mapper/素材 Mapper、单元测试；无数据库迁移、无外部接口调用。
- `admin`：素材组 API client 和素材管理列表操作。
- `miniapp` / `icepolar-dms`：N/A。

## 关键决策

1. **服务端生成名称**：避免客户端绕过租户边界或并发生成重复名称；复制接口只接收源组 ID。
2. **同事务深复制**：先校验源组和企业微信配置，再插入新组，按排序读取并插入全部素材；任一插入失败由事务回滚。
3. **复用外部图片 URL**：源组和副本属于同一企业微信配置，直接复制 `wecomImageUrl`，不调用 `FileApi` 或企业微信 API。
4. **不复制关联实体**：欢迎语模板、群发任务和定时任务仍指向原组；副本只是新的可编辑素材组。

## 流程

```text
管理员点击复制
  → POST copy(sourceGroupId)
  → 租户过滤并读取源组
  → 校验企业微信配置
  → 生成唯一副本名称
  → 事务内插入新组及按 sort 排序的全部素材
  → 返回新组 ID
  → 管理端刷新并选中新组
```

## 并发与风险

- 名称查询与插入存在并发窗口；实现应在候选名称插入冲突时重新生成后缀并重试有限次数，不能覆盖数据。
- 源组理论上不应为空；若读取到空组仍复制组记录会违反既有规则，因此应拒绝复制并回滚。
- 复制不产生企业微信外部副作用，不需要外部补偿或清理。
