# 活动排行榜与游戏兜底奖励技术设计

## 模块影响

- `backend/yshop-module-activity`：新增公开游戏排行榜查询；记录服务端当前局开始时间和每个报名的最佳完成成绩；扩展游戏终局兜底结算。
- `admin`：游戏模板表单显示并保存现有 `fallbackPrizeId` 字段。
- `h5`：结果页按活动模式展示入口；展示中奖名单榜或游戏成绩榜；游戏活动页展示兜底奖。
- 沿用现有期次兜底快照、中奖记录、兑奖、通知及租户范围。

## 关键决策

### 游戏最佳成绩

不新增每局历史明细表。报名表增加 `game_started_at`、`game_best_passed_level`、`game_best_duration_millis`、`game_best_finished_at`。每次新局开始时设置当前局开始时间；恢复进行中局不重置。终局在已锁定的报名行事务内计算服务器耗时，并仅在当前局的最高通过关数更高，或关数相同且用时更短时更新最佳成绩。

相同关数和用时按完成时间、报名 ID 排序，保证结果稳定。仅返回已完成局的报名；历史报名的最佳完成时间为空，因此不入榜。

### 榜单查询

在 `ActivityRegistrationMapper.xml` 使用带租户、期次、有效报名和已完成成绩条件的排序查询，数据库仅取前 10 条。由于需要关联用户资料并脱敏，服务层通过现有 `MemberUserApi` 批量取用户资料，再复用中奖名单的昵称/手机号脱敏规则构造公开响应。接口先验证期次存在并且 `drawMode=3`。

开奖榜继续使用现有 `/winners` API；H5 展示其服务端结果前 10 条。该 API 已负责租户和隐私脱敏。

### 兜底奖结算

模板保存继续使用现有独立 `fallbackPrizeId`，删除 `drawMode=3` 禁止条件；游戏期次生成逻辑已有兜底快照写入能力，无需改变数据库快照结构。终局按现有最高通过关选择常规奖并锁定库存；无已通过关、常规奖缺失或库存预占失败时尝试兜底快照。不对兜底快照执行数量扣减。单人限中仍在兜底前拦截重复派奖。

中奖记录创建逻辑抽取为同一内部操作，确保常规奖和兜底奖都增加期次中奖数并返回兑奖规则信息；兜底记录保留现有规则快照和兑奖流程。

### H5 结果页

`WinnerResultView` 接收榜单类型及标题。`drawMode=1` 展示“查看中奖排行榜”，`drawMode=3` 展示“查看闯关排行榜”，`drawMode=2` 不展示入口。弹窗根据类型渲染前 10 条名单或闯关成绩；游戏榜在点击时请求后端接口。加载、空数据和失败状态均在弹窗内呈现。

## 数据库迁移

新增 Flyway 迁移为报名表添加当前局开局时间及最佳成绩字段，并添加支持期次内成绩排序的联合索引。字段均可空，历史报名数据不回填。无需调整模板兜底奖字段或期次奖品快照。

## 风险与回滚

- 游戏榜不能用于历史报名，因为原数据没有可验证的服务端用时；旧用户完成新局后才会出现在榜单中。
- 新字段只影响游戏成绩计算，不改写已冻结的期次奖品、既有中奖记录或兑奖状态。
- 回滚需先停止游戏榜请求，再移除新增索引和列；不要回滚已有活动兜底奖快照结构。
