## Feature: Adapay 第三方支付集成

### Scope

**In-scope**

- 后端新增 Adapay（汇付天下）支付能力，提供统一的支付创建与回调处理接口。
- 支付成功后，订单状态变为已支付，系统记录支付方式为 Adapay。
- 支付结果通过 Adapay 回调异步通知到系统，并触发订单后续履约流程。
- 管理后台支持配置 Adapay 商户参数（应用 ID、商户号、公私钥、签名方式、回调地址等），配置方式与微信、支付宝类似。
- 管理后台所有展示订单支付方式的位置，需正确显示 Adapay。

**Out-of-scope**

- C 端支付页面直接选择 Adapay（本次仅提供后端支付接口，C 端接入由后续需求处理）。
- 收银结算页面改造。
- Adapay 分账、结算、对账等支付后业务。

**Deferred**

- Adapay H5、APP 等其他支付形态。
- 管理后台表单按支付方式动态展示字段。

### Use Cases

#### 调用方 - 使用 Adapay 支付订单

- **触发条件**：调用方已确认订单并选择 Adapay 作为支付方式。
- **主流程**：
  1. 调用方向后端发起支付请求，指定使用 Adapay。
  2. 系统根据订单信息与 Adapay 配置创建支付单，返回支付参数。
  3. 用户在 Adapay 收银台完成付款。
  4. Adapay 异步回调系统通知支付成功。
  5. 系统更新订单为已支付，并继续后续履约流程。
- **业务规则**：
  - 已支付订单不能被再次支付。
  - 同一订单一旦使用某渠道发起支付，即锁定为该渠道，不可切换为其他支付渠道。
  - 同一订单若因异常收到多次成功回调，应保证订单状态与库存扣减幂等。
  - 支付失败或关闭的订单允许用户重新发起支付，但仍只能使用原渠道或业务规则允许的渠道。
- **预期结果**：订单完成支付，支付方式记录为 Adapay，后续履约流程正常触发。

#### 平台管理员 - 配置 Adapay 支付服务商

- **触发条件**：平台管理员需要为指定租户启用 Adapay 支付。
- **主流程**：
  1. 管理员进入“支付管理 > 支付配置”。
  2. 新增 Adapay 配置，填写应用 ID、商户号、密钥、签名方式、回调地址等。
  3. 保存后，调用方即可使用 Adapay 发起该租户下的订单支付。
- **业务规则**：
  - 不同租户的 Adapay 配置相互隔离。
  - 支付类型和支付 ID 在下拉框中需能正确选择 Adapay，与微信、支付宝配置方式一致。
- **预期结果**：配置保存后，该租户下的订单可使用 Adapay 支付。

#### 平台管理员/门店运营 - 查看 Adapay 支付订单

- **触发条件**：管理员或门店运营查看订单列表或订单详情。
- **主流程**：
  1. 管理员进入订单列表或订单详情。
  2. 付款方式为 Adapay 的订单展示为“Adapay支付”。
- **业务规则**：所有展示支付方式的订单视图需统一显示 Adapay 文案。
- **预期结果**：Adapay 支付订单在管理后台可见且文案一致。

### Frontend Requirements

#### 管理后台 - 支付服务商配置

- 配置表单中“支付类型”下拉框需包含 Adapay 选项，与微信、支付宝并列。
- 配置表单中“支付 ID”下拉框需包含 Adapay 对应的选项。
- 表单字段保持通用，支持填写 Adapay 所需的公私钥、签名方式、回调地址等。

#### 管理后台 - 订单管理

- 订单列表、订单详情等页面中，支付方式为 Adapay 的订单需展示为“Adapay支付”。

### Edge Cases

- 同一订单已通过某渠道发起支付后，再次请求切换为其他渠道应被拒绝。
- Adapay 回调重复通知时，系统不应重复扣减库存或重复发放权益。
- 管理后台删除 Adapay 配置后，已产生的 Adapay 订单不应受影响，仅新订单无法继续使用该配置。

### Acceptance Criteria

- [ ] 调用方可通过统一支付接口指定 Adapay 创建订单支付单并完成付款。
- [ ] Adapay 支付成功后，订单状态更新为已支付，后续履约流程正确触发。
- [ ] 管理后台所有展示支付方式的位置，Adapay 均显示为“Adapay支付”。
