## Feature: Adapay 第三方支付集成

### Scope

**In-scope**

- 后端新增 Adapay（汇付天下）支付能力，提供统一的支付创建与回调处理接口。
- 支付成功后，订单状态变为已支付，系统记录支付方式为 Adapay。
- 支付结果通过 Adapay 回调异步通知到系统，并触发订单后续履约流程。
- 管理后台支持配置 Adapay 商户参数（应用 ID、商户号、公私钥、签名方式、回调地址等），配置方式与微信、支付宝类似。
- 管理后台所有展示订单支付方式的位置，需正确显示 Adapay。
- 后端支持对 Adapay 已支付订单发起全额退款，退款资金原路返回。
- 后端支持对 Adapay 未支付订单进行支付撤销（关闭 Adapay 侧支付单），用户主动取消、订单超时或重新支付前触发。
- 接收并处理 Adapay 退款/关闭异步通知，保证回调幂等。

**Out-of-scope**

- C 端支付页面直接选择 Adapay（本次仅提供后端支付接口，C 端接入由后续需求处理）。
- 收银结算页面改造。
- Adapay 分账、结算、对账等支付后业务。
- 部分退款。
- 已执行 Adapay 延迟分账确认（`profit_sharing_order.sharing_status` 为 `SUCCESS` 或 `PROCESSING`）后的订单退款。

**Deferred**

- Adapay H5、APP 等其他支付形态。
- 管理后台表单按支付方式动态展示字段。

### Use Cases

#### 调用方 - 使用 Adapay 支付订单

- **触发条件**：调用方已确认订单并选择 Adapay 作为支付方式。
- **主流程**：
  1. 调用方向后端发起支付请求，指定使用 Adapay。
  2. 系统根据订单信息与 Adapay 配置创建支付单，返回支付参数。
  3. 用户在 Adapay 收银台完成付款。
  4. Adapay 异步回调系统通知支付成功。
  5. 系统更新订单为已支付，并继续后续履约流程。
- **业务规则**：
  - 已支付订单不能被再次支付。
  - 同一订单一旦使用某渠道发起支付，即锁定为该渠道，不可切换为其他支付渠道。
  - 同一订单若因异常收到多次成功回调，应保证订单状态与库存扣减幂等。
  - Adapay 订单在待支付状态下每次调用统一支付接口重新发起支付，都必须视为一次新的支付 attempt，并生成新的外部支付单号 `outPayNo`，不得复用上一次传给 Adapay 的单号。
  - Adapay `outPayNo` 从 `orderId-1` 开始递增；同一订单同一渠道再次发起支付时，取该订单历史 Adapay 记录最大序号加 1，例如 `orderId-2`、`orderId-3`。
  - `pay_out_order_no` 保留历史 attempt 记录，但同一订单同一支付渠道在业务上只能有一条有效的待支付记录；创建新 Adapay attempt 前，应将上一条待支付记录关闭或置为非当前有效记录。
  - 支付失败或关闭的订单允许用户重新发起支付，但仍只能使用原渠道或业务规则允许的渠道。
  - 旧 attempt 的成功回调可能晚于新 attempt 到达；系统必须通过 `outPayNo` 反查订单并保证幂等，避免重复履约、重复扣库存或重复发放权益。
- **预期结果**：订单完成支付，支付方式记录为 Adapay，后续履约流程正常触发。

#### 平台管理员 - 配置 Adapay 支付服务商

- **触发条件**：平台管理员需要为指定租户启用 Adapay 支付。
- **主流程**：
  1. 管理员进入“支付管理 > 支付配置”。
  2. 新增 Adapay 配置，填写应用 ID、商户号、密钥、签名方式、回调地址等。
  3. 保存后，调用方即可使用 Adapay 发起该租户下的订单支付。
- **业务规则**：
  - 不同租户的 Adapay 配置相互隔离。
  - 支付类型和支付 ID 在下拉框中需能正确选择 Adapay，与微信、支付宝配置方式一致。
- **预期结果**：配置保存后，该租户下的订单可使用 Adapay 支付。

#### 平台管理员/门店运营 - 查看 Adapay 支付订单

- **触发条件**：管理员或门店运营查看订单列表或订单详情。
- **主流程**：
  1. 管理员进入订单列表或订单详情。
  2. 付款方式为 Adapay 的订单展示为“Adapay支付”。
- **业务规则**：所有展示支付方式的订单视图需统一显示 Adapay 文案。
- **预期结果**：Adapay 支付订单在管理后台可见且文案一致。

#### 平台管理员/门店运营 - 同意 Adapay 订单退款

- **触发条件**：管理员或门店运营对已支付且未分账确认的 Adapay 订单发起退款。
- **主流程**：
  1. 管理员进入订单详情或订单列表，点击“同意退款”/“取消订单并退款”。
  2. 系统校验订单支付方式为 Adapay、订单已支付、未处于分账成功/处理中状态。
  3. 系统生成退款单号 `outRefundNo`（雪花 ID，与微信/支付宝退款单号生成方式一致），调用 Adapay 退款接口；`outRefundNo` 不持久化到独立退款表。
  4. Adapay 返回受理成功/处理中，系统更新订单 `refund_status = 2`、`status = -2`，并回退库存、优惠券、门店收支、佣金。
  5. Adapay 异步通知退款结果，系统记录到订单日志表（`yshop_store_order_status`）。
- **业务规则**：
  - 仅支持全额退款，退款金额等于订单实付金额。
  - 已分账确认（`sharing_status = SUCCESS/PROCESSING`）的订单不允许退款，需等待后续需求支持分账回退。
  - 同一 `outPayNo` 只能有一笔成功退款。
  - 退款失败时，订单状态保持原状，失败原因记录到订单日志表，允许管理后台重新发起。
- **预期结果**：Adapay 订单完成全额退款，订单状态变为已退款，资金原路返回。

#### 用户/系统 - 取消未支付 Adapay 订单（支付撤销）

- **触发条件**：用户对未支付 Adapay 订单主动取消，或订单超时未支付被系统自动取消，或用户对待支付 Adapay 订单重新发起支付。
- **主流程**：
  1. 取消/重新支付请求到达后端。
  2. 系统查询该订单当前有效的 Adapay `outPayNo`。
  3. 调用 Adapay 关闭/撤销接口关闭 Adapay 侧支付单，并将 `pay_out_order_no` 对应记录置为 `status = 2`。
  4. 用户主动取消或超时取消时，按现有逻辑回退库存、优惠券；重新支付时进入新的支付 attempt。
- **业务规则**：
  - 未支付订单才可执行支付撤销；已支付订单应走退款流程。
  - 关闭 Adapay 支付单失败时，本地 `pay_out_order_no` 仍应标记为关闭，避免该 `outPayNo` 被再次使用；关闭失败记录日志告警。
  - 重新支付前必须先关闭上一条当前有效待支付记录，再生成新的 `outPayNo`。
- **预期结果**：未支付 Adapay 订单被正确关闭，不会产生后续支付成功回调导致误履约。

#### 系统 - 接收 Adapay 退款/关闭异步通知

- **触发条件**：Adapay 针对退款或支付关闭产生异步通知，回调到 `/app-api/order/notify/payBackadapay_h5{tenantId}.json`。
- **主流程**：
  1. 回调处理器根据 `outPayNo`/`outRefundNo` 反查对应记录。
  2. 按状态更新 `pay_out_order_no` 或将退款结果记录到订单日志表。
  3. 重复或乱序回调以最终状态幂等处理，不重复更新订单。
- **业务规则**：
  - 退款/关闭回调必须验签。
  - 对无法识别的单号返回 FAIL，对重复成功回调返回 SUCCESS 但不重复执行业务。
- **预期结果**：异步通知被正确、幂等地处理。

### Frontend Requirements

#### 管理后台 - 支付服务商配置

- 配置表单中“支付类型”下拉框需包含 Adapay 选项，与微信、支付宝并列。
- 配置表单中“支付 ID”下拉框需包含 Adapay 对应的选项。
- 表单字段保持通用，支持填写 Adapay 所需的公私钥、签名方式、回调地址等。

#### 管理后台 - 订单管理

- 订单列表、订单详情等页面中，支付方式为 Adapay 的订单需展示为“Adapay支付”。

### Edge Cases

- 同一订单已通过某渠道发起支付后，再次请求切换为其他渠道应被拒绝。
- Adapay 待支付订单重复调用支付接口时，每次都应生成新的 `outPayNo`，不能复用上一条创建中的支付单号。
- `pay_out_order_no` 对同一订单同一渠道只能存在一条当前有效的待支付记录，历史记录用于回调反查、审计和对账。
- Adapay 回调重复通知时，系统不应重复扣减库存或重复发放权益。
- 管理后台删除 Adapay 配置后，已产生的 Adapay 订单不应受影响，仅新订单无法继续使用该配置。
- 同一 `outPayNo` 只能有一笔成功退款；重复退款请求应被拒绝或幂等返回。
- 已分账确认（`profit_sharing_order.sharing_status = SUCCESS/PROCESSING`）的 Adapay 订单，退款请求应被拒绝。
- Adapay 退款/关闭回调重复或乱序到达时，应以最终状态幂等更新，不重复回滚库存、佣金或门店收支。
- 关闭回调晚于新支付请求到达时，应以 `pay_out_order_no` 最终状态为准，避免误关闭新 attempt。

### Acceptance Criteria

- [ ] 调用方可通过统一支付接口指定 Adapay 创建订单支付单并完成付款。
- [ ] Adapay 待支付订单每次重新调用支付接口时，`outPayNo` 按 `orderId-{n}` 递增，且不会向 Adapay 复用旧单号。
- [ ] `pay_out_order_no` 保留历史记录，但同一订单同一渠道任一时刻只有一条当前有效待支付记录。
- [ ] Adapay 支付成功后，订单状态更新为已支付，后续履约流程正确触发。
- [ ] 管理后台所有展示支付方式的位置，Adapay 均显示为“Adapay支付”。
- [ ] Adapay 已支付订单可全额退款，订单 `refund_status` 更新为已退款，`status` 更新为退款成功。
- [ ] 已分账确认（`profit_sharing_order.sharing_status = SUCCESS/PROCESSING`）的 Adapay 订单，退款接口返回拒绝。
- [ ] 未支付 Adapay 订单取消、超时或重新支付时，对应 `pay_out_order_no` 被标记为关闭，Adapay 侧支付单关闭。
- [ ] Adapay 退款/关闭回调重复通知时，系统幂等处理，不重复更新订单或产生重复流水。
