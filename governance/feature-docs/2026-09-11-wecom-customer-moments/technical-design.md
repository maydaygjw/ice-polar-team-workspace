# 企业微信客户朋友圈技术设计

## 模块影响

- `backend`：新增朋友圈任务领域、企业微信 API 编排、任务状态查询、菜单权限、数据库迁移和测试。
- `admin`：新增朋友圈编辑页、任务列表、素材组复用和客户管理员多选。
- `miniapp` / `icepolar-dms`：N/A，不涉及。

## 关键决策

1. **复用素材库，新增朋友圈编排**：保留现有 `TEXT`、`IMAGE` 素材模型；不复用客户群的混合附件编排方法，因为朋友圈只允许图片附件且最多 9 张。
2. **图片按任务上传**：现有 `wecomImageUrl` 是群发使用的图片 URL；朋友圈需要 `media_id`，创建任务时从本地图片读取并上传，随后把媒体 ID 写入任务快照。
3. **保存异步任务**：企业微信先返回 `jobid`，随后查询结果获得 `moment_id` 和无效成员；本地任务保存快照，避免素材后续变化影响历史记录。
4. **只立即创建，不自动重试**：网络异常无法判断外部任务是否已创建，因此状态置为待核查，不重复请求。
5. **默认可见范围**：不发送 `visible_range`，由企业微信按所选发表人的客户范围处理；本期不设计客户筛选模型。

## 流程

```text
管理端选择配置/管理员/素材
  → 后端校验租户、配置、成员和图片数量
  → 图片上传企业微信获取 media_id
  → 保存任务快照
  → add_moment_task
  → 保存 jobid
  → get_moment_task_result
  → 展示等待确认/已发表/失败
```

## 风险

- 客户管理员必须在企业微信应用可见范围内，企业微信可能返回部分无效成员。
- 媒体 ID、任务 jobid 具有外部生命周期，任务必须保存可诊断快照和错误信息。
- 真实企业微信环境的图片大小、格式和管理员确认时效需要测试环境验证。
