# printer-order-flow 测试计划

## 目标

验证 backend 从打印订单创建、链科文件页数计算、业务订单计价、设备订单快照到支付后打印提交的闭环。

## 环境

- 仅 local/test 环境。
- 后端通过 `LIANKE_PRINT_HOST` 指向独立 HTTP Mock 服务。
- 禁止测试默认指向真实链科生产接口。
- 使用测试租户、测试店铺、测试商品和一次性订单。

## Mock 场景

| 场景 | Mock 行为 | 预期 |
|---|---|---|
| 文件页数成功 | 返回确认后的成功码和页数 | 创建订单并按页数计价 |
| 文件页数业务失败 | 返回错误码和消息 | 拒绝创建订单 |
| 文件下载超时 | 延迟超过客户端 read timeout | 拒绝创建订单并记录可观测错误 |
| 文件超过大小限制 | 返回供应方限制错误 | 拒绝创建订单 |
| 空页数 | 成功但无有效页数 | 拒绝创建订单 |
| 打印提交成功 | 返回 task_id | DeviceOrder 进入排队状态 |
| 打印提交失败 | 返回 HTTP/业务错误 | 进入失败并触发退款 |
| 打印机列表多条 | 返回多条 `data.row` | 固定保存第一条打印机的型号和端口 |
| 打印机列表为空 | 返回空 `data.row` | 初始化失败，设备不可用于打印 |

## 端到端场景

- 管理端按店铺进入打印设备管理页面，录入设备并完成初始化。
- 初始化页面展示第一台打印机及其能力及待清理的规格/Option 数量，二次确认后清理并为文件打印/照片打印商品重新生成纸张和颜色 Option。
- 初始化失败，验证已删除的规格/Option 可回滚或通过补偿恢复。
- 文件打印 A4/黑白：固定 3 页、2 份，验证金额为 `(SKU base price + Option delta) × 3 × 2`。
- 文件打印切换纸张/颜色 Option：验证 Option 加价变化且 `dmPaperSize` 映射正确。
- 照片打印：上传 4 张图片、2 份，验证金额为 `(SKU base price + Option delta) × 4 × 2`，且没有 file_pages 请求。
- 横向/纵向 Option：验证快照存在，并按配置的加价计入或不增加金额。
- 商品分类改名：已创建订单仍按快照类型处理。
- 店铺 0/2 条 printer 设备：均拒绝下单。
- 重复订单请求：验证幂等行为，不生成重复业务订单或设备订单。

## 清理

测试订单、设备任务和 Mock 记录使用一次性数据；清理前先通过业务接口确认没有待退款、待打印或未完成的外部任务。不得直接删除可能已经触发真实资金或打印副作用的记录。
