# 活动中奖企业微信通知契约变更

## Admin API

统一前缀 `/admin-api/activity`，响应使用现有 `CommonResult`，要求登录、租户隔离和现有 `activity:winner:claim` 权限。

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/winner/send-notification` | 向指定中奖记录对应的企业微信客户创建中奖通知任务 |

请求体：

```json
{"winnerId": 20001}
```

成功响应：

```json
{"msgId":"企业微信消息任务 ID","senderUserId":"活动管理员企业微信 UserID"}
```

服务端从中奖记录关联的期次快照读取活动管理员，并按配置顺序选择同时满足以下条件的管理员作为发送人：

1. 中奖用户存在已匹配的企业微信客户联系人；
2. 该管理员是该客户联系人的有效跟进成员。

客户端不得传入 `userId`、客户联系人、企业微信外部联系人 ID、租户 ID 或发送人。消息内容由服务端生成，包含活动标题、奖品名称和兑奖说明；企业微信接口仍沿用现有客户文本消息任务语义。

以下情况返回业务错误且不创建成功响应：中奖记录不存在或无效、客户未匹配企业微信联系人、活动管理员未跟进该客户、期次快照缺少活动管理员、企业微信接口发送失败。

中奖记录新增 notificationStatus 通知状态：0 未发送、1 已发送、2 发送失败；单条和批量发送完成后均回写该状态，后台中奖记录列表展示并支持按状态筛选。重复操作会创建新的企业微信消息任务，前端发送前需二次确认。
