# 活动报名条件实例管理需求规格

## Scope

在现有活动报名条件类型注册机制之上，增加“条件实例”管理能力。条件类型仍由后端代码注册并负责实际校验；管理端不创建新的执行逻辑，只基于已注册类型创建可复用的条件实例。

本期涉及：

- `backend`：条件实例持久化、租户隔离、CRUD API、参数校验、模板引用校验。
- `admin`：条件实例列表、新增、编辑、删除、启停及参数配置界面；活动模板改为选择条件实例。
- `governance`：冻结 API、数据库、权限和 UI 契约。

不涉及：

- 在后台创建任意脚本、表达式或新的条件处理器。
- 修改已有条件处理器的业务执行逻辑。
- 修改历史期次快照和已生成报名记录。
- 小程序/H5 页面改造。

## Use Cases

### UC1：查看条件实例

管理员进入“活动管理 → 报名条件管理”，按当前租户查询条件实例列表，看到条件实例名称、所属类型、类别、参数摘要、说明、启用状态、引用数量和操作项。

### UC2：新增条件实例

管理员选择一个已注册的条件类型，填写实例名称、说明、参数和排序，保存后生成一个独立条件实例。例如：

- `1天内下单`：类型 `HAS_CONFIRMED_ORDER_WITHIN_DAYS`，配置 `{ "days": 1 }`。条件定义支持其他正整数天数，但当前外部接口仅支持 1 天。

同一条件类型允许创建多个实例，只要实例名称或参数不同即可。

### UC3：编辑条件实例

管理员可以修改实例名称、说明、参数、排序和启用状态。类型不可修改；如需不同类型，必须新建实例并删除原实例（删除规则见 UC4）。

### UC4：删除条件实例

管理员删除条件实例时，后端检查当前租户的活动模板是否引用该实例：

- 未被任何活动模板引用：允许删除。
- 已被任一活动模板引用：拒绝删除，并返回明确的业务错误，提示先从活动模板中移除该条件。

本期不检查历史期次快照和报名记录引用，历史数据不参与条件实例删除拦截。

### UC5：在活动模板中选择条件实例

活动模板编辑页面不再直接以条件类型作为扩展条件选项，而是加载当前租户启用的条件实例。管理员可以：

- 添加多个不同条件实例；
- 添加同一条件类型下的多个实例；
- 删除已选实例；
- 查看实例名称和参数摘要；
- 保存模板时提交条件实例 ID。

内置条件仍按现有内置条件选择方式工作，但如其需要参数，也必须由条件实例配置承载。

## Business Rules

1. 条件类型是后端 `ActivityCondition` 注册处理器的稳定标识，不允许通过管理端新增、删除或修改。
2. 条件实例必须关联一个当前已注册且可用的条件类型；未知类型、已停用类型或处理器不存在时不可新增/编辑。
3. 条件实例至少包含：实例 ID、租户 ID、条件类型、实例名称、说明、JSON 配置、排序、启用状态和审计字段。
4. 条件实例配置必须通过对应处理器的参数校验；禁止脚本、表达式、任意类名、外部 URL、租户 ID、用户 ID 或外部凭据。
5. `HAS_CONFIRMED_ORDER_WITHIN_DAYS` 的 `days` 必须为正整数；条件定义支持多天。当前外部订单接口仅支持当天，因此管理端暂只配置 `days=1`，其他天数由后端明确失败。
6. 同一租户下实例名称应唯一，避免模板选择和用户展示产生歧义；条件类型相同但参数不同的实例允许共存。
7. 启用状态只影响活动模板可选项和报名执行；停用实例不能新增到模板，已引用实例的模板保存/生成期次行为需在设计阶段明确并保持一致。
8. 活动模板保存时只保存条件实例 ID、排序和必要的实例配置快照；报名执行仍以期次快照为准。
9. 条件实例删除校验只针对当前租户的活动模板配置，不跨租户查询，不以历史期次快照作为删除阻断条件。
10. 所有管理端接口执行现有认证、`activity:condition:*` 权限和租户隔离。
11. 删除是破坏性管理操作，接口必须幂等：目标不存在时返回统一“条件实例不存在”，不得误删其他实例。

## Frontend Requirements

### 条件实例管理页

- 列表列：实例名称、条件类型名称、类别、参数摘要、说明、启用状态、模板引用数、更新时间、操作。
- 操作：新增、编辑、启用/停用、删除。
- 新增/编辑弹窗：条件类型选择、实例名称、说明、参数表单、排序、启用状态。
- 条件类型选择只展示后端返回的已注册类型；根据 `configSchema` 动态渲染参数表单。
- 当前 `HAS_CONFIRMED_ORDER_WITHIN_DAYS` 使用通用参数编辑器，参数键为 `days`；管理端暂只配置值 `1`。
- 删除前二次确认；被引用时展示后端返回的阻断原因。
- 列表、保存、删除、权限不足和参数校验失败均有明确反馈。

### 活动模板页

- 扩展条件下拉列表改为条件实例列表，显示“实例名称（条件类型名称）”。
- 同一条件类型的多个实例均可选择，不再按类型去重。
- 已选择实例展示实例名称和参数摘要，并支持移除。
- 仅展示启用实例；编辑已有模板时应能回显已保存的条件实例，即使该实例后来停用。

## Edge Cases

- 条件类型处理器已从后端移除，但数据库仍有实例：管理列表标记为不可用；不能新增到模板、不能执行报名；编辑仅允许修复为有效类型或删除（仍受模板引用规则约束）。
- 条件类型的 `configSchema` 与服务端校验不一致：以后端校验为准，前端展示通用错误。
- 两个实例配置相同但名称不同：允许保存，模板和用户端以实例 ID 区分。
- 同一模板重复引用同一条件实例：保存时拒绝重复引用，避免报名条件重复执行。
- 删除与模板保存并发：删除事务再次检查模板引用；任一引用存在则删除失败。
- 停用已被模板引用的实例：不自动修改模板；模板编辑页保留回显，但新模板不可选择；具体执行语义在设计阶段冻结。
- 租户 A 创建的实例不得被租户 B 查询、编辑、删除或引用。
- 订单条件的 `days` 仍由条件定义校验；当前外部接口仅支持值 `1`，其他值保存可以通过条件定义校验，但执行时明确失败，不能静默改查当天。
- 删除最后一个实例后，条件管理页展示空状态；活动模板无条件时按现有“无报名条件”语义处理。

## Acceptance Criteria

1. 条件管理页能列出当前租户所有条件实例，并显示对应注册类型及参数摘要。
2. 管理员能基于 `HAS_CONFIRMED_ORDER_WITHIN_DAYS` 新建 `1天内下单` 实例，并可被模板选择；条件类型仍保留多天参数定义。
3. 管理员能编辑实例名称、说明、参数和启用状态；类型字段不可编辑。
4. 未被活动模板引用的实例可以删除；已被任一当前租户活动模板引用的实例删除请求被拒绝，且不会删除数据。
5. 活动模板能够同时选择同一类型的多个实例，并在保存后正确回显。
6. 报名执行根据条件实例对应的类型和配置执行；当前 `days=1` 时调用外部商城 `HasTodayConfirmedOrder`，不传递 `days` 参数；其他天数明确失败。
7. 未知类型、无效参数、停用实例和重复实例引用均不能绕过服务端校验。
8. 所有条件实例接口均验证登录、权限和租户隔离。
9. 外部订单调用的请求/响应日志满足后端 DEBUG 脱敏规范。
10. 后端单元/接口测试、管理端构建和关键管理端 E2E 场景通过。

## Assumptions

- 条件实例名称和说明由租户维护，默认不覆盖后端条件类型的技术名称和默认说明。
- 条件实例的展示参数由注册处理器提供 `configSchema`，本期只实现已有处理器所需的参数控件。
- 当前历史快照不参与条件实例删除阻断，但已生成期次仍按其自身快照执行，不回溯读取被删除的实例。
- 条件实例表使用软删除或等价可审计删除机制；具体字段和删除实现留到技术设计阶段确定。
