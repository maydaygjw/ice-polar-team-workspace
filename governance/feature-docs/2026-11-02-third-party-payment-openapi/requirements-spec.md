# 第三方支付 OpenAPI 需求规格

## Scope

### In-scope

- 为第三方业务系统的服务端提供独立的支付 OpenAPI；调用方使用第三方客户端身份，不要求登录为平台会员或管理员。
- 使用平台统一维护的支付渠道配置。第三方通过平台支付接口创建支付单、查询支付单并申请全额退款，也可通过微信商家转账 API 向用户发起转账；第三方不保存或提交微信支付商户密钥、商户证书等渠道凭据。
- 以平台已有支付模块能力为基础提供接口适配层，复用已有支付配置、支付单创建、渠道回调、查单和退款能力；本需求不要求为第三方另建一套微信支付渠道实现。
- 在现有 OAuth2 客户端通用配置中以逗号分隔文本维护 scope，不新增 OpenAPI 专属 scope 管理表单。首期覆盖支付创建、支付查询、全额退款和商家转账操作，统一由 `payment` scope 授权。
- 第三方服务端通过客户端凭证获取访问令牌；令牌标识第三方客户端，不赋予会员或管理员身份。OpenAPI 每项操作按授权 scope 进行访问控制。
- 第三方可通过查询支付单获知最新支付结果；平台提供受配置约束的支付结果通知能力，使第三方无需只依赖人工对账。通知使用明文 JSON，不增加应用层签名或加密。
- 支付创建接口作为服务端接口工作，第三方可指定 `weixin` 或 `adapay`；微信时提供当前租户已启用微信支付配置 AppID 对应的用户 OpenID。平台响应提供渠道对应的支付参数，由集成方按渠道传递给支付客户端；平台不提供托管收银页面。
- 订单号幂等、客户端间数据隔离、支付状态以平台确认的微信支付结果为准。
- 商家转账仅向当前租户的平台会员发起；调用方提供会员 `userId`，平台从会员记录读取小程序 OpenID，并使用当前租户已配置的微信商户与已报备转账场景。调用方不得提交 OpenID、商户号、AppID、场景报备字段、密钥或通知地址。
- 转账受理不代表用户已确认或到账；最终状态以平台验签后的微信通知或主动查单为准，并通过既有 Webhook 通知第三方。

### Out-of-scope

- 独立商家转账查询、撤销接口；转账终态通过既有 Webhook 通知。
- 部分退款；首期只支持全额退款。
- 为第三方提供平台托管的 H5/JS 收银页面。
- 让第三方自行接入微信支付、保存渠道密钥或自行验签平台微信支付回调。
- 复用后台菜单权限标识作为第三方 API 授权。菜单权限控制后台用户，OpenAPI scope 控制 OAuth2 客户端。
- 改造既有 `/app-api` 会员支付流程或改变既有支付、退款状态语义。

## Use Cases

### 管理员配置 OpenAPI 权限

- **角色**：有权限管理系统集成的后台管理员。
- **目标**：维护平台允许授予第三方的操作 scope，并限制每个第三方客户端可调用的支付能力。
- **主流程**：管理员在 OAuth2 客户端通用配置中输入该客户端允许使用的 scope，多个值以英文逗号分隔。未授权给客户端的 scope 不得通过令牌申请取得，也不得用于调用接口。

### 第三方创建支付单

- **角色**：持有效 OAuth2 客户端令牌的第三方服务端。
- **目标**：委托平台按当前请求租户和该租户已启用的支付配置创建微信支付单。
- **主流程**：第三方服务端提交其业务订单标识、金额及必要的支付信息；平台校验客户端状态、scope、所属租户和支付配置，创建平台支付单并返回平台支付单标识、当前状态及支付场景所需信息。调用方可使用幂等标识安全重试。

### 第三方查询支付单

- **角色**：持有效 OAuth2 客户端令牌的第三方服务端。
- **目标**：按平台支付单标识或该客户端业务订单标识核对支付进度和最终结果。
- **主流程**：平台仅返回当前客户端所属范围内的支付记录；支付最终结果以平台验签后的微信支付通知或平台主动查单结果为准。

### 第三方申请全额退款

- **角色**：持有效 OAuth2 客户端令牌的第三方服务端。
- **目标**：对符合平台退款规则的已支付订单申请全额退款。
- **主流程**：第三方提交其可识别的支付单及退款原因等所需信息；平台校验退款 scope、归属关系、支付状态和现有渠道退款规则，向原微信支付渠道发起全额退款，并返回平台受理结果。退款是否完成按平台最终查询/回调结果确认。

### 第三方发起商家转账

- **角色**：持有效 OAuth2 客户端令牌且获得转账 scope 的第三方服务端。
- **目标**：通过平台已配置的微信商户能力向指定微信用户发起转账，并取得用户确认收款所需参数。
- **主流程**：第三方提交业务订单标识、当前租户会员 `userId`、金额及转账备注；平台校验会员、租户、客户端 scope、商户转账配置和幂等关系，从会员记录读取小程序 OpenID 并使用商户已报备场景创建转账单，返回商户单号、微信转账单号、状态及用户确认参数；用户确认后平台依据微信通知或查单更新终态，并通过 Webhook 投递。

## Business Rules

1. OpenAPI 与会员端 `/app-api`、管理端 `/admin-api` 使用不同接口边界。OpenAPI 的服务调用方是 OAuth2 客户端，不可将客户端令牌当作会员或管理员令牌使用。
2. OAuth2 客户端只能获得由管理员在 admin 授予且仍有效的已登记 scope；每个支付操作都必须显式校验对应 scope。客户端不得通过请求自行扩展授权范围。
3. OpenAPI scope 与后台菜单权限标识相互独立。后台菜单权限用于管理员授权，scope 用于外部客户端授权；菜单角色变化不得隐式授予或撤销第三方 scope。
4. OpenAPI 请求使用 `tenant-id` 请求头指定平台业务租户；支付渠道配置、是否允许外部 OpenAPI 调用及 Webhook 地址均由该租户在支付配置中维护。请求不得提交渠道密钥或商户号。
5. 支持微信支付和汇付（Adapay）。平台按当前租户和渠道查找服务端维护的支付配置；第三方无需获取渠道密钥。
6. 金额和币种、外部业务订单标识及支付状态需在平台支付记录中明确关联。相同客户端对同一业务订单重复创建时不得产生重复扣款；金额或关键业务信息不一致时必须返回明确冲突结果。
7. 支付单查询和退款只能访问当前 token 租户和 OAuth2 client 范围内的记录。知道其他客户端的支付单号不能绕过归属校验。
8. 全额退款须满足平台和微信支付现有退款规则。接口受理不等同退款完成，第三方应可查询退款/支付单最终结果；不得把浏览器跳转、第三方上报或创建退款的同步响应当作退款成功凭据。
9. 支付结果通知仅发送到支付配置中维护的 HTTP/HTTPS 地址；创建支付请求不得临时指定任意通知 URL。通知使用明文 JSON，接收方以事件 ID 去重。
10. 客户端停用、凭证撤销或 scope 移除后，不得继续创建新支付或退款；存量支付单的查询、支付回调、通知补偿及退款策略应在设计阶段明确，不得因客户端停用丢失已受理交易的终态处理。
11. API 调用、管理操作和支付/退款状态变化需保留可审计关联，避免记录客户端密钥、访问令牌或渠道密钥等凭据。
12. 商家转账与支付、查询、退款统一使用 `payment` scope；按租户、客户端和第三方订单号幂等。同一订单标识的金额、收款用户或备注不一致时返回冲突。
13. 转账只接受当前租户内存在且具备小程序 OpenID 的会员 `userId` 和 CNY 正整数分金额；AppID、商户号、转账场景、报备信息及通知地址均由平台读取，不接受调用方覆盖。缺少有效转账配置或会员无小程序 OpenID 时拒绝请求。
14. 微信回调与查单是转账最终状态的唯一依据。OpenID 只从会员记录临时读取，不复制到 OpenAPI 业务记录或日志；为幂等重试恢复响应而短期保存的 `packageInfo` 必须设过期清理。

## Frontend Requirements

### Admin (`admin`)

- 在管理端提供 OpenAPI scope 管理能力，管理员可识别每个 scope 对应的业务操作、说明及是否可授予。
- OAuth2 客户端通用配置中使用文本框维护 scope，多个 scope 以逗号分隔；scope 与后台菜单权限相互独立。
- 可查看客户端启用状态及其支付能力授权，避免管理员将退款能力与查询能力混为一项。
- 关键操作提供成功、失败和无数据反馈；危险或无效授权不得静默保存。

### Third-party integration

- 第三方集成方通过服务端调用 OpenAPI；收到 `packageInfo` 后由其小程序客户端按微信规则调起用户确认收款，不要求接入平台 H5 页面。
- OpenAPI 接入说明应覆盖客户端凭证获取/使用、`payment` scope、支付创建与查询、全额退款、商家转账发起、幂等和错误处理，以及支付/转账结果通知和重复事件处理规则。完整接口字段属于设计/契约阶段产物。

## Edge Cases

| 场景 | 处理要求 |
|---|---|
| 客户端令牌申请未授权或未登记的 scope | 拒绝签发超出客户端授权范围的令牌，并返回可诊断错误。 |
| 令牌有效但缺少当前操作 scope | 拒绝该操作，不产生支付、退款或转账副作用。 |
| 客户端已停用、令牌撤销或 scope 已移除 | 按设计确认的撤销生效策略拒绝后续请求；已受理交易仍可正确推进终态。 |
| 同一客户端同一业务订单重复创建且内容相同 | 返回既有支付单或等价幂等结果，不重复创建可扣款交易。 |
| 同一业务订单标识对应不同金额或关键内容 | 返回冲突，不覆盖原支付单的金额或业务关联。 |
| 查询或退款使用其他客户端的支付单标识 | 返回拒绝或不暴露记录存在性，不返回跨客户端支付信息。 |
| 支付请求未匹配到客户端租户下可用微信配置 | 拒绝创建并给出不泄露密钥/配置细节的错误。 |
| 微信支付/转账回调延迟、重复或与第三方客户端通知重复 | 平台状态更新需幂等；外部通知按 eventId 去重，非终态转账由平台查单兜底。 |
| 全额退款超出可退状态、重复申请或渠道处理异步 | 不得重复退款；返回明确受理/拒绝状态，最终结果可查询。 |
| 管理员移除客户端 scope 时存在进行中的支付或退款 | 新操作按最新权限拒绝；存量交易的状态同步、查询和通知按明确的过渡策略完成。 |

## Acceptance Criteria

1. 第三方服务端可使用 OAuth2 客户端身份调用独立 OpenAPI；其令牌不被识别为会员或管理员身份。
2. 后台管理员可在 OAuth2 客户端通用配置中以逗号分隔文本维护 scope；OpenAPI scope 不支持通配符；菜单权限标识不能代替 OpenAPI scope。
3. 客户端只能为已授权 scope 获取令牌；未获得 `payment` scope 时，支付创建、查询和退款接口均拒绝请求且不产生副作用。
4. 已授权客户端可通过平台创建微信或 Adapay 支付单并获得平台支付单标识及渠道支付信息；调用方无需提交或持有渠道商户密钥。
5. 相同客户端对同一业务订单按相同内容重试，不会形成重复扣款；订单标识冲突时返回明确错误。
6. 客户端可查询自身范围内支付单及平台确认的最终状态；无法读取其他客户端支付记录。
7. 已授权客户端可对符合规则的已支付订单申请全额退款，并可区分退款已受理与最终退款完成。
8. 已获 `payment` scope 的第三方可通过平台发起微信商家转账并取得用户确认参数；缺少该 scope 的客户端不能转账。
9. 平台可将支付和商家转账终态通知到客户端预先配置的地址；通知以明文 JSON 投递，重试和重复事件规则在设计规格中可验证。
10. 重要支付、退款和转账操作能关联到客户端、平台交易单和租户审计；日志不包含秘密凭据或完整收款 OpenID。

## Assumptions

- 支付渠道支持微信支付和汇付（Adapay）；支付宝及其他渠道不在本期范围。
- 本期包含支付创建、支付单查询、全额退款、微信商家转账发起及支付/转账结果通知，并在支付配置页面提供 OpenAPI 开关和 Webhook 地址。
- 用户付款由第三方按支付渠道提供的支付数据完成；平台不提供托管收银页。
- 支付和商家转账 API 统一使用 `payment` scope。admin 在 OAuth2 客户端通用配置中按逗号分隔文本维护。
- OpenAPI scope 不支持通配符。令牌申请的 scope 可省略，省略时授予客户端登记的全部 scope；显式请求时必须精确匹配客户端登记范围。
- 退款资格、退款渠道执行和微信支付异步处理复用平台现行能力；本需求不更改既有用户订单退款语义。
- 现有 OAuth2 客户端对象已保存 scope 列表并支持 client-credentials 授权；OpenAPI scope 使用现有 OAuth2 客户端 scope 列表；管理页面以文本输入多个 scope，不做固定选项穷举。
- 平台接口前缀规则已由本功能设计修订为独立 `/open-api`；现有 `/app-api` 会员路径与支付渠道回调不迁移。
- 首期不包括独立商家转账查询/撤销、部分退款、第三方支付配置管理和平台 H5 收银页面；用户确认收款由集成方客户端使用微信参数完成。
