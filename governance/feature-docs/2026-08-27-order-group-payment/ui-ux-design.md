# 拼单支付管理端 UI/UX 设计

## 目标与范围

本期仅为管理后台提供拼单配置，不实现小程序拼单页、分享页或用户支付界面。管理端需要让管理员清楚区分租户总开关、门店覆盖配置和付款时限。

## 租户配置

沿用现有租户参数管理页面，新增拼单支付参数记录，不改造参数类型或参数管理页面结构。现有参数统一按字符型保存，本功能只约定参数值内容：

| 参数 | 控件 | 说明 |
|---|---|---|
| `order.group-payment.enabled` | 字符串 | 保存 `0` 或 `1`；租户总开关，关闭时所有门店均不可创建拼单订单 |
| `order.group-payment.timeout-minutes` | 字符串 | 保存分钟数字符串；从发起人首份支付成功开始计算 |

配置说明文案：

> 本功能仅使用 AdaPay。付款时限只影响新开始的拼单订单，已开始的拼单订单使用订单中保存的截止时间。

## 门店配置

在门店编辑表单增加“拼单支付”配置，支持三态：

- 继承租户配置
- 启用
- 禁用

展示最终生效结果，例如“当前生效：启用（门店覆盖）”或“当前生效：禁用（继承租户配置）”。

当租户总开关关闭时，门店仍可保留“启用”覆盖值，但最终生效结果必须显示为“禁用（租户总开关关闭）”，避免管理员误以为门店可以使用。

## 交互与校验

- 使用现有参数页面的字符型表单和权限控制。
- 参数值按约定保存为字符串；不新增参数类型区分，也不修改 `infra_tenant_config.type` 的现有语义。
- 配置变更成功后刷新参数列表或详情。
- 本期不在管理端新增拼单支付明细操作、单笔支付退款和拼单分享操作。

## 服务订单详情

- 在现有“商品明细”区域附近增加“拼单支付明细”区域，仅当 `groupPaymentDetails` 非空时展示。
- 使用表格展示：拼单成员、付款人、支付份数、支付金额、支付时间和支付标识。
- 无明细时不占用弹窗空间；支付金额使用现有金额格式，时间使用现有日期格式。
- 仅展示信息，不增加支付、退款或编辑操作。

## 无障碍与响应式

- Switch、三态选择和付款时限输入均提供明确的字段标签和单位。
- 禁用状态、继承状态和最终生效状态不能只依靠颜色区分。
- 沿用现有 Element Plus 表单布局、提示和错误反馈。
