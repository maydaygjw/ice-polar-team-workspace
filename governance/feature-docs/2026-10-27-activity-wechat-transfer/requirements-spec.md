# 活动微信打款需求规格

## Scope

### In

- 活动奖品的兑奖规则增加“微信打款”，用于将现金奖励转入中奖/推荐奖励用户的微信零钱。
- 兑奖时由后端创建微信商家转账单，并将转账状态和活动来源写入现有用户微信转账明细。
- 统一会员详情手动打款与活动推荐现金奖励的数据源；记录包含转账类型、金额、微信状态、备注、商户单号和微信转账单号。
- 推荐现金奖励备注可识别活动、活动期次及达到的推荐层级。
- 财务模块新增“用户转账”菜单，按当前租户和后台数据权限分页查看用户转账明细；提供类型、状态、用户及备注关键字筛选。
- 会员详情展示该会员统一转账明细及类型、备注；保留现有手动微信打款入口。
- 后台显示等待用户确认、处理中、成功、失败或已撤销等微信转账结果，不将接口受理当作到账成功。
- 本期后台配置与后端能力不代表端到端现金奖励已开放；用户端调起确认收款完成前，不得面向用户正式投放该规则。

### Out

- 本期不修改 H5 或原生小程序的用户页面，不在客户端调起微信确认收款页面；后端契约须为后续客户端集成保留所需收款参数。
- 不接入微信支付之外的新转账渠道，不改变非现金奖品的现有兑奖方式。
- 不自动补发历史活动或会员打款记录，不从微信侧批量回填既有转账。
- 财务“用户转账”菜单本期只查询展示，不提供发起、撤销或人工改写转账状态的操作。

## Use Cases

| 角色 | 目标 | 主流程 |
|---|---|---|
| 活动运营人员 | 配置现金兑奖 | 在活动奖品规则中选择“微信打款”并配置奖励金额→保存活动配置 |
| 活动用户 | 领取现金奖励 | 按现有兑奖入口提交兑奖→后端创建微信转账→用户后续在微信端确认收款→商家和用户可查看最终状态 |
| 财务人员 | 核对用户转账 | 打开“财务 > 用户转账”→筛选并查看会员手动打款和活动推荐现金奖励记录及微信状态 |
| 运营人员 | 查看某会员转账历史 | 打开会员详情→查看统一转账明细、业务类型和备注；从既有入口发起会员手动打款 |

## Business Rules

1. 活动兑奖规则中的微信打款只允许绑定明确的现金金额；金额必须大于 0 且最多保留两位小数。
2. 用户兑奖时后端为对应奖励创建一笔商家转账，并登记到共享用户转账明细；同一奖励的重复请求不得产生重复打款。
3. 用户确认收款之前，转账状态保持待确认/处理中；只有微信最终状态为成功时才表示实际到账。转账失败时保留记录和失败原因，兑奖允许按既有失败重试规则处理。
4. 推荐奖励现金打款的类型明确标识为“推荐奖励现金打款”；其备注应包含活动名称、期次和推荐阶梯信息。会员详情人工打款记录使用独立的类型并显示其打款备注。
5. 会员手动打款和活动现金奖励共用同一明细集合、状态语义与租户隔离规则；记录不得因来源不同而重复存储在相互独立的明细中。
6. 财务菜单和会员详情只展示后端记录，不提供编辑金额、类型、备注或状态的能力。详情中保留已有手动打款发起入口。
7. 查询结果按当前租户隔离，并遵循管理端既有数据权限；不能通过用户 ID、活动期次或订单号查询其他租户数据。
8. 本期不包含用户端确认收款页面。后台转账“已受理”或“待用户确认”不可显示为“已到账”。
9. 历史手动打款记录需映射到会员手动打款类型，且保留其金额、微信状态及备注。

## Frontend Requirements

### Admin

- 活动奖品规则选择器增加“微信打款”；表单展示金额配置及规则说明。
- “财务 > 用户转账”提供分页表格，显示用户、转账类型、金额、微信状态、备注、商户单号、微信转账单号、失败原因和发起时间；支持类型、状态、用户、备注关键字筛选。
- 用户转账菜单为只读；空结果、加载失败、无权限和无数据状态有明确提示。
- 会员详情的微信打款记录展示类型和备注；记录只读并保留会员详情现有手动打款按钮。
- 后台必须用状态文字区分待用户确认、处理中、成功、失败和撤销，不只依赖颜色。

## Edge Cases

- 微信转账接口响应未知或超时：保留原商户单号并查单/幂等重试，不以新单号重复打款。
- 用户尚未确认收款：记录保持待确认；后台不得将兑奖/转账展示为已到账。
- 微信返回失败或超时关闭：记录保留失败状态及原因；再次兑奖不得重复生成已成功的转账。
- 并发或重复兑奖：同一活动奖励只能关联一笔有效转账。
- 会员缺少小程序 OpenID、微信商户配置不可用或规则金额不合法：不得创建伪成功记录；返回可理解错误并允许修正后重试。
- 活动名称、期次或档位后续被修改：已创建转账的备注仍能辨认原活动奖励来源。
- 类型/状态/用户筛选组合为空或跨租户 ID：返回空结果或权限隔离结果，不泄露其他租户信息。

## Acceptance Criteria

1. 活动奖品规则能配置微信打款金额，保存后活动兑奖可触发后端商家转账。
2. 活动兑奖创建的记录与会员详情手动打款记录出现在同一转账明细来源中，类型和备注可区分来源。
3. 推荐奖励现金打款记录可从类型识别，并在备注中辨认活动、期次和推荐层级。
4. 财务菜单可分页查看并按类型、状态、用户和备注关键字筛选用户转账明细；该页面不能编辑或发起转账。
5. 会员详情显示同一会员全部转账记录及类型、备注，记录只读，已有手动打款入口仍可使用。
6. 管理端正确区分待用户确认/处理中与最终成功/失败/撤销状态；未收到最终成功状态时不显示已到账。
7. 重复兑奖、并发请求或请求超时不会创建重复的有效转账单；失败原因和最终状态可追踪。
8. 所有新查询均遵守租户和后台数据权限，跨租户用户筛选不能读取数据。
9. 现有人工打款及非现金奖品兑奖行为保持兼容。

## Assumptions

- 活动端继续使用现有兑奖入口；本期仅修改 backend 和 admin，用户端调起微信确认收款页面作为后续独立阶段。
- “推荐奖励的现金打款”是共享明细中的独立转账类型；会员详情手动打款保留另一种类型。
- 本期财务菜单只读；现有查询/撤销能力不在新菜单中新增。
