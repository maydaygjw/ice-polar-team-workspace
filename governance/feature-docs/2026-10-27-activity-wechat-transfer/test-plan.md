# 活动微信打款测试计划

## 环境前置

- 使用本地/测试环境和隔离测试租户；不得使用生产商户、真实用户或生产资金。
- 测试租户配置可调用商家转账的 APIv3 商户参数、绑定 AppID、接口安全 IP 和已报备转账场景；自动化优先使用模拟微信响应/回调。
- 配置测试会员：一位拥有当前租户 `routineOpenid` 的用户及一位缺少 `routineOpenid` 的用户。
- 为财务查询权限和会员详情打款权限配置独立测试角色。

## API 场景

1. 创建活动推荐现金转账：验证返回商户单号、状态和 `packageInfo`；记录类型、金额和包含活动/期次/层级的业务备注正确。
2. 同一奖励重复/并发兑奖：只存在一笔处理中转账；相同商户单号查单/重试不会重复付款。
3. 注入成功、失败、撤销终态回调：验签/解密通过后共享记录和活动兑奖状态一致；重复回调不重复处理。
4. 伪造签名、金额不匹配、商户号不匹配、跨租户商户单号：拒绝更改财务状态。
5. 微信接口超时或未知结果：记录保留原商户单号与待确认状态；不得换单重试。
6. 缺少会员 OpenID、金额不合法、微信配置/场景缺失：不产生成功兑奖；返回可定位业务错误。
7. 终态失败/撤销后允许新的明确重试；原流水保留，新尝试仍关联同一活动奖励。
8. 全局分页按类型、状态、用户、备注关键字和时间过滤；校验租户及数据权限隔离。
9. 会员详情分页只返回指定会员的共享记录；无会员 ID 时不能获取全租户数据。
10. 同一通知 URL 分别接收支付成功事件和转账终态事件时，事件按类型分发至对应处理逻辑；重复回调幂等应答。

## Admin E2E 场景

1. 活动模板选择“微信打款”、配置金额并保存/重新打开，验证配置回显和金额校验。
2. 财务用户转账列表查看会员人工、活动中奖和推荐奖励三类记录；类型、活动备注、微信状态、失败原因和分页筛选准确。
3. 会员详情显示共享记录中的类型/备注且没有行内操作；原会员手动打款入口按权限显示。
4. 无财务查询权限的角色看不到菜单，直接请求列表接口被拒绝。
5. 验证待确认、处理中、成功、失败、已撤销及未知状态均以文字可辨认。

## 状态

- 不在本阶段调用真实微信支付转账接口；若后续需要真实商户联调，先确认测试环境、金额和副作用。
