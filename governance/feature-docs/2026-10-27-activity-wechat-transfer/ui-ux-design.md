# 活动微信打款 UI/UX 设计

## 活动模板：兑奖规则

- 在现有兑奖规则选项中增加“微信打款”。选中后显示金额输入框（元），说明“用户领取后将发起微信转账；用户确认前不代表到账”。
- 使用金额格式校验；提交错误显示在金额输入框附近，保留其他已填配置。
- 已生成期次按已保存的规则快照展示，不随模板后续修改变化。

## 财务：用户转账

- 在财务模块新增“用户转账”菜单，独立页面沿用后台列表页筛选栏、表格密度、分页和权限控制方式。
- 筛选项：用户/会员、转账类型、微信状态、备注关键字、创建时间。默认按创建时间倒序。
- 表格列：用户、类型、金额、微信状态、备注、商户单号、微信转账单号、失败原因、发起时间。
- 类型显示“会员人工打款”“活动中奖现金打款”“推荐奖励现金打款”；推荐奖励业务备注包含活动、期次和推荐阶梯。
- 状态使用文字标签；颜色仅作辅助。待用户确认、处理中、成功、失败、已撤销和未知状态均有明确文本。
- 全局页面只读，不显示发起、撤销、查单或编辑按钮。
- 加载时显示表格骨架/加载态；无记录展示空态；请求失败提供重试；无查询权限时隐藏菜单并由后端拒绝接口访问。
- 小屏视口表格允许横向滚动或切换为摘要卡片，避免筛选控件和金额列被截断。

## 会员详情：微信打款记录

- 保留现有会员详情“微信打款”发起入口和记录分页；记录新增类型和业务来源/备注列。
- 列表仅展示，不提供查询状态、撤销或编辑记录的行内按钮；查询状态由微信回调和后端兜底查单更新。
- 人工打款行显示“会员人工打款”类型及既有备注；活动打款行展示活动名称、期次、推荐层级和微信状态。

## 设计依据

- 复用现有 Vue 3、Element Plus 后台视觉与列表模式，不新增全局样式体系。
- UI/UX Pro Max 搜索建议：表单提交后给出明确状态反馈；状态不可只靠颜色表达；宽表格需避免窄视口溢出。
