# UI/UX 设计 — 订单计费模板与应收应付

## 范围与导航

在管理后台“财务管理”下新增：

1. 计费项管理
2. 计费模板管理
3. 应收应付管理

旧“店铺分账计费规则”入口在新引擎切换后隐藏。“分账收款人管理”和“分账结算记录”保留，分别作为主体来源和 AdaPay 执行结果。

## 通用交互原则

- 复用现有 Vue 3 + Element Plus 管理页布局、分页、弹窗、表单验证和权限指令。
- 金额统一以“元”展示，保留两位小数；比例输入显示 `%`。
- 列表默认使用紧凑密度，费用明细超出主视口时使用横向滚动，不压缩金额列。
- 删除、停用、重新计算等会改变配置或财务记录的操作使用确认对话框。
- 字段、收款人、商圈或标签失效时，显示快照名称和“已失效”标记，不显示空值。

## 计费项管理

### 页面结构

1. 查询区：计费项名称、计费方式、状态，“搜索/重置”。
2. 操作区：“新增计费项”。
3. 列表：名称、计费方式、订单属性、校验状态、启用状态、更新时间、操作。

### 新增/编辑弹窗

| 字段 | 交互 |
|---|---|
| 计费项名称 | 必填文本框，失焦时可校验重名。 |
| 计费方式 | 单选：订单比例/订单属性。 |
| 订单属性 | 仅属性类型显示，必填；右侧为“校验字段”按钮。 |
| 状态 | 默认启用。 |

字段校验反馈：

- 校验中：按钮 loading，防止重复提交。
- 成功：绿色提示“字段存在，数据类型为 DECIMAL”。
- 失败：表单项下红色错误，保存按钮不可用。
- 已被模板引用时，计费方式和属性设为只读，说明“已用于计费模板”。

## 计费模板管理

### 列表页

查询条件：模板名称、商圈、门店标签、模板类型（全局默认/商圈）、状态。

列表字段：模板名称、类型、商圈、门店标签、优先级、计费项数量、手续费承担主体、状态、更新时间、操作。全局默认模板使用明确标签，商圈/标签列显示“全部”。

### 编辑页/大弹窗

建议使用独立页或宽度不低于 1100px 的大弹窗，分两个区域：

#### 基本信息

- 模板名称
- 全局默认开关
- 商圈（非默认时必填）
- 门店标签（可选）
- 优先级
- 支付通道手续费承担主体
- 启用状态

打开全局默认后，商圈和门店标签自动清空并禁用。已有启用默认模板时，页面在保存前提示冲突模板名称，后端仍做最终校验。

#### 计费明细

使用可编辑表格：

| 列 | 交互 |
|---|---|
| 顺序 | 拖拽或上移/下移，页面自动重排。 |
| 计费项 | 仅选择启用项，已选项在后续行禁用。 |
| 计费方式 | 根据计费项只读展示。 |
| 基数/订单属性 | 比例项选择券前/券后；属性项直接显示计费项绑定的订单属性字段，只读取该字段值，不展示券前/券后选择。 |
| 比例 | 仅比例项输入，范围 0–100；属性项隐藏该列或显示“无需配置”。 |
| 收款主体 | 先选“当前商家/固定收款人”；固定时搜索本租户启用收款人。 |
| 操作 | 删除当前行。 |

订单属性计费项选择后，系统直接使用计费项绑定的订单属性金额；该行不需要配置券前/券后和比例，用户只需选择收款主体。顺序仍由通用明细排序控制，用于金额分配。

表格上方提示：“非商家计费项将按顺序分配；金额不足时当前项取剩余，后续项为 0；剩余金额归商家。”

保存时页面先定位第一个错误行，后端错误需映射回模板头或指定明细行。

## 应收应付管理

### 列表页

查询条件：订单号、门店、商圈、计算状态、确认收货时间范围。

列表字段：订单号、门店、商圈、券后金额、平台补贴、可计算金额、命中模板、计算状态、确认收货时间、计算时间、操作。

状态展示：

- 成功：绿色。
- 成功但有差异：黄色，鼠标悬停提示“存在理论金额未足额分配”。
- 计算失败：红色，列表展示截断后的失败原因。
- 计算中：灰蓝色 loading 状态，不显示操作按钮。

只有失败行显示“重新计算”。确认框明示：“将使用当前最新有效模板，成功后不可再重算。”

### 详情弹窗

宽度建议 1200px，自上而下分为：

1. **订单与模板**：订单、门店、商圈、确认收货时间、模板 ID/名称快照。
2. **金额口径**：券前、优惠、券后、平台补贴、可计算金额；同时显示公式。
3. **计费明细**：顺序、计费项、计费方式、基数/属性值、比例、理论金额、实际金额、收款主体、差异备注。理论与实际不一致行使用浅黄背景。
4. **主体汇总**：收款主体、应收/应付金额、手续费承担方、AdaPay 准备状态。
5. **失败/AdaPay 衔接**：按需显示失败码与原因，或分账订单号与状态。

银行卡号、证件号和手机号不在本详情中返回或展示。

## 加载、空和错误状态

- 首次加载：表格 loading，保留查询条件。
- 空列表：区分“尚未配置”和“无符合筛选条件的数据”；有创建权限时提供首次创建按钮。
- 选项加载失败：商圈、标签或收款人下拉显示重试入口，不允许保存不完整模板。
- 提交失败：保留已输入内容，展示后端业务错误，不关闭弹窗。
- 重算超时：恢复按钮，刷新当前行状态，不自动重复提交。

## 适配

本期仅管理后台桌面端。在 1280px 及以上完整展示；较小视口中表格横向滚动，表单改为单列。不新增小程序或移动管理端交互。
