### 需求歧义点

"对接积分系统"存在多种理解方向：

**方向 A：完善内部积分获取链路**
- 消费返积分（按订单金额比例返积分）
- 每日签到获取积分（连续签到阶梯奖励）
- 积分规则后台配置（返积分比例、签到积分值）
- 用户积分明细查询

**方向 B：对接外部积分平台**
- 对接第三方积分系统 API
- 积分同步/兑换外部积分
- 外部积分查询接口

**方向 C：积分系统管理后台**
- 在 admin 后台增加积分规则配置页面
- 积分流水查询/统计
- 用户积分手动调整

### 推荐方案（方向 A：完善内部积分获取链路）

基于现有代码推断，最可能的需求是**方向 A**，因为：
1. 系统已有积分商城但无获取途径，积分系统不完整
2. 已有签到相关 VO 字段（`signNum`, `isDaySign` 等），说明曾规划签到功能
3. `BillDetailEnum` 已预留 `TYPE_10("sign","签到")`
4. 无外部积分平台相关的配置或接口痕迹

**推荐实现范围**：
1. **积分规则配置表** + admin 管理页面
   - 消费返积分比例（如 1元 = 1积分）
   - 签到基础积分 + 连续签到阶梯奖励
2. **支付成功后返积分** — 在 `AppStoreOrderServiceImpl.paySuccess()` 中触发
3. **签到功能 API** — C-end 签到/查询签到状态
4. **用户积分明细 API** — 查询积分收支流水
5. **用户积分余额展示** — miniapp 个人中心显示积分
