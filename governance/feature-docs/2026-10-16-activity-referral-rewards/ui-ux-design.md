# 活动推荐阶梯奖励 UI/UX 设计

## 管理端：活动模板向导

### 向导结构

现有模板向导为基础信息、时间/报名规则、奖品配置三步；新增第四步“推荐奖励”，置于最后。原“推荐报名增加一次抽奖/游戏机会”开关继续留在原规则步骤，说明其只增加当期机会；新步骤只配置阶梯奖品。

### 推荐奖励配置

- 新人推荐、普通推荐分为两个独立卡片/表单区。卡片标题下显示规则摘要：新人只在活动模板下首次成功参加时计入；新人也计入普通人数。
- 每种类型下以重复行编辑阶梯：人数门槛、奖品选择、推荐奖励数量、删除操作；卡片底部提供“新增阶梯”。行按人数门槛升序排列。
- 数量标签写为“本期推荐奖励份数”，并辅助说明“独立于开奖奖品数量”。奖品名、图片和兑奖说明从活动奖品库带入。
- 阶梯摘要即时预览，例如“普通推荐 3 人：A；5 人：B（达到 5 人时同时获得 A、B）”。新人和普通分开展示。
- 空配置状态说明不启用对应类型的阶梯奖品奖励；不影响旧机会开关。
- 奖品为空、人数非正整数/重复/顺序错误、数量非正整数时在对应控件下显示具体错误；提交失败后保留输入，并将焦点移到错误汇总/首个无效控件。
- 键盘可操作新增、删除、选择和人数编辑；仅图标按钮有可访问名称；不依赖颜色单独区分新人/普通类型。

### 期次记录

在期次结果/中奖管理区域增加“推荐奖励”页签或独立表格入口，明确与“中奖记录”分开。表格展示推荐人、类型、达成档位、奖品、奖励时间、兑奖码、兑奖状态和兑奖时间。此表格无后台代兑奖、发送中奖通知、中奖海报按钮。

## H5：活动详情与奖励

### 阶梯说明

- 活动详情中展示新人推荐和普通推荐两组奖品阶梯，读取期次快照；未登录用户可以查看规则和奖品，但不能看到个人进度或奖励记录。
- 登录且已报名用户在活动结果区域展示两张进度卡：当前人数/下一档人数、已达档位、剩余人数。普通人数包含新人；新人进度只累计本模板首次参加的用户。
- 每档奖励行显示奖品图片、名称和门槛；较高档说明包含此前已达档奖励。数量耗尽的档位标注“本期已发完”。

### 我的推荐奖励和兑奖

- 当前用户在该期的推荐奖励按档位分别列出；每行显示奖品、类型/门槛、兑奖说明和状态。
- 待兑奖且为线上奖品时显示“立即兑奖”；点击后展示加载状态，成功后刷新为“已兑奖”，失败时保留重试入口并展示错误原因。
- 处理中状态禁止再次点击；已兑奖状态展示成功时间。线下兑奖显示兑奖码、复制操作和现有客服提示，不调用线上发放动作。
- 推荐奖品记录单独于中奖结果列表，不进入中奖名单、公示海报和分享提示；原抽奖/游戏机会展示与分享提示保持原行为。

### 响应式、状态与可访问性

- H5 手机窄屏采用单列卡片；奖品图片固定比例并预留空间，避免异步加载造成内容跳动。长奖品名允许换行，不出现横向滚动。
- 主要操作目标至少 44 CSS px，邻近按钮间距不少于 8 px；复用现有字号、语义色和圆角，不新建全局视觉样式。
- 进度同时显示文字和数值，不只使用颜色或进度条表达。图片提供可理解的替代文本；兑奖和复制按钮有明确可访问名称及焦点态。
- 数据加载时为两组进度和奖励列表显示稳定骨架；无配置时不渲染区块；已配置但暂无推荐时显示“分享后好友报名即可累计本期进度”；请求失败提供重试入口。
- 管理端和 H5 表单/操作错误就近展示；表单提交错误同时提供可聚焦的错误摘要及对应字段定位。
