# 端到端测试计划：business-region 权限体系

## 测试场景

### 管理后台

1. 创建绑定部门的 `business-region`。
2. 在 `business-region` 下创建门店。
3. 一个门店分配多个管理员。
4. 一个用户分配多个门店。
5. 多门店管理员登录后，验证门店范围列表展示其全部可管理门店。
6. 部门受限角色登录后，验证 `business-region` 和门店列表按部门过滤。
7. 使用无效或停用的 `business-region` 创建/编辑门店时应失败。
8. 验证每个租户只有一个默认 `business-region`。
9. 验证默认 `business-region` 不能直接删除。

### 小程序

本期暂不实现小程序端，相关用例后续补充。

### 跨系统链路

1. 管理后台创建区域和门店。
2. 后端根据门店归属写入新业务数据的 `business_region_id` 和 `dept_id`。
3. 匹配部门和门店权限的后台用户可以看到业务数据。
4. 不在部门或门店权限范围内的后台用户看不到业务数据。

## 端到端用例

| 编号 | 流程 | 预期结果 |
|---|---|---|
| 商圈权限-001 | 管理后台创建 `business-region` | 区域出现在后台列表和选择器中 |
| 商圈权限-002 | 管理后台在区域下创建门店 | 门店保存 `businessRegionId` 和派生 `deptId` |
| 商圈权限-003 | 用户绑定门店 A+B | 用户登录上下文包含两个门店 ID |
| 商圈权限-004 | 多门店管理员打开订单列表 | 可见门店 A+B 订单，不可见门店 C 订单 |
| 商圈权限-005 | 租户初始化或迁移 | 每个租户存在且仅存在一个默认区域 |
| 商圈权限-006 | 删除默认区域 | 后端拒绝删除并提示先设置新的默认区域 |
| 商圈权限-007 | 设置新的默认区域 | 新区域成为默认区域，旧默认区域取消默认标记 |

## 测试数据

- 至少一个租户，包含两个部门。
- 每个租户有一个默认 `business-region`。
- 部门 A：
  - business-region A1
  - 门店 A1-1、门店 A1-2
- 部门 B：
  - business-region B1
  - 门店 B1-1
- 后台用户：
  - 租户管理员
  - 部门 A 管理员
  - 绑定门店 A1-1 和 A1-2 的门店管理员
  - 未绑定门店的普通门店用户

## 环境要求

- 后端测试环境包含 MySQL 8.0 和 Redis。
- 管理后台具备不同角色的测试账号。
- 后端实现完成后重新生成接口快照。
