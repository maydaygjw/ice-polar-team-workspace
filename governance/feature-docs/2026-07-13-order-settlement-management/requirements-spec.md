## Feature: 订单结算管理

### Scope

**In Scope**

1. 在管理后台「订单中心」菜单下新增「订单结算管理」页面，以订单维度展示 Adapay 支付订单的结算状态。
2. 列表展示：订单号、店铺名称、订单金额、支付时间、订单状态、结算状态（分账状态）、分账时间。
3. 支持按订单号、店铺、订单状态、结算状态、支付时间范围筛选。
4. 点击订单弹窗（Dialog）查看结算明细，展示：
   - 分账订单基本信息（Adapay 支付 ID、确认 ID、分账时间）
   - 各角色分账明细（角色名称、收款人姓名、分账金额、是否承担手续费）
   - 收款人银行卡信息（银行名称、银行卡号脱敏摘要、开户省份/城市）
   - 手续费承担方标记（仅标注「是/否」，不展示手续费金额）
5. 结算状态映射：
   - **未结算**：非 Adapay 支付，或 Adapay 支付但未创建分账记录
   - **待分账**：分账记录 `sharing_status=0`
   - **分账中**：分账记录 `sharing_status=1`
   - **已结算**：分账记录 `sharing_status=2`（Adapay 分账成功）或 `sharing_status=4`（已回退到虚拟余额结算），商家实际已收到钱
   - **分账失败**：分账记录 `sharing_status=3`
6. 列表默认按支付时间倒序排列。
7. 结算明细以弹窗（Dialog）方式展示，仅 Adapay 支付且存在分账记录的订单可打开明细弹窗。

**Out of Scope**

- 非 Adapay 支付渠道（微信、支付宝、余额、现金）的结算管理——这些订单直接标记为「未结算」即可。
- 结算操作（手动分账、重试分账）——已在「分账结算记录」页面实现。
- 对账功能——已在「日终对账记录」页面实现。
- 结算数据导出（deferred）。
- 退款订单的结算回退展示（本期仅展示当前结算状态，不追溯退款影响）。

**Deferred**

- 结算记录 CSV/Excel 导出。
- 结算数据统计看板（结算率、失败率趋势等）。
- 退款对结算状态的影响追踪。

### Use Cases

**UC-1: 财务/运营人员查看订单结算列表**

- 角色：平台财务、运营、租户管理员
- 目标：查看所有 Adapay 订单的结算状态，快速定位未结算或结算异常的订单。
- 主流程：
  1. 用户进入「订单中心 → 订单结算管理」页面。
  2. 页面默认展示所有订单的结算状态列表（含非 Adapay 订单，标记为「未结算」）。
  3. 用户可按订单号、店铺、订单状态、结算状态、支付时间范围筛选。
  4. 列表展示订单号、店铺名称、订单金额、支付时间、订单状态、结算状态、分账时间。
  5. 用户点击某条订单的「查看明细」，弹出 Dialog 查看结算明细。
- 业务规则：
  - 租户管理员只看到自己租户的订单。
  - 平台财务/超管可选择租户查看。
  - 非 Adapay 支付订单的结算状态统一显示为「未结算」，不可展开。

**UC-2: 查看单笔订单的结算明细**

- 角色：平台财务、运营、租户管理员
- 目标：查看一笔 Adapay 订单的完整分账结算信息。
- 主流程：
  1. 用户点击列表中某条 Adapay 支付订单的「查看明细」。
  2. 系统展示结算明细区域，包含：
     - 分账基本信息：Adapay 支付 ID、确认 ID、分账时间、计算方式（计费规则/佣金回退）
     - 分账明细表：每条明细展示角色（平台/店铺/配送方/销售方）、收款人姓名、分账金额、手续费标记
     - 收款人银行卡信息（脱敏）：银行名称、银行卡号（脱敏）、开户省份/城市
  3. 用户关闭明细，返回列表。
- 业务规则：
  - 分账明细按 role 排序（平台 > 店铺 > 配送方 > 销售方）。
  - 银行卡信息仅展示脱敏字段，不展示完整卡号。
  - 分账失败时展示 `error_msg` 错误信息。

### Business Rules

1. **结算状态判定**：仅 `pay_type = adapay` 且在 `yshop_adapay_profit_sharing_order` 中存在记录的订单才计算结算状态；不存在分账记录的统一标记为「未结算」。
2. **订单-分账关联**：通过 `yshop_store_order.order_id = yshop_adapay_profit_sharing_order.order_id` 关联。
3. **多租户隔离**：所有查询基于 `tenant_id` 过滤；平台财务可选择租户。
4. **数据脱敏**：银行卡号仅展示脱敏摘要（`settle_account_card_no_mask`），不返回完整卡号。
5. **只读页面**：本页面不提供任何结算操作按钮；操作类需求跳转至已有的「分账结算记录」页面。
6. **分账明细完整性**：无分账记录的 Adapay 订单（如支付后未创建分账挂起记录）标记为「未结算」；`sharing_status=2` 或 `sharing_status=4` 均标记为「已结算」。
7. **手续费展示**：仅展示「是/否」承担手续费标记（`fee_flag`/`fee_bearer_role`），不展示手续费金额。

### Edge Cases

- 同一订单号在 `yshop_adapay_profit_sharing_order` 中可能存在多条记录（重试/重跑场景）——取最新一条（`create_time` 最大）展示结算状态。
- Adapay 支付但分账记录中 `sharing_status=4`（已回退到虚拟余额结算）——结算状态显示为「已结算」，明细弹窗中标注回退信息（`fallback_revenue=1`）。
- 非 Adapay 支付订单（微信/支付宝/余额/现金）——统一显示「未结算」，不可展开明细。
- 支付时间为空的订单——按创建时间排序兜底。
- 订单状态为已退款（`status=-1` 或 `refund_status=2`）但分账记录仍存在——展示实际结算状态并标注退款信息。
- 收款人已被删除/禁用——分账明细中的收款人信息来自分账明细固化时的快照；若关联查询返回空，展示「收款人已删除」。

### Acceptance Criteria

- [ ] 订单中心菜单下出现「订单结算管理」入口，权限控制正确。
- [ ] 列表正确展示所有订单（含非 Adapay 订单），Adapay 订单带结算状态。
- [ ] 结算状态正确映射：未结算/待分账/分账中/已结算/分账失败/已回退。
- [ ] 按订单号、店铺、订单状态、结算状态、支付时间范围筛选功能正常。
- [ ] 点击 Adapay 订单可查看结算明细（分账基本信息 + 明细表 + 收款人银行卡脱敏信息）。
- [ ] 非 Adapay 订单不可展开明细。
- [ ] 租户管理员只能看到本租户数据。
- [ ] 银行卡信息只展示脱敏版本，不泄露完整卡号。
- [ ] 分账失败的订单展示错误信息。

---

### Assumptions

1. 支付类型枚举值 `adapay` 已在 `pay_type` 字段中使用，可直接用于过滤。
2. 订单-分账记录为一对多关系（重试产生多条），本页面始终取最新一条。
3. 页面为只读，不需要对接 Adapay API 或触发任何支付/分账操作。
4. 数据量较大（订单表 + 分账表联合查询），后端需要分页 + 索引优化。
5. 收款人银行卡信息查询为联表查询，性能可接受（分账明细数量有限，每笔订单 ≤4 条）。
