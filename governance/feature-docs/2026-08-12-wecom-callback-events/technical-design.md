# 企业微信客户联系回调技术设计

## 模块影响

- `yshop-module-mp-biz`：扩展企业微信账户回调凭据，新增公开回调 Controller 与验签解密服务。
- `yshop-server`：登记公开回调与租户忽略路径。
- `sql`：为 `mp_wecom_account` 增加回调 Token 和 EncodingAESKey。
- `admin`：扩展企业微信配置类型、录入表单和列表状态。
- 不影响 miniapp、DMS、MQ 和现有客户同步流程。

## 关键决策

1. 使用 `/app-api/mp/wecom/callback/{accountId}`。GET 在解密前无法从密文确定租户，且 CorpID 可能跨租户重复，因此用全局账户 ID 定位配置。
2. Token、EncodingAESKey 与客户联系 Secret 语义不同，独立加密存储；存量账户字段为空时仅回调不可用。
3. 回调查询显式忽略请求携带的租户上下文，定位账户后使用账户真实租户记录日志，为后续业务处理保留正确边界。
4. 复用项目现有 WxJava 4.6.0 的签名与 XML 能力，并扩展 AES 解密以校验加密帧尾部 `receiveid/CorpID`；POST 解密后再校验 `ToUserName` 与账户 CorpID。
5. 不按事件类型分发。合法事件统一记录后返回 `success`，兼容企业微信新增事件。
6. XML 仅作安全解析，禁用 DOCTYPE、外部实体和 XInclude；日志清除 CR/LF，避免日志注入。
7. 管理端不回填回调凭据；编辑时根据 `callbackConfigured` 提示配置状态，同时留空由后端保留原值。

## 流程

### GET URL 验证

按账户 ID 跨租户查询配置 → 校验配置完整 → 验签、解密并校验帧尾 CorpID → 返回裸明文。

### POST 事件

按账户 ID 跨租户查询配置 → 验签、解密并校验帧尾 CorpID → 安全解析 → 校验 `ToUserName` → 记录请求信息与解密 XML → 返回裸文本 `success`。

## 迁移与回滚

- 新增可空字段，兼容存量数据；现有同步能力不依赖新字段。
- 回滚为删除两个回调凭据字段，执行前需确认不再使用回调。

## 风险

- 企业微信失败或超时会重试，本期无副作用但可能重复打印。
- 解密 XML 含客户标识，按用户要求用于联调日志；后续生产业务处理时应改为结构化脱敏日志。
- 未来开始更新业务数据时，必须另行设计幂等、乱序与补偿，不能直接扩展当前日志入口。
