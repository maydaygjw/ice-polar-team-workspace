# 需求规格：商圈目的地维护

## Scope

### In

- 在商圈管理列表每行增加“商圈目的地”操作按钮。
- 点击后在管理后台标签页打开目的地维护页面，并限定在当前商圈下。
- 支持目的地分页查询、新增、编辑和删除。
- 目的地字段：名称（必填）、代码、地图地址（必填）、标签、排序。

### Out

- 不新增小程序端目的地页面或接口。
- 不把目的地标签拆分为独立标签字典或关联表。
- 不改变商圈、门店、订单和支付状态规则。

## Use Cases

- 商圈运营人员从某个商圈进入目的地页，维护该商圈下的学校宿舍楼、医院楼栋等目的地。
- 运营人员通过名称或代码检索目的地，并按排序查看结果。

## Business Rules

- 每个目的地只属于一个商圈，不能跨商圈创建或更新。
- 目的地继承所属商圈的部门归属；用户不能直接编辑部门字段。
- 目的地查询和写操作同时受租户隔离及部门数据权限约束。
- 地图选择结果保存地址文本、经度和纬度；地址和经纬度必须完整。
- 删除采用现有后台逻辑删除语义。

## Frontend Requirements

- 商圈列表操作列提供“商圈目的地”按钮，并复用现有权限指令。
- 目的地页面展示当前商圈名称、筛选区、列表、分页和新增按钮。
- 表单提供名称、代码、地址地图选择、标签和排序；编辑时回填已有地图结果。

## Edge Cases

- 直接访问目的地页但缺少商圈编号：提示缺少商圈信息并返回商圈管理页。
- 当前商圈已删除或当前用户无权访问：页面按接口错误处理，不展示或提交目的地数据。
- 删除后目的地不应继续出现在当前商圈列表。

## Acceptance Criteria

- [ ] 商圈列表点击“商圈目的地”后新增一个后台标签页，并显示当前商圈的目的地列表。
- [ ] 新增时名称、地图地址和地图坐标校验生效，保存后列表可见。
- [ ] 代码、标签、排序可保存并在列表/编辑表单中回显。
- [ ] 编辑和删除只影响当前商圈下的目的地。
- [ ] 不同租户或无部门权限的商圈目的地不可查询、创建、更新或删除。

## Assumptions

- “标签”按单个文本字段保存，暂不支持多选标签关系。
- 目的地页面复用现有百度地图选择组件，地址展示为组件返回的完整地址文本。
