# 技术设计：订单每日序号

## 模块影响

- `backend/yshop-module-mall/yshop-module-order-biz`：订单 DO、计数 DO/Mapper、订单创建流程和响应 VO。
- `backend/sql`：订单字段与每日计数表升级脚本。
- `admin`、`miniapp`：本期无需代码改动；接口返回新增字段后保持向后兼容。

## 关键决策

1. 序号按租户、门店和服务端自然日计数，不复用已有全局自增取餐号表，避免改变 `numberId` 既有语义。
2. 使用数据库计数行的唯一约束和事务内原子递增，避免“查询最大值再加一”在并发下产生重复序号。
3. 订单创建先取得计数值并写入订单；序号写入订单后不再更新。计数更新与订单写入处于同一事务，失败时一起回滚。
4. 通过 MapStruct/BeanUtils 现有转换链把只读字段带入 admin/app 响应，不接受请求回写。

## 迁移与兼容

- 新字段 nullable，旧订单不回填。
- 新计数表首次使用时按订单创建日期生成当天记录；不扫描历史订单初始化，避免改变历史序号语义。
- 升级脚本提供反向 SQL；删除新字段前需确认旧版本已停止写入。

## 风险

- 应用服务器时区改变可能改变自然日边界；本期沿用现有服务器本地时间约定。
- 若未来需要按租户时区计数，需要引入明确的时区配置并调整日期计算，不能仅改展示层。
