# 测试计划 — 分账收款人结算

## 环境前置

- 测试租户配置 AdaPay 测试环境及至少一个平台级、一个店铺级收款人。
- 准备一条当前绑定记录、一条已解绑历史关系和一个旧结算账户快照。
- 准备 AdaPay Mock 响应：成功、空列表、失败、处理中和部分失败。
- 为测试账号配置查询和重新拉取权限，并准备无权限账号。

## 数据库迁移验证

1. 升级脚本创建 4 张新表，字段类型、默认值、主键、唯一键和查询索引与设计一致。
2. 重复执行升级脚本不会重复建表、重复建索引或重复插入菜单权限。
3. 绑定/解绑/换绑和收款人禁用不会删除或覆盖绑定历史记录。
4. 回滚脚本只删除本功能新增结构和菜单权限，不修改既有收款人、店铺及分账订单数据。

## API 场景

1. 汇总查询只读本地数据，不触发 AdaPay 请求。
2. 店铺 Tab 只返回店铺级收款人，历史解绑数据显示非当期。
3. 平台 Tab 可按平台、配送方、销售方过滤。
4. 日、周、月边界汇总金额、手续费和净到账金额正确。
5. 单日重新拉取返回任务标识，重复提交同一日期被拒绝或复用运行中任务。
6. 重新拉取幂等，不重复累计结算明细。
7. 单收款人失败不影响其他收款人，并产生部分失败状态。
8. 租户隔离、店铺数据范围和权限校验生效。

## E2E 场景

1. 财务从财务菜单进入页面，在两个 Tab 间切换并完成查询。
2. 店铺 Tab 按历史店铺查询解绑收款人，确认显示非当期和净到账金额。
3. 平台 Tab 按角色查询并打开结算明细。
4. 授权用户重新拉取某日，看到拉取中、完成和失败摘要状态。
5. 无重新拉取权限用户不显示操作入口。

## 验证备注

实现阶段填写实际命令、环境、数据和结果；需求/设计阶段不执行业务测试。
