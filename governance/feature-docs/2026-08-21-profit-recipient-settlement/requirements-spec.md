# 分账收款人结算

## Scope

### In Scope

1. 在「财务」菜单新增独立的「分账收款人结算」模块；不合并现有「店铺收入报表」。
2. 每日定时获取前一日所有分账收款人的 AdaPay 结算明细，并保存到本地。
3. 支持按指定单日重新拉取 AdaPay 结算明细；页面查询只读取本地数据，不实时调用 AdaPay。
4. 页面提供「店铺」和「平台」两个 Tab。
5. 店铺 Tab 展示店铺级收款人，可按商圈、店铺、收款人和结算日期过滤，并保留历史绑定关系。
6. 平台 Tab 展示平台级收款人，可按平台、配送方、销售方角色过滤。
7. 支持按日、周、月汇总，金额展示结算金额、手续费和扣除手续费后的净到账金额。
8. 保存成功、失败、处理中、未发起和失败回账等结算状态，成功记录计入到账汇总。

### Out of Scope

- 修改现有「店铺收入报表」的统计口径或菜单位置。
- 实时查询 AdaPay、提现操作、金额调整和自动冲正。
- 将 AdaPay 结算金额拆分到订单；AdaPay 结算明细不提供订单号。
- 导出、退款冲销和银行侧独立对账。

### Deferred

- 平台级收款人到账金额按店铺拆分。
- 结算明细导出。

## Use Cases

### UC-1：系统每日采集结算明细

角色：系统。每天在结算数据可查询后，按租户和所有当前/历史收款人拉取前一日结算明细并保存。单个收款人失败不得阻断其他收款人，任务须记录整体和分收款人结果。

### UC-2：财务重新拉取某日数据

角色：财务/管理员。选择一个结算日期发起重新拉取，系统异步执行并返回执行标识；重复拉取不得产生重复结算记录，结果以最新成功采集数据为准，并保留执行日志。

### UC-3：财务查看店铺收款人结算

角色：财务/运营。进入店铺 Tab，按结算周期、商圈、店铺、收款人查询店铺级收款人的结算金额、手续费和净到账金额；解绑后的历史记录仍可按原店铺查询，并标记「非当期」。

### UC-4：财务查看平台收款人结算

角色：财务/运营。进入平台 Tab，按结算周期、平台角色和收款人查询平台、配送方或销售方的到账汇总和明细。

## Business Rules

1. AdaPay `settle_details` 是结算事实来源；不使用本地分账明细金额替代。
2. 净到账金额 = `settle_amt - settle_fee_amt`，金额精确到分。
3. 只有 `settle_stat=succeeded` 的记录计入成功到账汇总；其他状态保留并可查询，但不计入净到账金额。
4. 结算日期使用 AdaPay 返回的 `settle_date`，按 `Asia/Shanghai` 解释；周按周一至周日，月按自然月。
5. 每日任务拉取前一自然日；AdaPay 单次查询时间跨度不得超过 31 天，单日重拉只允许一个结算日期。
6. 拉取范围包含当前启用、当前禁用、已解绑但仍有历史关系的收款人；历史关系须保留原 `member_id` 和 `settle_account_id`。
7. 店铺 Tab 只展示店铺级收款人；平台 Tab 只展示平台级收款人，并按角色过滤。
8. 店铺绑定历史按生效时间和失效时间保存。当前仍绑定且启用的记录标记「当期」，已解绑、已换绑或已禁用的历史记录标记「非当期」。
9. 每次采集以任务批次执行；某个收款人的完整响应成功后，才替换该收款人该结算日的活动数据。重复拉取不得重复累计；失败或部分失败时保留对应收款人的最近一次成功数据。
10. 所有查询按租户隔离，并遵循现有商圈/店铺数据权限；只读权限与重新拉取权限分离。
11. 平台级收款人没有固定店铺归属，不在店铺 Tab 中按店铺展示或拆分平台到账金额。

## Frontend Requirements

| 区域 | 要求 |
|---|---|
| Tab | 店铺收款人、平台收款人 |
| 店铺筛选 | 结算周期、汇总方式、商圈、店铺、收款人、当期状态 |
| 平台筛选 | 结算周期、汇总方式、角色、收款人 |
| 汇总表 | 周期、收款人、角色、原关联商圈/店铺、结算金额、手续费、净到账金额、记录数、采集状态 |
| 明细 | 结算日期、结算类型、结算状态、结算金额、手续费、净到账金额、脱敏卡号、失败描述 |
| 采集操作 | 显示最近采集状态；授权用户可选择单日重新拉取并查看执行进度 |
| 状态反馈 | 支持加载、空数据、部分失败、拉取中、失败和成功提示 |

## Edge Cases

- 已解绑或逻辑删除的收款人仍有历史结算时，必须使用历史快照展示，不能因当前收款人记录不可用而丢失。
- 收款人更换结算账户后，旧账户在历史日期的本地结算仍可查询；重拉时按旧账户快照尝试，若外部账户已不可查，不影响本地历史数据。
- AdaPay 返回空明细时，任务记录成功但数量为 0，不作为系统错误。
- 同一日期部分收款人查询失败时，页面应标记该日「部分失败」，已成功收集的记录仍可查询。
- 净到账金额出现负数、日期非法或状态未知时保留原始数据并标记异常，不静默修正。
- 历史绑定无法从既有数据准确还原时，不得伪造生效/失效日期，应标记历史关系不完整。

## Acceptance Criteria

- [ ] 财务菜单出现独立的「分账收款人结算」，现有「店铺收入报表」保持不变。
- [ ] 每日任务能拉取前一日所有当前/历史收款人的 AdaPay 结算明细并保存本地。
- [ ] 页面查询不调用 AdaPay；日、周、月汇总均来自本地结算明细。
- [ ] 净到账金额按 `settle_amt - settle_fee_amt` 计算并精确到分。
- [ ] 店铺和平台两个 Tab 的收款人范围、角色过滤正确。
- [ ] 解绑后的收款人能按原店铺查询，并显示「非当期」。
- [ ] 更换结算账户后，旧账户历史数据仍可重新拉取和查询。
- [ ] 同一日期重新拉取不会重复累计，失败不会覆盖最近一次成功数据。
- [ ] 结算状态、采集状态、失败原因可查询，部分失败可识别。
- [ ] 租户隔离、商圈/店铺数据权限和只读/重拉权限生效。

## Assumptions

1. AdaPay SDK 使用 `com.holuntech:pay-java-adapay:2.14.14-SNAPSHOT` 的 `querySettleDetail` 接口；其日期跨度限制由 SDK 和 AdaPay 双重约束。
2. 每日任务在 AdaPay 前一日结算数据可查询后执行，具体调度时间在部署配置中确定。
3. AdaPay 结算明细没有订单号，因此本功能展示收款人结算账户到账事实，不提供订单级明细。
