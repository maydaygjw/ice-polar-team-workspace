# UI/UX 设计 — 分账收款人结算

## 页面定位

- 菜单：财务 → 分账收款人结算
- 页面：只读结算到账报表
- 独立于现有「店铺收入报表」
- 页面不直接请求 AdaPay

## 页面结构

顶部使用两个一级 Tab：

1. **店铺**：店铺级分账收款人。
2. **平台**：平台级分账收款人。

切换 Tab 后保留各自的筛选条件和分页状态，避免切换时混淆两种归属口径。

## 店铺 Tab

筛选项：

- 汇总方式：日 / 周 / 月
- 结算日期范围
- 商圈
- 店铺
- 收款人
- 关系状态：全部 / 当期 / 非当期

汇总表列：

- 结算周期
- 收款人名称
- 原关联商圈
- 原关联店铺
- 当前关系状态
- 结算记录数
- 结算金额
- 手续费
- 净到账金额

历史解绑记录保留原店铺和商圈名称，并在关系状态列显示灰色「非当期」标签；当前有效关系显示绿色「当期」标签。

## 平台 Tab

筛选项：

- 汇总方式：日 / 周 / 月
- 结算日期范围
- 角色：全部 / 平台 / 配送方 / 销售方
- 收款人

平台 Tab 不展示店铺和商圈筛选，避免将平台到账错误拆分到店铺。

## 明细与采集操作

点击汇总行打开明细弹窗/抽屉，展示：

- 收款人及角色
- 结算日期
- 结算类型
- 结算状态
- 结算金额
- 手续费
- 净到账金额
- 脱敏银行卡号
- 失败描述

页面右上角提供「重新拉取」入口，仅有 `pay:profit-recipient-settlement:recollect` 权限时显示。选择单个日期后提交异步任务；展示任务状态、成功/失败收款人数和失败摘要。

## 状态与反馈

- 页面加载：表格显示 loading。
- 无数据：分别显示店铺 Tab 和平台 Tab 的空状态说明。
- 部分失败：顶部显示警告，说明目标日期仍有收款人未采集成功。
- 拉取中：按钮禁用并显示进度，禁止同日期重复提交。
- 拉取失败：保留已有本地数据，提示失败原因。
- 金额：统一人民币元，保留两位小数，金额列右对齐。

## 权限与安全

- 页面查询按钮受 `pay:profit-recipient-settlement:query` 控制。
- 重新拉取按钮受 `pay:profit-recipient-settlement:recollect` 控制。
- 不展示完整银行卡号、身份证号或 AdaPay 密钥。
- 沿用现有 Element Plus 表格、分页、日期选择器、标签和消息提示模式。
