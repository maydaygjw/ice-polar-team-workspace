# Adapay 店铺收入报表

## Scope

### In Scope

1. 在管理后台新增独立的「店铺收入报表」页面，不复用「订单结算管理」页面。
2. 按店铺、结算日期汇总 Adapay 分账成功后店铺角色实际收到的结算收入。
3. 汇总列表展示结算日期、店铺、结算订单数、关联订单金额合计、店铺结算收入合计。
4. 从汇总行穿透到当日该店铺的结算明细，展示每笔店铺结算金额及对应订单金额、订单号和结算时间。
5. 支持按结算日期范围、店铺筛选；支持分页和空数据状态。

### Out of Scope

- 订单编辑、订单状态维护、分账重试、提现和对账操作。
- 非 Adapay 支付的收入统计。
- 平台、配送方、销售方角色收入统计。
- 收入导出、图表看板和退款冲销。

### Deferred

- 已回退到虚拟余额的店铺收入是否纳入同一报表，后续单独确定口径。

## Income Definition

- 统计对象：`sharing_status=2`（分账成功）的 Adapay 分账记录。
- 店铺收入：该分账记录中 `role=店铺` 的明细金额。
- 结算日期：分账记录的 `sharing_time`，按 `Asia/Shanghai` 自然日归属，不使用订单创建时间或支付时间。
- 订单金额：关联订单的实付金额，用于明细对照；店铺收入不从订单金额反推。
- 待分账、分账中、分账失败、已回退记录不计入本报表。

## Use Cases

### UC-1：财务查看店铺日收入汇总

1. 用户进入「店铺收入报表」。
2. 页面默认按结算日期倒序展示店铺日汇总。
3. 用户按日期范围或店铺筛选并查看订单数、订单金额和店铺结算收入。

### UC-2：查看某店铺某日收入明细

1. 用户点击汇总行的「查看明细」。
2. 系统展示该店铺、该结算日对应的每笔成功结算记录。
3. 用户可查看订单号、订单金额、店铺结算金额、结算时间，并可跳转现有订单详情页查看订单。

## Business Rules

1. 汇总金额只累加店铺角色明细，不能把一笔分账的全角色金额作为店铺收入。
2. 每笔成功分账记录最多取一条店铺角色明细；缺少店铺角色明细的记录不产生店铺收入。
3. 同一租户的数据必须隔离；店铺数据权限沿用现有后台权限范围。
4. 日期范围按半开区间 `[开始日 00:00:00, 结束日+1日 00:00:00)` 查询。
5. 页面只读；不在报表页面提供订单维护、分账重试或收入调整操作。

## Frontend Requirements

| 区域 | 要求 |
|------|------|
| 筛选栏 | 结算日期范围、店铺；查询、重置 |
| 汇总表 | 结算日期、店铺名称、结算订单数、订单金额合计、店铺收入合计、查看明细 |
| 明细弹窗/抽屉 | 店铺和结算日摘要；订单号、订单金额、店铺结算金额、结算时间、分账状态 |
| 交互 | 点击订单号跳转已有订单详情；加载、空数据、请求失败均有反馈 |

## Edge Cases

- 某日没有成功分账的店铺不展示空汇总行。
- 分账记录存在但没有店铺角色明细时不计入收入，也不计入结算订单数。
- 订单金额与分账主记录快照不一致时，明细同时展示订单实付金额和店铺结算金额，不静默覆盖。
- 已回退记录不计入 Adapay 结算收入，避免把虚拟余额收入误标为 Adapay 到账收入。
- 关联订单被逻辑删除时，仍保留成功结算明细，订单号可见但不可跳转或显示“订单不可用”。
- 同一订单存在多条历史分账记录时，只统计实际成功且对应店铺角色明细的一笔有效结算记录，避免重复累计。

## Acceptance Criteria

- [ ] 管理后台有独立的「店铺收入报表」入口，不依赖订单维护页面。
- [ ] 汇总按 `店铺 + sharing_time 自然日` 分组，并正确展示订单数、订单金额合计和店铺收入合计。
- [ ] 汇总收入只包含分账成功记录的店铺角色金额。
- [ ] 待分账、分账中、分账失败和已回退记录不计入 Adapay 店铺收入。
- [ ] 汇总行可穿透到指定店铺、指定结算日的逐笔明细。
- [ ] 明细同时展示每笔结算金额和关联订单金额，并可识别订单号。
- [ ] 日期边界按 `Asia/Shanghai` 自然日处理，结束日不会漏数或串入下一日。
- [ ] 租户及现有店铺数据权限生效，页面为只读且无订单维护操作。
- [ ] 无数据、订单缺失和请求失败均有明确展示。

## Assumptions

1. 现有分账明细中的 `role=2` 表示店铺，金额已在分账创建时固化。
2. `sharing_time` 在数据库中按系统统一时区写入，查询层按 `Asia/Shanghai` 解释自然日。
3. 订单详情已有可复用的后台路由；本功能只提供跳转，不新增订单详情能力。
