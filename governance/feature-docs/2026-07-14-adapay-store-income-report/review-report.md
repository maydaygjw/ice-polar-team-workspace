# Review Report — Adapay 店铺收入报表

## 结论

实现与需求和契约文档一致，当前可进入联调。未发现会把平台或其他角色金额计入店铺收入的代码路径；查询仅统计 `sharing_status=2` 且 `role=2` 的记录，并按租户和当前用户店铺范围过滤。

## 检查项

| 检查项 | 结果 | 说明 |
|--------|------|------|
| 收入口径 | 通过 | 店铺收入取分账明细固化金额，不从订单金额反推 |
| 日期口径 | 通过 | 使用 `sharing_time`，按开始日含、结束日次日排除处理 |
| 多租户隔离 | 通过 | 查询显式带 `tenant_id` |
| 店铺数据权限 | 通过 | 超级/租户管理员不限制；其他用户使用登录态 `shopIds/shopId` |
| 重复分账 | 通过 | 每个租户订单只取成功记录中的最新 ID |
| 页面职责 | 通过 | 独立只读报表，不提供订单维护、重试、提现或调整 |
| 敏感信息 | 通过 | 报表接口不返回银行卡、身份证和收款人信息 |
| 构建与静态检查 | 通过/受阻 | 后端编译、XML、前端 ESLint 通过；全量测试和 ts-check 受既有基线问题阻断 |

## 残余风险

- 需要在测试数据和真实数据库上确认聚合查询执行计划及大日期范围性能。
- 需要确认生产菜单父级名称为「门店中心」；升级脚本未找到父菜单时会跳过菜单注册。
- 退款冲销和虚拟余额回退收入尚未纳入本期口径。
