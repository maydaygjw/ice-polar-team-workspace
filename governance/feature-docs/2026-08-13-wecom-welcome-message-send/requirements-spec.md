# 企业微信客户添加欢迎语自动发送需求规格

## Scope

在企业微信客户添加外部联系人事件到达后，根据事件中的 `State` 找到商圈，读取该商圈已启用的系统欢迎语模板，并使用事件中的 `WelcomeCode` 调用企业微信客户欢迎语发送接口。图片沿用模板管理阶段通过企业微信“上传图片”接口获得的 URL。

本期只改 backend 事件处理和发送链路；欢迎语模板仍由上一阶段的系统内模板管理功能维护。管理端不新增页面或发送按钮。

## Use Cases

### UC-01 客户添加后自动发送

1. 客户通过企业微信“联系我”二维码添加员工。
2. 企业微信向系统回调 `change_external_contact` / `add_external_contact` 事件。
3. 系统验签、解密并校验 CorpID。
4. 系统异步处理事件：使用 `State` 匹配当前租户的启用商圈。
5. 系统查找该企业微信配置和商圈下唯一的启用欢迎语模板。
6. 系统使用 `WelcomeCode` 发送文字消息和图片消息，顺序固定为文字后图片。
7. 系统记录处理结果，重复事件不得重复发送。

### UC-02 无匹配模板时跳过

当事件没有 `State`、`State` 不对应启用商圈、商圈没有启用模板或模板图片 URL 缺失时，系统记录可审计的跳过原因，不调用发送接口。

### UC-03 企业微信发送失败

企业微信接口确定性失败时，系统保留失败记录；发送请求结果不明确时记录未知并告警。外部发送接口不自动重试，避免因回调重试造成重复发送；消费者内部异常直接记录终态，避免延迟重试导致 WelcomeCode 过期。

## Business Rules

- 仅处理 `Event=change_external_contact` 且 `ChangeType=add_external_contact` 的事件；其他事件继续验签并快速返回成功，不进入欢迎语发送流程。
- `State` 使用当前联系我配置创建时写入企业微信的商圈 `code`，不使用商圈名称或数据库 ID 作为事件匹配值。
- `State` 匹配必须在事件所属租户上下文内完成，禁止跨租户按 code 查询。
- 一个租户、企业微信配置、商圈只能存在一个有效欢迎语模板；只有 `status=1` 的模板可以触发发送。
- 欢迎语内容固定为模板文字在前、单张图片在后；图片使用系统保存的企业微信 `url`，不再次上传。
- 使用企业微信事件返回的 `WelcomeCode` 作为发送目标，不使用 `external_userid` 代替。
- `WelcomeCode` 仅在回调后 20 秒内有效，且每个 WelcomeCode 最多调用一次发送接口；不能把发送接口调用当作普通可重试请求。
- `WelcomeCode`、企业微信 Secret、access token 不写入普通业务日志，也不返回给管理端。
- 回调接口只负责验签、解密和投递消息，不能同步等待企业微信发送完成；发送结果以处理记录和日志为准。
- 企业微信没有提供可依赖的本地事务一致性，允许“发送成功后进程崩溃导致状态未更新”的极小重复风险；通过唯一事件键、分布式锁和发送前后状态控制降到最低，并在评审中明确。

## Event Fields

解密后的 XML 至少读取：

| 字段 | 用途 | 敏感性 |
|---|---|---|
| `ToUserName` | 校验 CorpID | 普通 |
| `Event` | 判断客户联系事件 | 普通 |
| `ChangeType` | 判断 `add_external_contact` | 普通 |
| `UserID` | 记录添加客户的企业成员 | 业务标识 |
| `ExternalUserID` | 记录外部联系人快照标识 | 业务标识 |
| `State` | 匹配商圈 code | 业务标识 |
| `WelcomeCode` | 调用发送欢迎语接口 | 短期敏感凭据，禁止日志明文 |

## Frontend Requirements

N/A：本期复用已有欢迎语模板页面的启停状态；不新增前端 API、页面、按钮或发送记录页面。

## Edge Cases

- 企业微信重复投递同一个事件：只允许一个处理记录进入发送流程，后续重复事件直接幂等结束。
- `WelcomeCode` 缺失：记录为 `SKIPPED`，不调用企业微信。
- `State` 为空或商圈已停用：记录为 `SKIPPED`。
- 模板被停用、删除或不完整：记录为 `SKIPPED`。
- 企业微信返回欢迎码失效、权限不足或素材 URL 失效：记录为 `FAILED`，不再次使用同一个 WelcomeCode 调用发送接口。
- 发送请求超时或连接在请求发出后中断：结果可能为未知，记录为 `UNKNOWN` 并告警，不自动重发，避免违反 WelcomeCode 只能调用一次的约束。
- 如果企业微信侧已为相关成员配置管理端欢迎语，事件可能不返回 `WelcomeCode`；系统按缺失 WelcomeCode 跳过，不尝试改用其他客户标识发送。
- 同一客户短时间内从多个联系我配置添加：每个企业微信事件按自己的 `WelcomeCode` 和 `State` 独立处理。
- 事件 XML 非法、验签失败或 CorpID 不匹配：返回非法请求，不投递业务消息。
- Redis Stream/MQ 不可用：回调处理失败并返回非成功响应，让企业微信按其机制重试；不能丢弃事件。
- 模板编辑发生在事件入队和消费之间：消费时读取最新启用模板；发送记录保存文字和图片 URL 快照，便于审计。

## Acceptance Criteria

- AC-01：有效 `add_external_contact` 事件可被验签、解密并异步投递，HTTP 回调在发送完成前返回 `success`。
- AC-02：事件 `State` 能在当前租户内匹配商圈 code，并只读取该配置/商圈的启用模板。
- AC-03：发送请求包含原始 `WelcomeCode`、模板文字和一个图片附件，顺序为文字后图片。
- AC-04：无 State、无匹配商圈、无启用模板或图片不完整时，不调用发送 API，并有明确跳过原因。
- AC-05：同一个 `WelcomeCode` 重复投递不会创建第二个发送任务或再次调用发送 API。
- AC-06：发送接口对同一个 WelcomeCode 最多调用一次；消费者处理异常记录终态，外部调用结果不明确时记录 `UNKNOWN` 并告警，不自动重发。
- AC-07：租户 A 的 State、模板和发送记录不能被租户 B 使用或读取。
- AC-08：日志中不出现完整 WelcomeCode、Secret、access token 和完整 XML。
- AC-09：现有欢迎语模板 CRUD、联系我配置创建/更新、其他企业微信回调事件不受影响。

## Assumptions

- 现有联系我创建流程已将商圈 `code` 作为企业微信 `state` 写入配置；本期不改变该格式。
- 企业微信配置已配置客户联系回调 Token、EncodingAESKey、CorpID 和 Secret。
- 企业微信图片 `url` 可直接作为客户欢迎语图片附件的 `pic_url` 使用。
- 本期不发送文本之外的图文标题、描述、链接或视频等附件类型。
- 发送记录用于幂等和审计，不提供管理端查询页面；如需运营统计，另立需求。
