# 活动管理重构 UI/UX 方案

## 菜单与路由

- 菜单路径为“营销 → 活动管理”，活动管理作为父菜单，不直接承载列表。
- 子菜单依次为：模板管理、期次管理、报名管理、中奖管理、条件管理。
- 期次、报名、中奖页面支持从关联业务跳转，并携带模板/期次筛选上下文；直接进入时显示完整筛选器。

## 条件管理

- 列表展示：条件名称、类型、说明、版本、启用状态、更新时间、操作。
- 内置条件显示“系统内置”标识；不提供修改执行逻辑的入口。
- 停用操作需二次确认，提示只影响新模板选择和新期次生成，不影响历史期次。
- 空、加载、错误状态沿用管理端标准表格模式。

## 模板管理

- 原活动配置页面迁移为模板管理。
- 表单分组为基础信息、周期与报名时间、活动内容、报名条件、奖品配置。
- 报名条件区域使用条件卡片；支持选择、排序和展开配置，展示条件说明和配置校验错误。
- 已停用条件不可新选；历史模板引用停用条件时显示警告和处理建议。
- 保存前显示条件组合规则：“以下所有条件均满足后方可报名”。

## 期次、报名、中奖

- 期次管理保留生成、报名开关、开奖、二维码和统计能力，并提供查看报名/中奖按钮。
- 报名管理承载查询、导出、增加抽奖次数和删除报名；显示条件通过摘要/详情。
- 中奖管理承载查询和导出，支持按期次、用户、奖品和状态筛选。
- 原隐藏页面改为正式菜单页面，按钮仍按现有权限控制。

## 用户端 H5

- 活动详情中的“报名条件”由接口条件列表生成；每项展示名称、说明和通过/未通过状态。
- 未报名时展示待校验状态；报名失败时突出具体失败条件的安全原因。
- 不展示内部条件类型配置、企微管理员 ID、标签 ID、租户信息。
- 条件列表为空时展示“无额外报名条件”，但仍展示报名时间和重复报名规则。
