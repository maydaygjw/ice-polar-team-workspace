## Feature: 普通券与周期券

### Scope

**In Scope**

1. 优惠券新增券类型：普通券、周期券。
2. 周期券配置发放起始时间、截止时间，以及发放周期（每 N 天一次，默认每天一次）。
3. 周期券只能选择“领取后立即生效，有效期 X 天”，不能选择固定时间或无限期。
4. 周期券在发放周期内，每个用户每个周期最多领取一次；领取后生成一张独立的用户优惠券。
5. 周期券只支持无码/页面领取；普通券继续支持现有兑换码类型，不新增“是否展示”字段。

**Out of Scope**

- 周期券自动推送消息或定时预生成用户券；用户进入可领取入口并领取时按周期即时发放。
- 周期券的店铺适用范围改造。
- 领券中心展示开关。

### Business Rules

1. 普通券保持现有行为和数据兼容，未传券类型的历史调用按普通券处理。
2. 周期券必须有发放起始时间、截止时间，且截止时间晚于起始时间。
3. 周期券必须使用领取后有效期，`expirationDay` 必须为正数。
4. 周期券的 `issueCycleDays` 必须为正数；周期起点为发放起始日期，按自然日计算周期桶。
5. 周期券在发放周期外不可领取；周期券每个用户在同一周期只能成功领取一次。
6. 周期券领取记录保存周期日期，数据库唯一约束保证并发重复领取幂等。
7. 周期券不生成或接受通用码、一卡一码；用户通过现有页面领取入口领取。

### Acceptance Criteria

- [x] 管理后台可以选择普通券或周期券。
- [x] 选择周期券时显示发放周期配置，默认每 1 天一次。
- [x] 周期券的有效期方式固定为“领取后有效期”，固定时间和无限期不可选。
- [x] 周期券在开始时间前、截止时间后不能领取。
- [x] 同一用户同一周期重复领取失败；进入下一周期可以再次领取。
- [x] 周期券领取后的用户券按 `expirationDay` 正确计算有效期。
- [x] 普通券创建、领取、使用和兑换码行为不回归。

### Assumptions

1. “每天发一次”按自然日理解；`issueCycleDays=1` 时按发放起始日期切分每日周期。
2. 截止时间为周期领取窗口的结束时间，包含截止时间瞬间。
3. 周期券不主动给用户推送，用户通过现有页面领取入口领取。
