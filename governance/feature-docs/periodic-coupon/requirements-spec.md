## Feature: 普通券与周期券（重新实现）

### Scope

**In Scope**

1. 优惠券新增券类型：普通券、周期券。
2. 周期券配置独立的发放开始时间、发放结束时间，以及领取间隔 `issueCycleDays`，形成按周期重复发放的可领取窗口。
3. 同一用户在同一个发放周期内最多领取一次；进入下一个发放周期后可以再次领取。每次成功领取都生成一条新的领取关系，即一张独立的用户券。
4. 每张用户券沿用现有领取关系的核销逻辑，独立记录领取、使用和使用时间；重复领取不会复用或重置已有用户券。
5. `taking_effect_time`、`expiration_time` 继续表示领取后用户券的有效起止时间，不再表示周期券的发放窗口。
6. 用户券发放时，将本次领取对应的有效起止时间固化到领取关系记录；后续用户券查询和可用性判断统一使用关系记录中的起止时间。
7. `expirationDay` 仅作为券模板的领取后有效期配置，不作为已发放用户券的有效性判断字段。
8. 普通券和周期券都必须选择一个商圈；店铺适用范围限定在该商圈内，支持不限制店铺、指定店铺、排除指定店铺。
9. 周期券只支持无码/页面领取；普通券继续支持现有兑换码类型，不新增“是否展示”字段。

**Out of Scope**

- 周期券自动推送消息或定时预生成用户券；用户进入可领取入口后即时领取。
- 领券中心展示开关。

### Business Rules

1. 普通券保持现有行为和数据兼容，未传券类型的历史调用按普通券处理。
2. 周期券必须有 `issueStartTime`、`issueEndTime`，且结束时间晚于开始时间。
3. 周期券仅在发放窗口内可领取；发放开始时间和发放结束时间均视为可领取边界，结束时间之后不可领取。
4. `issueCycleDays` 必须为正整数；周期起点为 `issueStartTime`，每 `issueCycleDays` 个自然日形成一个发放周期，最后一个不足完整周期的时间段仍属于最后一个周期。
5. 周期券仅在发放窗口内可领取；同一用户在当前发放周期已有成功领取记录时不可再次领取，进入下一周期后可以再次领取。
6. 每次成功领取都新增一条领取关系，并扣减一张库存；同一用户是否可以继续跨周期领取，同时受现有 `receiveType`/`limitNumber`、库存和券状态约束。
7. `receiveType=2` 时，`limitNumber` 是该用户针对该券模板的累计领取上限，不按周期重置；`receiveType=1` 时可在不同发放周期重复领取。
8. 每条领取关系代表一张独立用户券，沿用现有 `isUsed`、`receiveTime`、`usageTime` 逻辑；一条关系核销后不影响同一用户领取的其他关系。
9. 周期券的用券时间固定为“领取后立即生效，有效期 X 天”，即 `expirationType=2` 且 `expirationDay` 为正数；领取成功时将 `receiveTime` 转换为该条用户券的 `taking_effect_time` 和 `expiration_time` 并持久化。`taking_effect_time`、`expiration_time` 不参与发放窗口判断，也不能被复用为发放时间字段。
10. 普通券领取时也将其有效期配置转换为用户券有效期快照：固定时间直接复制，按领取后天数按 `receiveTime` 计算，无限制时间的失效时间为空。
11. 店铺适用范围与商品适用范围独立：
    - 不限制店铺：不配置店铺 ID，所选商圈内所有可用店铺均适用。
    - 指定店铺：选择一个或多个属于所选商圈的店铺，仅所选店铺适用。
    - 排除店铺：选择一个或多个属于所选商圈的店铺，所选商圈内除所选店铺外的店铺适用。
12. 商圈必须存在、属于当前租户且通过当前数据权限校验；所选店铺必须属于该商圈，排除模式不能跨租户或跨商圈排除店铺。
13. 周期券不生成或接受通用码、一卡一码；用户通过现有页面领取入口领取。
14. 领取关系表不新增周期日期、周期桶或唯一索引；按已有 `receive_time` 判断当前周期的领取记录，现有领取、核销和多次领取关系逻辑保持不变。

### Acceptance Criteria

- [ ] 管理后台可以选择普通券或周期券。
- [ ] 创建和编辑优惠券时必须选择商圈。
- [ ] 店铺选择器仅展示所选商圈下的店铺；切换商圈时清空已选店铺。
- [ ] 选择周期券时显示独立的发放开始时间和发放结束时间。
- [ ] 周期券的用券时间只能选择“领取后立即生效，有效期 X 天”，固定时间和无限制时间不可选。
- [ ] 周期券领取后的用户券以该次 `receiveTime` 为生效时间，并按 `expirationDay` 计算失效时间。
- [ ] 用户券发放后，领取关系中保存计算后的 `taking_effect_time` 和 `expiration_time`；后续有效性判断不再依赖模板的 `expirationDay` 动态计算。
- [ ] 周期券在同一发放周期内重复领取失败。
- [ ] 周期券进入下一个发放周期后，同一用户可以再次领取，每次生成独立用户券和独立领取关系。
- [ ] 周期券在发放窗口外不能领取。
- [ ] `issueCycleDays` 按发放开始时间切分周期，周期内限领一次；`limitNumber` 按用户累计领取次数生效，不随周期重置。
- [ ] 普通券和周期券均支持在所选商圈内不限制店铺、指定多个店铺、排除多个店铺。
- [ ] 选择“不限制店铺”且未选择店铺时，所选商圈内任意适用店铺均可使用；指定模式只允许所选店铺使用；排除模式禁止所选店铺使用。
- [ ] 店铺范围查询遵循租户隔离和当前管理员/用户的数据权限。
- [ ] 每张领取后的用户券可以独立使用；一张券使用后，其他领取的券仍保持原状态。
- [ ] 普通券创建、领取、使用和兑换码行为不回归。

### Assumptions

1. “周期范围”指周期券的发放时间窗口；`issueCycleDays` 决定窗口内每个领取周期的长度。
2. 周期券的库存仍是券模板的全局剩余库存；每次领取消耗一张库存。
3. 周期券不主动给用户推送，用户通过现有页面领取入口领取。
4. 每张优惠券只归属一个商圈；不支持一张券跨多个商圈配置。
