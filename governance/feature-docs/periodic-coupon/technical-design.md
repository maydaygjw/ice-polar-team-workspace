# 技术设计 — 普通券与周期券

## 模块影响

| 模块 | 变更 | 说明 |
|---|---|---|
| `yshop-module-coupon-api` | 修改 | 新增券类型枚举及错误语义 |
| `yshop-module-coupon-biz` | 修改 | 周期配置校验、按周期领取、状态查询 |
| `backend/sql` | 修改 | 优惠券类型/发放周期字段，领取关系周期日期字段及唯一索引 |
| `admin/` | 修改 | 后台优惠券表单和列表展示 |

## 关键决策

1. 复用现有 `taking_effect_time`、`expiration_time` 表示周期券的领取起止时间；普通券继续表示固定用券时间。
2. 新增 `coupon_kind` 区分普通券和周期券，避免与现有 `coupon_type`（满减/折扣）混淆。
3. 新增 `issue_cycle_days` 表示发放间隔天数。周期桶由发放起始日期加上经过天数除以间隔计算。
4. 在领取关系表新增可空 `period_date`。普通券保持 NULL；周期券写入当前周期日期，并建立 `(coupon_id, uid, period_date)` 唯一索引，利用数据库保证并发幂等。
5. 周期券不新增定时任务；现有领取/兑换请求负责校验周期并即时创建用户券，避免无用户领取时预生成大量关系数据。
6. 周期券固定 `get_type=0`，不生成兑换码，统一走页面领取接口。

## 兼容与风险

- 新字段默认普通券/每天一次，历史数据和未升级客户端继续按普通券工作。
- 旧客户端创建周期券时若未传新字段，后端按普通券处理；后台新表单负责完整配置。
- 周期券的库存仍从优惠券 `number` 扣减；库存耗尽后当前周期及后续周期均不可领取。
