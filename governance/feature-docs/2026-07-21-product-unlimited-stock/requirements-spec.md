# 商品不限制库存

## Scope

### In

- 商品、规格（SKU 属性值）、选项三个层级支持库存值为 `-1`，表示不限制库存。
- 管理端在商品、规格、选项的库存输入中允许填写 `-1`，并明确展示“不限制库存”语义。
- 店铺导入支持“不限制库存”开关，开启后导入的商品和规格库存统一为 `-1`；源文件库存为 `-1` 时也按不限制库存处理。
- 下单、购物车、订单计算等路径中，库存为 `-1` 的商品/规格/选项跳过库存校验与扣减。
- 售后退货还原库存时，库存为 `-1` 保持不变，不恢复也不扣减。
- 同步已存在库存数据：非 `-1` 保持原逻辑不变。

### Out

- 不修改商品、规格、选项表结构；使用现有 `stock` 字段的 `-1` 作为约定值。
- 不新增库存预警、库存报表或定时任务；当前系统无活跃预警/报表。
- 不处理积分商城、抽奖等非普通商品库存。
- 不改变管理端除库存输入与展示外的其他页面结构。

## Use Cases

1. 租户管理员在店铺导入参数页勾选“不限制库存”，预览/确认导入的商品和规格库存均按 `-1` 处理，不受源文件库存值影响。
2. 不勾选时，源文件库存按原逻辑解析；支持源文件库存字段为 `-1` 以表示不限制库存。
2. 租户管理员在规格（SKU）维度将库存设为 `-1`，任意规格组合下单均不校验库存。
3. 租户管理员在选项维度将库存设为 `-1`，带该选项的商品下单不校验选项库存。
4. 用户下单含不限制库存的商品/规格/选项时，系统正常流转订单，不触发“库存不足”异常。

## Business Rules

- 库存 `-1` 为“不限制库存”的唯一约定值；`0` 仍表示无库存，不允许下单。
- 商品、规格、选项三层规则一致：任意一层库存为 `-1` 时，该层不参与库存校验与扣减。
- 订单创建时：
  - 商品 `stock != -1` 则校验并扣减商品库存；
  - 规格 `stock != -1` 则校验并扣减规格库存；
  - 选项 `stock != -1` 则校验并扣减选项库存。
- 退款/取消恢复库存时，仅对非 `-1` 的库存执行恢复；`-1` 保持为 `-1`。
- 批量导入、店铺导入等写入商品数据时，允许 `stock = -1`。
- 店铺导入参数页提供“不限制库存”开关；开启后，本次导入的所有商品/规格库存均写入 `-1`；关闭时按源文件库存解析。
- 现有库存加减 SQL/代码需确保 `-1 + N` 或 `-1 - N` 不会出现非预期数值；不限制库存时直接跳过更新。

## Frontend Requirements

- 管理端商品表单、规格表格、选项表格的库存输入框允许输入 `-1`。
- 库存为 `-1` 时，列表/详情展示为“不限制库存”或隐藏具体数字；为 `0` 时仍展示“无库存”。
- 下单、购物车前端无需特殊处理，由后端接口返回库存充足。

## Edge Cases

- 商品库存 `-1` 但规格库存为有限值：规格层仍正常校验，商品层跳过。
- 商品库存为有限值但规格/选项库存 `-1`：仅商品层校验扣减，规格/选项层跳过。
- 多层混合时，各层独立判断，不因某一层 `-1` 而影响其他层。
- 并发场景下有限库存扣减仍保持现有原子性；不限制库存不参与扣减，避免行锁竞争。
- 历史订单中若商品曾为 `-1`，后续改为有限值，不影响历史订单。

## Acceptance Criteria

- 商品、规格、选项库存设置为 `-1` 后，下单任意数量均不触发库存不足异常。
- 库存为 `-1` 的商品/规格/选项，订单创建成功后对应库存仍保持 `-1`。
- 库存为有限值的商品/规格/选项保持原有校验与扣减逻辑。
- 管理端展示库存为 `-1` 时使用“不限制库存”文案。
- 后端编译通过；管理端类型检查与构建通过。

## Assumptions

- 现有 `stock` 字段类型为整型，可存储 `-1`；无需扩容。
- 订单库存校验与扣减集中在 `AppStoreProductServiceImpl`、`StoreOptionService`、`StoreProductAttrValueMapper` 等少数位置，改造范围可控。
- 不限制库存不计入现有库存报表/预警；当前系统无实际运行的预警/报表逻辑。
