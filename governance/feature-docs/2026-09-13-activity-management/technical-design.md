# 活动管理技术设计

## 模块影响

- 新增活动业务模块，负责活动模板、活动期次、报名、奖品和中奖结果。
- `admin` 消费活动管理 API；本期不实现 `miniapp` 页面，但保留后续 app API 语义。
- 活动模块通过 `mp-api` 使用本地企微客户/群标签查询能力，并通过 `infra-api` 使用临时文件能力；禁止依赖对应 `-biz` 实现。
- 小程序码生成复用现有 mp 小程序码服务语义，不新增永久二维码业务表；活动二维码使用微信 `createwxaqrcode`，把活动参数放入页面查询串，完整页面路径按微信 128 字节限制校验。

## 关键决策与权衡

1. **模板与期次分离**：模板保存周期规则，期次保存完整快照。这样模板可继续配置，而历史报名/中奖结果不被回溯修改。
2. **一期按周生成期次**：首期只支持每周指定星期和完整日期时间；保留周期类型扩展点，但不引入自定义表达式。
3. **期次生命周期与报名解耦**：期次状态明确表示未开始、进行中或已结束；报名开关独立由时间扫描或后台操作维护，后台显式结束期次，不以报名截止或开奖结果隐式结束。
4. **开奖以期次为边界**：有效报名和奖品库存均属于期次；开奖事务先取得期次锁，再确认状态和有效报名，保证定时任务与人工触发幂等。
5. **抽奖次数按报名记录累计**：报名默认获得 1 次，额外次数通过受控增量接口发放；开奖将每次机会展开为抽签位，保留额外机会的概率权重。
6. **中奖限制固化到期次快照**：`singleWinner` 随模板复制到期次，开奖只读取快照，避免模板后续修改影响历史开奖。
7. **奖品采用配置型奖品**：首期只保存名称、图片、数量和领取说明，不绑定优惠券、积分或物流，减少跨模块耦合。
8. **小程序码临时化**：二维码是投放产物，不写入永久业务素材表；生成请求使用期次定位参数，避免模板变更造成投放链接指向错误期次。
9. **外部订单条件独立客户端**：`HAS_CONFIRMED_ORDER_WITHIN_DAYS` 在活动模块内通过独立 HTTP Client 调用外部商城接口；商城域名从 `TenantConfigApi` 读取当前租户的 `we7_mall_host`，不依赖 mp `-biz` 实现，也不把外部接口调用下沉到报名控制器。

## 必要流程

### 期次生成

模板启用后，按“租户 + 模板 + 期次开始时间”幂等生成期次，并复制内容、校验规则、管理员、社群、群和奖品快照。模板停用不生成新期次；已生成期次按其快照继续执行。

### 报名

报名接口在事务内校验当前租户、期次状态、报名时间、用户唯一性，以及本地管理员客户关系和本地群成员/标签关系。用户身份从当前登录态获取，再通过 `yshop_user.id = mp_wecom_customer_contact.member_id` 获取企微联系人 `external_user_id`；联系人不存在时，开启的企微/社群校验均失败。成功后只产生一条期次报名记录，报名表保存会员主键、可选推荐人用户 ID 和渠道标识。

新增 `HAS_CONFIRMED_ORDER_WITHIN_DAYS` 条件时，处理器先通过 `MemberUserApi` 获取当前会员，再读取其 `externalUserId` 和条件配置 `days`，从 `TenantConfigApi` 获取当前租户的 `we7_mall_host`，最后使用 GET 表单参数调用订单接口。当前外部接口只支持当天查询，管理端暂配置 `days=1`；当配置其他天数时条件明确失败，不能静默按当天放行。外部接口返回失败、超时或结构异常统一按条件失败处理，并将失败原因写入报名条件结果快照。

用户端通过受保护的 `GET /app-api/activity/period/eligibility` 获取当前用户的实时条件结果；报名接口复用同一套条件执行逻辑。H5 在进入确认报名页前检测一次，报名提交失败后再次检测并展示未通过条件，避免只显示笼统的报名失败信息。

### 抽奖次数与开奖

报名记录保存累计抽奖次数和已使用次数。开奖将每个有效报名展开成对应数量的抽签位并随机打乱；开启 `singleWinner` 时，同一用户首次中奖后跳过其余抽签位，关闭时允许其按抽签位多次中奖。开奖结束后统一标记报名记录的抽奖次数已使用。

### 开奖

定时任务扫描到达开奖时间的期次；人工开奖复用同一服务。两者使用同一把期次锁，在事务内将待开奖期次置为开奖中，按有效报名随机分配奖品，写入中奖快照并统计实际中奖人数。开奖完成不负责结束期次，失败回滚，不产生部分结果。

### 二维码

后台对具体期次调用生成接口，页面路径固定使用不带查询参数的 `hlmall/pages/index/index.html`。微信小程序码接口的 `page` 不允许携带查询参数，因此服务端将 `open_activity`、模板 ID、商圈代码和可选渠道码压缩到不超过 32 个字符的 `scene`（格式为 `a=1&t={templateId(base36)}&r={region_code}[&c={channelCode}]`）；参数超限或包含不支持字符时明确失败，不截断。二维码接口的 `periodId` 只用于定位后台期次，服务复用现有小程序码生成和临时文件 URL 返回约定，返回 URL 与预期过期时间；不创建永久文件记录。

## 风险与迁移

- 需要确认本地企微群成员数据与会员身份的稳定关联字段；若无法关联，报名校验只能明确返回数据缺失。
- 开奖随机结果需保留可审计的开奖时间、操作来源和奖品快照；首期不承诺可复现随机种子。
- 数据库升级使用 `backend/sql/upgrade-2026-09-13-activity-management.sql`，禁止修改基线 SQL；迁移脚本必须包含回滚语句。
- 小程序页面尚未交付，二维码在页面上线前可能只能作为预投放素材；页面路径变更时必须同步契约和二维码生成规则。
