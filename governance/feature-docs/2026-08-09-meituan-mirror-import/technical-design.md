# 美团镜像库店铺导入技术设计

## 模块影响

- `backend`：店铺导入模块新增只读镜像库查询适配器和镜像数据解析器；扩展导入请求、批次来源信息及商品选项元数据。
- `admin`：导入来源选择、`poi_id` 表单、镜像批次展示和预览统计。
- `backend/sql`：导入批次增加来源类型和来源 `poi_id`；不修改镜像库，不新增业务商品表字段。
- `governance/CONTRACT`：实现后更新后台 OpenAPI 快照。

## 关键决策

1. 镜像库作为服务端固定配置的外部只读数据源，不把数据库连接信息暴露给管理端，也不让导入模块依赖外部库的业务实现。
2. 使用独立、懒加载、只读连接池；查询必须使用参数绑定、连接/读取超时和单批次行数上限。
3. 解析器输出导入模块自有的规范化商品行模型：`foods` 负责商品/SKU，`foods.forbid_single_buy=1` 映射为单点不送；`food_attrs` 以同一门店快照中 `attr_id` 是否出现过空 `sku_id` 推断属性类型，兼容绑定到 SKU 的商品选项。
4. 当 `foods.spec_text` 为空时，使用当前 SKU 的规格属性值回填导入行 `sourceSpec`，保证预览列表与最终商品规格展示一致。
5. `food_attrs.selected` 仅转换为选项默认值；`required`、`min_selected_count`、`max_selected_count`、`sale_status` 和 `value_price` 必须保留到选项写入契约。
6. 外部查询与本地预览批次写入不做跨数据库事务；外部查询失败时不创建本地批次或店铺。
7. 确认流程继续复用现有 `StoreShopWriteApi` 和 `ProductImportWriteApi`，保证租户、店铺和商品写入边界不被绕过。

## 流程

```text
导入来源=镜像库 + poi_id + 新店参数
        ↓
只读查询 foods / food_attrs / food_categories
        ↓
按 poi_id + spu_id 聚合商品，按属性类型组装 SKU 和选项
        ↓
数据校验、预览批次、管理员调整
        ↓
复用现有确认流程创建新店铺、分类、商品、SKU、选项
```

## 风险与回滚

- 镜像库账号权限或网络变化只影响镜像导入，不影响文件导入和主库启动；连接配置缺失时镜像模式应不可用并返回明确提示。
- 本地迁移只增加可回滚的批次来源字段；删除导入记录仍不删除店铺、商品、分类和选项。
- SKU 关联不完整、分类缺失和选项规则超出目标模型时必须保留预览错误/警告，禁止静默丢弃。
