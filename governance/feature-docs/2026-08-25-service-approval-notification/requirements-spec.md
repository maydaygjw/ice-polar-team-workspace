# 需求规格：服务订单审批通过短信通知

## Scope

在服务订单后台审批流程中增加短信通知：当服务订单审核状态由“待审核”变为“审核通过”后，向下单用户发送短信，提醒其进入对应租户小程序完成支付。

本期仅影响 `backend`，不新增前端页面、不新增公开 HTTP 接口、不新增数据库表或字段。

## Use Cases

| # | 场景 | 描述 |
|---|---|---|
| UC-1 | 首次审批通过 | 管理员将待审核服务订单审批通过，系统在审批事务提交后向下单用户发送通知短信。 |
| UC-2 | 拒绝后重新审批通过 | 服务订单被拒绝、用户修改并重新提交后再次审批通过，系统再次发送一条通知短信。 |
| UC-3 | 审批拒绝 | 管理员拒绝服务订单，不发送审批通过短信。 |

## Business Rules

1. 仅当状态发生真实转换 `PENDING(0) → APPROVED(1)` 时发送短信。
2. `PENDING(0) → REJECTED(2)` 不发送短信。
3. 被拒订单修改后重新回到待审核，再次通过时允许再次发送；每次新的待审核到通过转换对应一条短信。
4. 本期不判断订单支付状态；只要发生待审核到审批通过的状态转换，就发送该模板内容。
5. 短信接收人为服务订单关联的下单用户（订单 `uid` 对应的 Member 用户）。
6. 短信模板编码固定为 `service_approval_notification`。
7. 模板参数：
   - `time`：服务订单预约开始时间 `siteStartTime`，格式为 `yyyy-MM-dd HH:mm`。
   - `tenant`：服务订单所属租户名称。
8. 业务审批是主流程。模板缺失、短信渠道不可用、用户手机号缺失或发送失败，均不得回滚已经提交的审批结果。
9. 短信发送必须在审批事务提交后触发，并复用现有短信 MQ 和短信日志能力。
10. 并发审批必须保证同一轮待审核状态只产生一次通知；已审批订单继续遵守现有“不能重复操作”语义。

## SMS Content

业务内容为：

```text
您的订单已审核通过，预约服务时间：${time}。请及时进入“${tenant}”小程序完成支付。
```

系统短信模板服务当前使用 `{time}`、`{tenant}` 解析本地模板参数；因此系统模板配置应使用等价的 `{time}`、`{tenant}` 占位符，短信平台侧按其审核通过的模板参数格式配置。代码只传递参数名和值，不拼接短信正文。

## Edge Cases

| 场景 | 处理 |
|---|---|
| 订单不存在或服务订单扩展记录不存在 | 保持现有审批错误语义，不发送短信。 |
| 当前状态不是待审核 | 保持现有“已审核不能重复操作”错误语义，不发送短信。 |
| 并发审批同一订单 | 通过带待审核条件的原子更新只允许一个请求成功；只有成功请求注册短信发送。 |
| 预约时间为空或格式异常 | 审批结果不回滚；记录通知构建失败，短信不发送。实现阶段应沿用现有数据校验并补充测试。 |
| 租户名称查询失败 | 审批结果不回滚；记录通知失败原因，短信不发送。 |
| 用户不存在或手机号为空 | 审批结果不回滚；由现有短信服务记录/返回手机号校验失败，并记录业务日志。 |
| 短信模板未配置或未启用 | 审批结果不回滚；记录模板校验失败。 |
| 短信 MQ 投递或供应商发送失败 | 审批结果不回滚；复用现有短信日志记录发送结果，并记录业务上下文。 |

## Acceptance Criteria

- [ ] 审批状态从待审核变为审核通过后，事务提交后调用模板 `service_approval_notification`。
- [ ] 短信发送给该订单的下单 Member 用户。
- [ ] 参数 `time` 为预约开始时间，格式为 `yyyy-MM-dd HH:mm`。
- [ ] 参数 `tenant` 为订单所属租户名称。
- [ ] 审批拒绝不发送短信。
- [ ] 拒绝后修改并再次审批通过时再次发送短信。
- [ ] 已审批订单不能重复审批，也不能重复注册本轮短信通知。
- [ ] 短信模板、渠道、手机号或供应商发送异常不影响审批结果。
- [ ] 审批事务回滚时不发送短信。
- [ ] 模板参数缺失、租户名称不可用、手机号为空等异常有可检索日志。
- [ ] 现有服务订单审批、拒绝后修改和短信发送测试保持通过。

## Assumptions

- `siteStartTime` 是本短信要求的预约服务时间，不使用服务结束时间或实际履约时间。
- `tenant` 使用系统租户的 `name`，不使用门店名称、商圈名称或小程序 AppID。
- `service_approval_notification` 已由各环境管理员在短信平台和系统短信模板管理中配置、审核并启用；功能代码不新增环境相关的 API 模板 ID、渠道或密钥配置。
- 现有 `SmsSendApi.sendSingleSmsToMember` 及其异步 MQ、短信日志链路满足发送基础能力，不新增通知表、重试表或公开重发接口。
- 现有系统短信日志是发送审计事实；业务日志补充订单号、租户 ID 和模板编码，不记录密钥或完整手机号。
