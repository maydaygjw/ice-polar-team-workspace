# 店铺收款人绑定界面设计

## 页面范围

只调整管理后台现有店铺编辑页和订单结算管理页。复用 Element Plus 表单、选择器、标签、表格和消息反馈；不新增页面入口或改变小程序支付体验。

## 店铺编辑页

### 表单结构

在现有“分账收款人”表单项处改为“主分账收款人”，保留单选下拉和当前分账开关。该主收款人仍是本系统分账及新生成应收应付的唯一店铺收款主体。

在其下增加“其他店铺收款人”区块：

| 区域 | 内容 |
|---|---|
| 提示说明 | “用于订单结算同步匹配。有效/无效仅作记录；两种状态都会参与匹配。此处收款人不会用于本系统分账。” |
| 绑定列表 | 收款人名称、脱敏 Member ID、关系标记、操作。 |
| 添加操作 | 从当前租户店铺级收款人中选择并加入列表。 |
| 关系标记 | 每行提供“有效/无效”单选或选择器，默认有效；状态变化只保存标记。 |
| 移除操作 | 明确提示将结束当前店铺关系；历史关系保留用于历史记录核查。 |

每行使用 `el-tag` 区分“有效”和“无效”，同时显示文字，不能只靠颜色传达状态。表单控件使用可见标签；不以 placeholder 代替字段名。提交期间禁用重复提交，成功后显示现有统一成功提示，失败时保留填写内容并显示具体错误。

### 选择与校验

- 主收款人单选，保持当前启用收款人的校验和分账启用校验。
- 非主列表允许多个 recipient ID，但同一店铺不重复；主收款人同时存在于非主列表时给出提示并阻止重复配置。
- 非主关系状态只允许 `有效` / `无效`；无效仍然保留在列表且继续参与订单结算同步匹配。
- 全局禁用或历史绑定的收款人仍显示在已绑定列表，使用独立状态标签呈现，避免误以为有效/无效标记改变了 AdaPay Member 状态。
- 若该店铺尚未保存，先创建店铺再保存收款人绑定；编辑已有店铺时主绑定和非主列表通过完整绑定接口一次提交。

### 空、加载和错误状态

- 首次加载绑定列表时显示表格骨架或行内 loading，不闪现“无绑定”空态。
- 无非主收款人时显示简短空态说明和“添加收款人”按钮。
- 候选收款人为空时说明当前租户暂无可绑定的店铺级收款人，并提示先在分账收款人管理中同步/创建。
- 保存失败时保留本地选择；跨租户或类型校验错误显示后端业务提示。

## 订单结算管理

同步操作沿用现有按钮和加载状态，不因非主关系标记无效而禁用。同步后详情中的已匹配收款人沿用现有表格结构，并展示收款人名称、脱敏 Member ID、金额、手续费承担标记。

- 本地唯一匹配到某店铺收款人时展示该收款人。
- 未匹配或多重匹配时展示“未匹配/待核查”，不显示任意收款人名称。
- 不展示 AdaPay 未返回的来源渠道推断。
- 保留键盘可达性、焦点可见、错误提示靠近操作上下文；状态文本对比度按现有语义色达到 WCAG AA。

## 适配与视觉

- 保持现有店铺编辑弹窗表单栅格和间距，不引入新的颜色、字体或依赖。
- 在窄视口下非主绑定列表改为纵向信息行，避免横向滚动；名称和脱敏 Member ID 可换行，操作按钮保持可见。
- 表单操作间距至少 8px；可点击目标不小于 44×44 CSS px。
- 页面不新增动画；加载、保存和状态变更依靠明确的 loading、成功、错误反馈表达。

## 设计依据

现有页面已使用 Element Plus 表单和下拉控件。UI/UX Pro Max 的表单检索建议字段具有关联的可见标签，并在提交后反馈成功或错误；Vue 栈检索建议复杂验证可使用 VeeValidate/FormKit，但项目当前使用 Element Plus 和既有校验机制，本次沿用现有实现，不引入校验库。该检索未提供与项目完全匹配的特定后台视觉模式，布局和颜色遵循现有管理端样式。
