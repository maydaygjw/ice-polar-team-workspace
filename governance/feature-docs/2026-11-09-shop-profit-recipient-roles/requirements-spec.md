## Feature: 店铺多分账收款人绑定与对账归属

### Scope

**In Scope**

1. 一个店铺可绑定一个主分账收款人及多个对账收款人。
2. 本系统生成的店铺订单分账和应收应付中的店铺收款主体只使用主分账收款人；对账收款人只用于订单结算记录匹配及对账归属。
3. 管理后台可以查看和维护主收款人与对账收款人的绑定用途。
4. 保留绑定关系变更历史；既有订单、支付时分账快照和已生成的对账结果不回算或改写。
5. 订单结算管理同步 AdaPay 分账状态时，可按该订单所属店铺绑定的任一收款人匹配远端分账明细，包括主收款人与非主收款人；非主收款人的有效/无效标记不影响匹配。
6. 在已有本地支付和分账确认可关联的范围内，日终对账使用 AdaPay Div 行的收款 Member ID 检查实际收款人与本地预期明细的差异。

**Out of Scope（当前假设，待确认）**

1. 通过本地绑定阻止 AdaPay 控制台或其他独立系统、渠道直接发起的分账。本地应用不能控制未经过本系统的分账入口。
2. 推断 AdaPay 账单未提供的分账来源渠道。Div 账单没有来源渠道字段。
3. 在无法关联本地订单或无法唯一识别店铺时，自动将外部流水归到某个店铺。
4. 非 AdaPay 支付渠道的分账与对账。

### Use Cases

**UC-1：管理员设置店铺主收款人与对账收款人**

- 角色：有店铺维护权限的管理员/运营人员。
- 目标：登记店铺用于本系统分账的主收款人，以及可能被其他入口用于收款、需要在对账时识别的收款人。
- 主流程：
  1. 管理员在店铺编辑页选择一个主分账收款人。
  2. 管理员选择零个或多个对账收款人。
  3. 系统校验收款人属于当前租户且类型适用于店铺，并保存关系与用途。
  4. 页面清楚显示各收款人的用途和启用状态。
- 业务规则：
  - 一个店铺最多有一个当前主分账收款人。
  - 对账收款人不得作为本系统分账目标。
  - 非主收款人可标记为“有效”或“无效”；该标记只记录店铺关系状态，不代表 AdaPay Member 或结算账户的实际状态。
  - 非主收款人的有效/无效标记不影响订单结算管理同步分账状态时的 Member ID 匹配。
  - 一个收款人重复添加到同一店铺时不得产生重复绑定。

**UC-2：本系统按主收款人创建分账**

- 角色：支付、计费及分账处理流程。
- 目标：确保本系统的支付分账、计费规则解析、分账请求和重试只使用主收款人。
- 主流程：
  1. 支付或分账流程读取店铺当前主收款人。
  2. 服务端校验其用途为主分账收款人，并执行既有状态、租户和结算账户有效性校验。
  3. 订单分账明细仍保存支付时实际采用的收款人快照。
- 业务规则：
  - 对账用途的收款人不可由前端参数、计费规则或重试请求绕过用途校验后用于本系统出账。
  - 主收款人变更只影响后续新交易，不改写历史订单分账明细。
  - 生成应收应付时，店铺对应的商家收款主体取生成时的主收款人并固化快照；非主收款人不替代该主体。

**UC-3：财务核查其他收款人产生的分账差异**

- 角色：财务/运营人员。
- 目标：识别 AdaPay 实际收款 Member 与本地订单预期收款人不一致的情况，并利用店铺绑定信息辅助定位归属。
- 主流程：
  1. 日终对账按已有支付/确认关联关系读取对应 Div 行。
  2. 系统按 `(paymentId, confirmId, Member ID)` 汇总账单金额，与本地分账明细比较。
  3. 当账单出现本地未预期的 Member ID 时，记录收款人差异；若该 Member ID 有唯一店铺对账绑定，则展示该店铺归属供核查。
  4. 管理员在对账明细中查看账单金额、本地预期金额、Member ID 脱敏信息和差异状态。
- 业务规则：
  - 来源渠道不可从现有 Div 账单推断；页面不得显示未经账单/API 支持的渠道判断。
  - 若一 Member ID 关联多个店铺，或不能唯一关联到店铺，结果标记为待核查，不自动归属到单一店铺。
  - AdaPay 有确认单但本地没有对应分账记录时，现状只产生确认单级汇总差异。本期是否扩展这类记录的收款人明细和店铺归属，列为待确认事项。

### UC-4：管理员同步订单的远端分账状态

- 角色：财务/运营人员。
- 目标：将 AdaPay 返回的分账状态和实际分账明细同步到订单结算记录。
- 主流程：
  1. 管理员在订单结算管理中对 AdaPay 订单执行“同步分账状态”。
  2. 系统查询 AdaPay 已有的支付确认与分账明细。
  3. 系统以订单所属店铺为范围，将远端分账明细按完整 Member ID 匹配到该店铺绑定的任一收款人。
  4. 匹配包含主收款人和全部非主收款人，不因非主收款人关系标记为无效而跳过。
  5. 系统同步本地分账状态和明细，不创建或重试远端分账。
- 业务规则：
  - 该操作只查询和同步 AdaPay 已存在的支付确认，不发起资金操作。
  - 脱敏 Member ID 只用于展示，不用于匹配。
  - 成功匹配的非主收款人仍按非主用途记录，不因此获得本系统分账授权。

### Business Rules

1. 所有店铺、收款人和绑定关系均按租户隔离；管理端读取和写入遵守现有店铺数据权限。
2. 主分账收款人和对账收款人是不同用途。用途校验必须在服务端实际分账路径执行，不能只依靠管理端隐藏选项。
3. 只有主收款人进入本系统订单的分账规则解析、分账订单明细生成、AdaPay 分账请求及失败重试。
4. 生成应收应付时，店铺收款主体使用生成时的主收款人并保留快照；后续关系变更不回算历史记录。
5. 订单结算管理同步远端分账状态时，按订单所属店铺的收款人关系匹配 Member ID；主收款人与非主收款人均参与匹配，非主收款人的有效/无效标记不参与匹配筛选。
6. 非主收款人的有效/无效是店铺关系上的记录标记，不等同于 AdaPay Member、结算账户或全局收款人状态，也不改变本系统出账授权。
7. 对账收款人用于 Member ID 到店铺的辅助映射，不代表系统授权该收款人参与本系统分账。
8. 绑定启停、更换或移除不得修改既有支付/分账/应收应付/对账快照；历史绑定应保留足以解释旧交易的生效区间或等效审计信息。
9. Member ID 是对账匹配键；角色或收款人名称只能用于展示，不能替代 Member ID 匹配。
10. 对账发现账单金额或收款 Member 与本地预期不一致时标记差异供人工核查，不自动冲正、调账或重试资金操作。
11. 本地用途和绑定规则只约束经过本系统的调用。外部渠道的分账阻断需由该渠道或 AdaPay 权限配置实现，不能以本地映射承诺拦截。

### Frontend Requirements

**管理后台**

| 页面 | 要求 |
|---|---|
| 店铺编辑 | 分开展示主分账收款人和对账收款人；主收款人单选，对账收款人多选；说明对账绑定不会让该收款人进入本系统分账。 |
| 收款人选择 | 只允许选择当前租户的店铺级收款人；显示名称、Member 类型、脱敏 Member ID 和启用/结算账户状态。 |
| 非主收款人关系 | 可标记“有效/无效”；说明该标记只作记录，订单结算管理同步分账状态时两种状态均参与匹配。 |
| 对账明细 | 对已支持的分账确认展示账单与本地差异、脱敏 Member ID、可唯一确定时的店铺归属；来源渠道没有数据时不展示来源推断。 |
| 订单结算管理 | 同步分账状态时按订单所属店铺匹配任一已绑定收款人，不按非主收款人的有效/无效标记过滤。 |

**小程序/H5**

无新增配置页面；支付行为对用户保持现状。

### Edge Cases

- 店铺未配置主收款人但配置了对账收款人：不得因此启用本系统分账。
- 主收款人未启用、无有效结算账户或不属于当前租户：按既有规则拒绝本系统分账。
- 同一收款人重复绑定为同一店铺的对账收款人：去重或拒绝，不重复计数。
- 收款人从主用途改成对账用途：仅影响之后交易；既有订单快照仍指向支付时收款人。
- 非主收款人关系标记为无效：订单结算管理同步远端分账状态仍按 Member ID 匹配该收款人。
- 应收应付生成后主收款人发生变更：历史商家收款主体快照仍保持生成时的主收款人。
- 收款人禁用或本地解绑后仍有历史交易：历史绑定信息可供既有结算/对账查询，不能把历史关系当作当前分账授权。
- 账单出现本地明细没有的 Member ID：记录差异；仅在绑定关系唯一时提供店铺归属。
- Member ID 同时绑定到多个店铺：标记归属歧义，不任意选择一家店铺。
- 账单有确认单但找不到本地分账订单：当前仅能形成汇总级差异；是否读取 Member 明细并做店铺映射待确认。
- AdaPay 账单不含来源渠道：对账结果不可标记具体外部渠道。
- 跨租户传入收款人 ID 或店铺 ID：拒绝请求，且查询不泄漏其他租户记录。

### Acceptance Criteria

- [ ] 店铺可同时保存一个主收款人和多个对账收款人，并能区分用途。
- [ ] 本系统新支付/分账流程及失败重试只会使用主收款人；对账收款人不能通过前端、计费规则或服务端请求参数绕过用途校验。
- [ ] 管理端可以维护并清楚区分两类绑定，显示用途说明和必要的脱敏状态信息。
- [ ] 应收应付生成时，店铺收款主体取主收款人并固化；非主收款人不替代该快照。
- [ ] 订单结算管理同步 AdaPay 分账状态时，可匹配该店铺的主收款人及全部非主收款人；非主关系标记为有效或无效均不影响匹配。
- [ ] 对已有本地支付/分账记录的交易，账单 Member ID 与本地预期不一致时，能呈现差异；有唯一对账绑定时可辅助归属到店铺。
- [ ] 无法唯一确定店铺时标记待核查，不错误归属；没有渠道字段时不推断具体渠道。
- [ ] 现有主收款人迁移后仍保持原绑定和分账行为；历史订单、分账记录和已完成对账结果不被改写。
- [ ] 所有读写遵守租户隔离、店铺数据权限及既有财务审计要求。

### Assumptions and Open Questions

1. **本系统与外部渠道边界**：本阶段的出账拦截仅适用于经过本系统的分账入口；不包含直接控制 AdaPay 控制台或独立外部渠道的权限。外部账单没有来源渠道字段，不推断由哪个渠道发起。
2. **无本地订单的 AdaPay 确认单**：待确认是否扩展日终对账，使其为本地无分账记录的确认单展开 Div 收款人明细，并按店铺绑定匹配归属。当前明确的“任一店铺收款人均可匹配”适用于订单结算管理的同步分账状态操作。
3. **共享 Member ID**：订单结算管理按订单已知的所属店铺，在该店铺绑定关系范围内匹配；无本地订单的流水若同一 Member ID 关联多个店铺，仍无法仅凭 Member ID 唯一确定店铺。
4. **非主关系标记**：有效/无效仅为店铺绑定记录的标记；不改变 AdaPay Member、结算账户或全局收款人状态，也不影响订单结算管理的匹配范围。
