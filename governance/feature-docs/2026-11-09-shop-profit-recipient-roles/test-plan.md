# 测试计划

## 范围

验证店铺主/非主收款人绑定、应收应付主收款人快照、订单结算状态同步匹配和管理后台交互。测试使用本地单测、Mapper/服务测试及 AdaPay 响应模拟，不调用真实 AdaPay 资金接口或生产环境。

## 后端场景

| 场景 | 预期 |
|---|---|
| 迁移已有主绑定历史 | 旧记录用途为 PRIMARY、标记有效，原有效期和快照不变。 |
| 保存主收款人和多个非主收款人 | 同租户、店铺级收款人写入；重复 ID 被拒绝或规范化；跨租户、非店铺级收款人被拒绝。 |
| 非主绑定有效标记改为无效 | 记录产生新历史版本；Member ID 匹配结果不变。 |
| 订单结算同步导入远端 `div_members` | 主收款人和有效/无效非主收款人均按店铺与完整 Member ID匹配。 |
| Member ID 未匹配或多重映射 | 不任意关联收款人，返回/保存待核查明细。 |
| 已有本地分账记录同步状态 | 只更新状态、手续费和对应明细 feeFlag；不改写支付时收款人和金额快照。 |
| 店铺生成应收应付且存在非主绑定 | 商家主体 recipientId 仍为主收款人；非主收款人不进入应收应付或分账目标。 |
| 全局禁用非主收款人 | 仍可通过历史店铺关系解析订单结算同步 Member ID；不影响主出账校验。 |
| 保留主收款人但关闭分账开关 | 该主关系仍参与订单结算同步匹配；不允许新发起分账。 |

## 管理后台场景

| 场景 | 预期 |
|---|---|
| 打开店铺编辑页 | 主收款人单选；非主列表多选/逐条标记；有效/无效说明清楚。 |
| 保存非主收款人为无效 | 保存标记但该收款人仍保留在列表和同步匹配范围。 |
| 清空或删除非主绑定 | 当前关系结束，历史版本保留。 |
| 同步 AdaPay 分账状态 | 无效标记不禁用同步按钮；成功后显示正确的已匹配或待核查状态。 |
| 网络或校验失败 | 用户输入保留，显示错误提示；不出现部分绑定保存。 |

## 数据与安全检查

- 所有查询按 `tenant_id` 和店铺范围执行；跨租户 ID 不可读取或写入。
- Member ID 在服务端按原值精确匹配，页面只呈现脱敏值。
- 应收应付和订单分账历史快照不因绑定修改而变化。
- 对账来源渠道不由 AdaPay 未提供的数据推断。
