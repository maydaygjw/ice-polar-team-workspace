# 审查报告

## 结论

功能实现审查通过，保留管理端全仓 TypeScript 检查未通过这一验证缺口。后端目标模块编译及映射测试、管理端生产构建均通过。

## 审查要点

- 店铺主收款人仍由 `profit_sharing_recipient_id` 表示；现有出账、计费和应收应付来源没有扩展到非主收款人。
- 非主关系与主关系用途分离，关系标记使用独立的 `mark_status`，解绑或标记变化保留历史版本。
- 新增绑定保存校验店铺范围、租户、收款人店铺归属、店铺级类型及主次重复；收款人全局状态不作为非主绑定有效性条件。
- 订单结算同步只匹配当前店铺关系中的完整 Member ID。VALID/INVALID 均可匹配；未匹配或多重匹配时不猜测归属。
- 前端请求和响应字段与 `contract-changes.md` 对齐；Member ID 仅展示脱敏值。
- AdaPay 返回数据没有渠道来源字段，界面和说明没有声称可以识别或阻止其他独立渠道。

## 验证缺口

- `pnpm ts:check` 报告 1570 条全仓 TypeScript 错误，包含既有的 API 全局类型缺失、组件类型不匹配及店铺表单类型推断错误。新增绑定 API 和绑定保存/回填代码行未命中诊断，但全仓检查仍失败。
- 未连接浏览器 E2E 环境；按 `test-plan.md` 保留人工验证场景。
- 未在实库执行 Flyway 迁移；部署前由独立 db-migrator 执行并验证迁移。
