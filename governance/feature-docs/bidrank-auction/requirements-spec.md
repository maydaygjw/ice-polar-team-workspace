# 商圈排名竞价 — Requirements Spec

来源：BACKLOG-005，遗留系统（饭火轮 PHP `addons/hlmall`）迁移。作为独立可售卖模块交付。

## Scope

平台运营方按商圈发布"排名竞价活动"，商家对本店所在商圈的排名档位公开升价竞拍；付清全款者入围，中标店铺在生效周期内于小程序门店列表按档位随机曝光。

### 交付分期

- **本期（backend + admin）**：`yshop-module-bidrank` 模块骨架、5 张表 + upgrade SQL、admin 周期活动配置（含档位、是否启用、内容说明/规则）、按模块套餐授权售卖。
- **延后（下一期，随小程序）**：app-api 竞价接口（出价/加价/预付/尾款）、结算入围 Job、退款 MQ、门店列表排序注入生效、小程序前端、admin 竞拍监控与入围结果查看。
- **Out（不做）**：密封投标模型、跨商圈打包竞价、竞价数据 BI 报表。

> 下文业务规则/流程描述完整功能；本期只交付上述"本期"子集，其余规则随延后期落地。

## 角色与用例

| 角色 | 用例 |
|------|------|
| 平台运营（admin） | 创建/编辑/发布/取消竞价活动；配置档位（范围+名额+起拍价）；查看竞拍与入围结果 |
| 商家（miniapp） | 查看本商圈活动与当前价栈；对某档位出价/加价（付预付）；付尾款；查看中标与生效状态 |
| C 端用户（miniapp） | 门店列表中，中标店铺在其档位范围内随机曝光（无感知） |
| 系统（Job/MQ） | 结算入围、写排序结果、异步退款 |

## Business Rules

1. **竞拍模型（分阶段透明升价）**：商家可对本店在某档位反复加价（自己一直加价），加价须满足最小加价幅度。价格透明度按档位是否出满分阶段：
   - **未出满**（有效出价数 < `slot_count`）：只展示起拍价，**不展示当前最低价/入围门槛**；此阶段任意 ≥ 起拍价的出价即先占位。
   - **已出满**（有效出价数 ≥ `slot_count`）：展示当前**最低入围价**（第 `slot_count` 高的出价）作为门槛；新出价欲入围、或已入围者欲保位继续加价，须 > 最低入围价 + 最小加价幅度。
2. **档位=范围+名额**：一个档位定义排名范围 `[rank_start, rank_end]` 与名额 `slot_count`（`slot_count ≤ 范围位数`）。允许范围重叠。
3. **随机曝光**：中标店铺不占固定名次，在其档位范围内**每次读取时随机**落位；范围内多余位置由默认排序填充。
4. **每店独立出价**：出价单绑定 `store_id`；同商家多店各自竞拍、各自计费。
5. **两段支付**：出价即付预付款＝当前出价 × `deposit_ratio`（默认 20%）；加价时补足预付差额。
6. **周期排期与尾款截止**：活动按 `cycle_type`（每周/每月）循环。每周期：竞拍开始 = 生效日期 − `advance_days`（当天 `start_time`）；竞拍结束 = +`duration_minutes`（出价锁定）；支付截止 = 竞拍结束 + `pay_minutes`（早于出结果）。商家须在支付截止前付清全款（全款−已付预付），此后不接受加价/新出价。
7. **出结果/结算**：支付截止后结算 Job 对**已付全款**的出价按档位出价降序取前 `slot_count` 名中标，于本周期生效日期起生效。
8. **未付尾款**：截止时未付清 → 出价作废、不参与结算、**预付款没收不退**。
9. **未中标退款**：已付全款但未入围 → **全额退款**，经 RocketMQ 异步处理。
10. **生效展示**：中标记录写入排序结果表，在 `[effect_start_date, effect_end_date]` 内对门店列表生效；周期结束自动失效。
11. **多租户/数据权限**：全部记录带 `tenant_id`；商圈从门店派生，档位/出价/结算带 `dept_id`。
12. **历史不可变**：出价历史、结算/退款财务记录一经生成不可改（红线）。
13. **按模块售卖**：功能整体挂独立菜单树，经租户套餐 `menu_ids` 授权；未授权租户后台无入口、app 接口短路，排序注入回退默认排序。

## Frontend Requirements

- **admin（本期）**：竞价活动列表/表单（含档位子表）、发布/取消。菜单受套餐授权显隐。
- **admin（延后）**：竞拍监控（价格栈、出价单）、入围结果查看 —— 依赖竞价数据。
- **miniapp（延后）**：商圈活动入口、档位状态、出价/加价+付预付、付尾款、我的竞拍状态。入口受租户 feature flag 控制。

## Edge Cases

- 并发出价/加价 → 需串行一致（分布式锁），按当前阶段校验门槛（未满：≥ 起拍价且高于自身上次出价+幅度；已满：> 最低入围价+幅度），拒绝不达门槛的出价。
- 出满临界（第 `slot_count` 个出价落地瞬间）→ 门槛从"起拍价"切换为"最低入围价"，以服务端串行结果为准。
- 尾款截止瞬间的临界出价/支付 → 以服务端时间为准，截止后一律拒绝。
- 中标者尾款支付成功回调延迟跨越截止 → 以支付单实际完成时间判定。
- 名额 > 有效出价数 → 剩余名额空置，由默认排序填充。
- 活动生效期与新活动重叠同一商圈 → 以生效中活动为准，新活动生效前不覆盖。
- 商家中途退店/停业 → 生效中排名按运营规则下线（本期：手动取消 + 退款按规则）。

## Acceptance Criteria

> 本期出口＝AC 1 + AC 6；AC 2–5 属延后期（随小程序）。

1. 运营可创建含多档位的活动并发布；未授权租户看不到菜单。
2. 商家可出价并支付预付；档位未满不展示最低价，出满后展示最低入围价；可反复加价，拒绝不达门槛的出价。
3. `final_pay_deadline` 后出价锁定，付清全款者进入结算，未付清者作废且预付不退。
4. 结算按档位取前 `slot_count` 名中标；未中标者全额异步退款。
5. 生效期内，中标店铺在门店列表其档位范围内随机曝光；周期结束失效并回退默认排序。
6. 所有出价历史与财务记录不可变；全链路租户隔离。

## Assumptions（已确认，可否决）

- 竞拍模型：分阶段透明升价 —— 档位未满不显示最低价、出满后显示最低入围价，可反复加价。
- 展示：范围内随机曝光（范围+名额，允许重叠）。
- 每店独立出价。
- 预付比例默认 20%；未付尾款预付款没收；尾款截止后不可加价。
- 时间模型：周期性排期（每周/每月 + 提前天数 + 启动时间 + 活动时长 + 支付时长），每周期派生实际时间。
- 保留老系统字段：是否启用、竞拍内容说明、竞拍内容规则（富文本）；显示天数比例改为范围内随机；**不做**商圈管理员可见/可编辑委派。
- 结算与排序采用确定性 Job（非遗留概率天数机制）。
