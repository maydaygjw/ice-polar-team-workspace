# 后台直接退款 — 需求规格

## 背景
订单管理页（`admin` 商城订单列表及「服务订单」列表）的操作中，管理员需要能对已支付订单**直接发起退款**，无需用户先申请退款、也不限制发货状态，退款后订单显示为「已退款」。

## 范围内
- 将现有「取消并退款」入口从「仅未发货」放宽到「已支付未退款的任意发货状态」（去掉 `statusStr==='未发货'` 限制，合并为单个下拉项）。
- 可见条件：`paid === 1 且 refundStatus === 0 且 isSystemDel === 0`。
- 行为：二次确认后按订单实付金额（`payPrice`）**一键全额退款**，走原退款链路（微信/支付宝/余额）。
- 退款成功后：`refundStatus = 2`（展示为「已退款」），同时 `status = -2`。
- 写入订单状态流水。
- 「订单 → 服务订单」页面增加可见的「退款」按钮，仅在 `paid === 1 且 refundStatus === 0 且 isSystemDel === 0` 时显示，不判断 `status`。

## 范围外
- 部分退款 / 自定义退款金额（仍由现有「确认退款」弹窗 `StoreOrderRefund.vue` 承担）。
- 不改动现有「确认退款」（退款中订单）逻辑。
- 无新增数据库字段、无新增接口、无新增权限点（复用 `order:store-order:update` 与 `cancelAndRefund` 端点）。

## 验收标准
1. 已支付未退款（refundStatus===0、未删除）订单的「更多」中出现「取消并退款」，不限发货状态。
2. 「服务订单」中 `paid===1 && refundStatus===0 && isSystemDel===0` 的订单出现「退款」按钮，`status` 为 0/1/2/3 均可。
3. 点击 → 确认弹窗显示退款金额 → 确认后退款成功。
4. 列表刷新后该订单状态显示「已退款」。
5. 已退款（`refundStatus===2`）、退款中（`refundStatus===1`）、已删除订单不显示「退款」入口。
6. 重复退款被后端拦截（`ORDER_REFUNDED`）。

## 边界与备注
- 单个下拉项覆盖所有已支付未退款未删除订单；不再按状态拆分多个同名项。
- 退款中订单仍走列表中独立的「确认退款」按钮（支持部分退款）。
