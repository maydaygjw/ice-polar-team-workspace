# 活动奖品与开奖规则管理测试计划

## 范围

覆盖 backend 奖品/规则/模板关联/期次快照，以及 admin 两个新页面和模板配置改造。无需新增 miniapp/h5 页面测试。

## 后端测试

### 单元测试

- 规则注册表返回 `POINTS`、`BALANCE` 元数据；未知规则不可保存。
- Key/Value 参数校验：必填、类型、正数、金额精度、范围、未知危险 key。
- 奖品 CRUD：名称唯一、租户隔离、启停、规则绑定；被引用奖品删除被阻断。
- 模板奖品整体替换：新增、更新、删除关联在同一事务；重复奖品和跨租户奖品被拒绝。
- 期次生成：复制奖品展示字段、规则参数和版本；后续奖品修改不影响快照。
- 发布清理：执行前备份并记录活动期次、报名、中奖、期次奖品、期次快照行数；清理后上述运行表行数均为 0，旧 `prize_config` 不被读取。
- 空壳规则：`POINTS`、`BALANCE` 可查询元数据并保存到奖品/期次快照，但开奖不调用积分、余额服务，不改变用户账户。

### 集成测试

- Admin API 登录、权限、租户和数据范围校验。
- 奖品 CRUD、规则查询、模板保存、期次详情完整响应。
- 开奖后只产生中奖结果和规则快照，不产生奖励发放记录，不改变用户积分或余额。
- 外部调用日志包含业务主键、规则、耗时、结果，且不打印敏感参数。

## 管理端测试

- `pnpm ts:check`、对应 test/prod build。
- 奖品新增/编辑 Key/Value 参数、字段级校验、规则切换限制。
- 模板选择奖品、只改数量/排序、停用奖品回显、重复选择阻断。
- 规则页只读；引用奖品删除失败原因正确展示。

## E2E 主场景

1. 创建加积分奖品，保存 `amount=100`，在模板中关联并设置数量，生成期次。
2. 修改奖品参数为 200，确认已生成期次仍为 100，新期次为 200。
3. 开奖后确认只生成中奖记录和规则快照，不改变用户积分或余额。
4. 重复触发开奖不会重复生成中奖结果。
5. 创建被模板引用的奖品，删除被拒绝；停用后已关联模板可回显，新模板不可新增。
6. 租户 A 的奖品、规则参数和模板关联不能被租户 B 查询或操作。
