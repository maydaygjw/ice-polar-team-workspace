# 活动奖品与开奖规则管理技术设计

## 模块影响

- `backend/yshop-module-activity`：新增租户奖品库、开奖规则注册表、模板奖品关联和期次奖品快照；扩展现有模板保存、期次生成和开奖流程。本期不新增奖励发放记录。
- `admin`：新增奖品管理、开奖规则只读页；活动模板改为选择奖品库中的奖品。
- `miniapp`、`h5`：本期不新增页面；已有期次详情/中奖结果只消费快照返回值，不依赖奖品库实时数据。
- 不引入新的外部系统，也不调用积分、余额发放服务；积分/余额规则只保留空壳注册类。

## 关键决策

1. **开奖规则是后端注册策略**：使用稳定标识注册 `DrawRuleHandler`，规则元数据包含名称、说明、参数说明和版本；管理端只能查询，不能配置脚本或类名。
2. **规则参数归属奖品**：奖品表保存 `draw_rule_type` 和 JSON `draw_rule_params`。模板只保存奖品关联、数量和排序，不重复保存或覆盖规则参数。
3. **奖品库与期次快照分离**：模板和奖品后续修改只影响新生成期次；期次奖品保存名称、图片、领取说明、规则标识、规则参数和规则版本。
4. **预留奖励扩展点**：抽奖只写中奖记录和开奖规则快照；本期不创建奖励记录、不执行奖励。未来启用奖励时再以中奖记录为幂等边界。
5. **规则切换采用新建奖品**：奖品被模板引用后允许修改展示信息和参数，但不允许直接更换开奖规则；需要更换规则时新建奖品，避免同一奖品语义漂移。
6. **历史运行数据清理后切换新模型**：发布前清空所有历史活动期次及关联运行数据；模板保存和期次生成只使用模板奖品关联，不读取旧 `prize_config`。

## 核心模型

### 奖品库 `yshop_activity_prize`

租户级可复用奖品。字段包括 `id`、`tenant_id`、`name`、`image`、`claim_instruction`、`draw_rule_type`、`draw_rule_params`、`sort`、`enabled`、通用审计字段和逻辑删除字段。

约束：同租户未删除奖品名称唯一；`draw_rule_type` 必须来自当前启用注册规则；参数由对应 handler 校验；被模板引用时禁止删除。

### 模板奖品关联 `yshop_activity_template_prize`

模板与奖品的多对多关联表，字段包括 `id`、`tenant_id`、`template_id`、`prize_id`、`quantity`、`sort`、审计字段和逻辑删除字段。唯一键为租户、模板、奖品组合。

保存模板时整体替换关联集合：先校验全部奖品，再在同一事务内新增、更新和逻辑删除关联，禁止部分成功。

### 期次奖品快照 `yshop_activity_period_prize`

保留现有展示字段，新增 `source_prize_id`、`draw_rule_type`、`draw_rule_params`、`draw_rule_version`。开奖和用户端结果只读取这些快照字段，不回查奖品库。

### 奖励发放记录

本期不新增奖励发放记录表。中奖记录只保存期次奖品快照中的开奖规则和参数，后续启用实际发奖时再增加独立奖励记录和状态机。

## 服务流程

### 奖品保存

1. 校验租户、名称、图片/说明字段和排序。
2. 校验开奖规则存在且启用，调用 handler 的参数校验器校验 JSON object。
3. 编辑时禁止改变已被模板引用奖品的规则标识；参数变更只影响后续期次。
4. 记录奖品变更审计，事务提交后返回完整奖品及规则摘要。

### 模板保存与期次生成

模板请求只提交 `prizeId`、`quantity`、`sort`。后端校验奖品可用、租户一致、规则仍可用，并保存关联表。

生成期次时读取模板关联和奖品库，在同一生成事务中写入期次奖品快照，复制规则参数和版本。若某个奖品或规则不可用，整期期次生成失败，不生成不完整快照。

旧模板 `prize_config` 不迁移、不转换，也不再读取；没有新模板奖品关联的模板需要重新配置后才能继续使用。

### 开奖与奖励

1. 现有开奖事务先锁定期次并写中奖记录，中奖记录保存期次奖品快照引用。
2. 中奖记录落库后不创建奖励记录，不调用积分/余额服务。
3. handler 仅保留注册、元数据和参数校验扩展点；积分/余额空壳类不得执行任何业务副作用。

## API 与权限实现约定

- 管理端控制器统一前缀 `/admin-api/activity`，详细请求/响应见 `contract-changes.md`。
- 奖品 CRUD 权限：`activity:prize:query/create/update/delete`；开奖规则查询权限：`activity:draw-rule:query`。
- 模板保存权限继续使用模板权限，但请求结构从内嵌奖品对象改为奖品关联列表。
- 所有查询、写入和引用校验均显式带 `tenant_id`；删除奖品前检查未删除模板关联。
- 外部调用必须记录结构化日志；本期没有积分/余额服务调用和奖励重试。规则保存/快照生成日志至少包含租户、业务主键、规则标识、耗时和结果；不得打印完整参数中的敏感值。

## 兼容与回滚

- 新增数据库对象仅包括奖品库、模板奖品关联表，以及期次奖品规则快照字段；不导入、不转换旧 `prize_config`。
- 发布前执行一次有备份的数据清理：删除所有活动期次及其报名、中奖、期次奖品和期次快照；模板表保留，但旧奖品 JSON 不再作为运行数据源。
- 新表或快照字段发布失败时回滚新增对象/字段；历史活动运行数据清理必须通过独立清理脚本和备份恢复，不与结构回滚混用。

## 风险

- 积分/余额服务不在本期范围，不评估其幂等能力和事务边界。
- 不保留新旧奖品模型并行路径；模板接口和页面只使用新奖品关联，不能把旧 `prize_config` 自动转换为新奖品。
- 规则版本升级不影响已生成期次；新版本必须通过新注册版本或兼容校验，不能覆盖历史快照含义。
