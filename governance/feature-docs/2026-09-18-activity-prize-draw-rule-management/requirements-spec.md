# 活动奖品与开奖规则管理需求规格

## Scope

为活动管理增加独立的奖品库和开奖规则管理能力：

- 管理端维护当前租户可复用的奖品。
- 后端注册固定的开奖规则，管理端只查询和选择开奖规则，不能新增或编写脚本。
- 奖品维护时关联一个开奖规则，并同时填写该开奖规则的参数（通用 Key/Value）。
- 每个奖品只能关联一个开奖规则；每个模板中的奖品关联只配置数量和排序。
- 生成期次时保存奖品名称、图片、数量、领取说明、开奖规则和规则参数快照。
- 开奖时保存中奖奖品对应的开奖规则快照，为后续奖励执行预留扩展点；本期不实际发放积分、余额或其他奖励。

不涉及：

- 管理端在线编写 JavaScript、表达式、SQL 或任意类名。
- 管理端新增开奖规则或改变规则执行代码。
- 修改已生成期次的奖品和规则快照。
- 修改现有抽奖位生成和中奖抽取算法；本需求只保存开奖规则配置和快照，不实现中奖后的奖励发放。

## Use Cases

### UC1：维护奖品库

管理员进入“活动管理 → 奖品管理”，按当前租户查看奖品列表，维护：

- 奖品名称；
- 奖品图片；
- 领取说明；
- 开奖规则；
- 开奖规则参数；
- 启用状态和排序。

奖品创建时必须选择一个已注册且启用的开奖规则，并填写该规则参数。奖品停用后不能被新模板选择，但已被模板引用时仍需回显。

### UC2：查看开奖规则

管理员进入“活动管理 → 开奖规则”，查看后端注册的开奖规则、名称、说明、参数提示和版本。

开奖规则是只读元数据，不提供新增、编辑或删除。每个开奖规则可以声明参数说明，具体参数值维护在奖品上。

### UC3：活动模板关联奖品

管理员创建或编辑活动模板时，从当前租户启用的奖品库选择一个或多个奖品，并配置：

- 奖品数量；
- 展示顺序；

同一个奖品在同一模板中不得重复关联。模板保存时服务端校验奖品存在、租户一致、状态可用，以及奖品已关联的开奖规则仍可用、参数合法。

奖品的开奖规则及其参数均由奖品库决定，模板不能修改开奖规则或规则参数。

### UC4：生成期次快照

生成活动期次时，将模板关联的奖品完整复制到期次奖品快照，至少包含奖品名称、图片、领取说明、数量、排序、开奖规则、规则参数和规则版本。

后续修改奖品库、开奖规则说明或模板配置，不影响已生成期次。

### UC5：保留开奖规则扩展点

开奖抽取中奖记录后，保存期次奖品快照中的开奖规则和参数，但本期不执行奖励发放：

- 积分规则和余额规则仅保留后端空壳类及注册标识；
- 空壳规则不调用积分、余额或其他外部/内部发放服务；
- 自定义规则仅保留后端注册策略扩展点，不能由管理员动态编程。

本期不产生奖励发放记录、不提供奖励重试接口，也不宣称积分或余额已到账。后续真正启用规则时再补充发放幂等、失败重试和审计要求。

## Business Rules

1. 奖品库数据按租户隔离，所有奖品、模板关联和期次奖品查询必须带租户约束。
2. 奖品名称在同一租户内唯一；删除是逻辑删除。
3. 已被任一活动模板引用的奖品不允许删除；必须先从模板中移除。
4. 奖品停用不自动修改已引用模板；已引用模板允许回显，但新模板不可新增停用奖品。模板保存时不得因既有停用奖品回显而丢失其关联。
5. 奖品被模板关联后，奖品库的名称、图片、领取说明、开奖规则和规则参数修改只影响后续新建期次；已生成期次使用自身快照。
6. 一个奖品只能绑定一个开奖规则；一个模板可以关联多个不同奖品，但同一奖品不得重复关联。
7. 开奖规则是后端注册表的稳定标识。规则元数据至少包括 `type`、名称、说明、参数说明、版本和启用状态；业务和管理端统一称为“开奖规则”。
8. 开奖规则参数统一为 JSON object 的 Key/Value，不允许脚本、表达式、任意类名、外部 URL、租户 ID、用户 ID、凭据或数据库语句。
9. 每种开奖规则由后端策略自行校验参数。示例：加积分使用 `{ "amount": 100 }`；加余额使用 `{ "amount": "10.00" }`。金额和数量必须使用对应规则的精度、范围和非负校验。
10. 奖励策略只能使用服务端传入的中奖用户、期次、奖品快照和已校验参数；策略不得信任客户端传入的用户 ID、租户 ID 或开奖规则。
11. 本期开奖只生成中奖记录和规则快照，不执行奖励发放；规则参数不得被解释为已到账结果。
12. 奖品数量参与现有开奖抽取逻辑；规则参数中的奖励数量只表示未来单个中奖用户的奖励值，不替代奖品数量。
13. 开奖规则参数只在奖品库维护，模板只关联奖品；生成期次时将奖品及其规则参数复制到快照，不得在开奖时读取模板或奖品库实时配置。
14. 奖品库和开奖规则查询接口使用管理端认证、租户隔离和活动权限；开奖沿用现有期次开奖权限和事务边界。
15. 发布前清空全部历史活动期次及其报名、中奖、期次奖品和期次快照数据；模板不再读取旧 `prize_config`，已有模板必须重新配置奖品库关联。

## Frontend Requirements

### 奖品管理页

- 列表：奖品名称、图片、开奖规则、规则参数摘要、规则说明、启用状态、模板引用数、更新时间、操作。
- 新增/编辑：奖品名称、图片上传、领取说明、开奖规则选择、开奖规则参数、启用状态、排序。
- 开奖规则只能选择后端返回的启用规则；编辑时规则可按业务规则限制为不可变，若要更换规则需新建奖品。
- 开奖规则参数使用通用 Key/Value 编辑器，并根据所选开奖规则展示参数说明。
- 被模板引用的奖品删除按钮可见但删除时必须展示后端阻断原因。
- 停用奖品后列表和模板选择器明确显示“已停用”。

### 开奖规则页

- 展示开奖规则、名称、说明、版本、参数说明和状态。
- 不提供开奖规则新增、编辑、删除按钮。

### 活动模板页

- 奖品配置改为从奖品库选择奖品，不再直接维护完整奖品对象。
- 每个已选奖品展示名称、图片、开奖规则、数量、排序和领取说明；规则参数只读展示摘要。
- 关联奖品时不允许修改开奖规则或规则参数；如需修改，先维护奖品库并按快照规则影响后续期次。
- 已被停用但已关联的奖品必须回显，不能在编辑模板时静默删除。
- 同一奖品重复添加时前端提示，服务端仍必须拒绝。
- 模板保存失败时保留参数输入和错误位置。

## Edge Cases

- 奖品已被模板引用时删除：拒绝删除且不产生部分删除。
- 奖品在模板编辑期间被停用：保存既有引用允许回显；新添加该奖品拒绝。
- 奖品在模板编辑期间被删除：保存时返回奖品不存在，不能保存模板。
- 开奖规则已从代码移除但奖品仍引用：奖品标记为规则不可用；不能新增模板关联，已有模板和期次按明确的失败/回滚策略处理。
- 参数缺失、类型错误、负数、精度超限或多余危险键：服务端拒绝奖品保存或模板保存。
- 开奖接口重复调用：抽奖结果幂等，不重复生成中奖记录；本期不涉及重复发奖。
- 活动没有奖品：允许模板保存，但开奖完成后中奖人数为 0；如产品要求必须有奖品，应在模板启用时阻断，需在设计阶段冻结。
- 奖品图片或领取说明为空：按管理端字段校验处理；不允许客户端自行补默认值。
- 租户 A 的奖品、规则参数和模板关联不得被租户 B 查询、修改、删除或引用。
- 旧 `prize_config` 中的奖品不进入新奖品库；模板接口统一只读取新模板奖品关联。

## Acceptance Criteria

1. 管理员可以创建、编辑、启停和查询当前租户奖品；已被模板使用的奖品无法删除。
2. 管理员可以查看后端注册的开奖规则，但不能通过管理端新增、修改或删除开奖规则。
3. 活动模板可以关联多个奖品，每个奖品可配置数量和排序；同一奖品不能重复关联。
4. 奖品可以关联一个开奖规则并维护通用 KV 参数；规则和参数不可由模板篡改，且保存时按规则策略校验。
5. 生成期次后，奖品和开奖规则参数冻结在期次快照中，后续奖品库或模板变更不影响该期次。
6. 积分和余额规则存在后端空壳注册类，但不会实际改变用户积分或余额。
7. 自定义规则只能由后端注册策略提供，管理端不能提交脚本、表达式、类名或外部调用地址。
8. 开奖结果包含规则快照，但本期不生成奖励发放记录或奖励重试流程。
9. 发布前历史活动期次数据已清空；旧模板奖品数据不迁移，模板接口不再兼容旧 `prize_config`。
10. 所有管理端 API 均验证登录、权限、租户隔离和引用关系；跨租户访问不得成功。
11. 后端模块测试、管理端类型检查/构建、奖品 CRUD、模板关联和开奖幂等场景通过。

## Assumptions

- 奖品库是租户级可复用资源，不跨租户共享。
- 开奖规则由后端代码注册，当前保留 `POINTS`（加积分）和 `BALANCE`（加余额）的空壳类及元数据；规则默认不可用于实际发奖，后续再实现执行逻辑。
- 奖品在奖品库中确定开奖规则并维护参数，模板只关联奖品，不填写或覆盖规则参数。
- 旧模板奖品 JSON 不迁移、不转换；新版本不读取旧 `prize_config`。
- 发布前清空历史活动期次、报名、中奖、期次奖品和期次快照；新版本从空期次数据开始运行。
- 积分和余额发放服务不在本期范围内；后续启用奖励时另行补充服务契约、幂等记录和失败重试方案。
