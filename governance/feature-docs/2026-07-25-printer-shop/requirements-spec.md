# printer-shop 需求规格

来源：BACKLOG-008（已确认范围/状态机/退款/拓扑）+ `governance/KNOWLEDGE/lianke-cloud-print-api.md`。

## Scope

**In**
- 新设备类型 `printer`，接入链科云打印 v3（后端直连，不经 DMS）。
- 打印店业态：一店 = 一云盒(deviceId) = 一打印机。
- 后端：设备/网关分发、按页计价（专属计价器，不侵入通用价格逻辑）、提交打印任务、查询、取消、接收链科状态回调、状态同步到设备订单与业务订单。
- 支付成功后自动提交打印任务（device-biz 消费 `order.pay.notice`）；打印失败自动退款。
- 页数：PDF/Office 文档由链科文件页数接口获取，图片按 1 页计；价格 =（SKU 基础单价 + Option 加价）× 页数 × 份数。
- 管理后台：仅「打印任务管理」页。

**Out**
- 小程序端（本期不实现，但回调/状态模型为其预留）。
- 一云盒多打印机、一店多设备。
- 扫描功能（链科支持但本期不用）。
- 打印店管理（复用现有门店管理）、打印机管理（复用现有商品管理）——不新增界面。
- 配送平台对接（接口未定，仅占位 `PrintDeliveryGateway`）。

**Deferred**
- 打印进度实时推送（先轮询/回调驱动）。
- 配送平台接入与业务订单 status=2（已送达）的自动推进（待配送契约）。

## Use Cases

1. 运营在后台创建打印店并绑定云盒(deviceId) → 系统校验 deviceId 唯一且与 shop_code 一致。
2. 运营配置打印商品（=该店打印机），纸张大小、颜色等能力通过商品 Option 配置，并可设置加价。
3. 用户下单打印商品并支付成功 → 系统自动向链科提交打印任务（含文件 URL + 规格）。
4. 链科回调任务状态 → 系统更新设备订单与业务订单状态。
5. 打印成功 → 业务订单进入"待收货/已完成"；失败 → 自动退款。
6. 运营在后台查看/重试/取消打印任务。

## Business Rules

- 一个店铺只能绑定一个云盒，一个云盒只对应一台打印机；`deviceId` 同时作 `shop_code` 与 `device_code`。
- 打印任务由支付成功触发（自动，device-biz 消费 `order.pay.notice`）。
- **计价**：按页。后端通过链科接口获取实际页数；价格 =（SKU 基础单价 + 纸张/颜色等 Option 加价）× 页数 × 份数。走打印专属计价器，普通商品价格逻辑不变。
- 业务订单主状态用全链 `0 待制作 → 1 配送中 → 2 已送达/待评价 → 3 已完成`；打印完成(SUCCEEDED)即推进到 1 并发起配送下单（配送接口未定，先占位）。
- 退款走独立 `refund_status`（0→1→2），终态 `-2 已退款`。
- 打印失败（含链科返回 `task_result.code != 0`）→ 自动退款，无需人工审核。
- 状态机只允许前进；重复/乱序回调幂等。
- 打印文件存 OSS 私有桶 + 短时效签名 URL；成功后按策略清理。
- 回调原文打 debug 日志，不入库。

## Frontend Requirements（admin）

- 仅新增「打印任务管理」：任务列表（task_id/店铺/文件/状态/失败原因/页数/时间）、详情、手动查询状态、取消、重试。
- 打印店沿用现有门店管理页，打印机沿用现有商品管理页，均不改动。

## Edge Cases

- 支付成功 MQ 重投 → 同一订单不得重复提交打印任务（按 orderNo/task_id 幂等）。
- 页数入参与附件实际页数不符 → 拒绝下单（防多收/少收）。
- 回调乱序（SUCCESS 先于 PARSING 到达）→ 以终态为准，不覆盖。
- 已 SUCCEEDED 后收到 REVOKED/FAILURE → 忽略，不回退。
- 链科回调无签名 → 校验 device_id 归属 + task_id 匹配 + 状态机合法，否则丢弃。
- 云盒离线/设备连接异常（task_result.code=503）→ 记 failureReason，自动退款。
- 文件 URL 过期导致链科拉取失败 → 视为打印失败。
- 配送平台接口未提供 → SUCCEEDED 后配送下单占位，业务订单暂不自动推进到 2。

## Acceptance Criteria

- 后台可创建打印店（门店管理）并绑定云盒，deviceId 唯一且 = shop_code = device_code。
- 下单传页数，后端用附件实际页数校验，不符拒绝。
- 打印订单按（SKU 基础单价 + Option 加价）× 页数 × 份数计价，普通商品价格不受影响。
- 支付成功后自动向链科提交任务并拿到 task_id（不重复提交）。
- 链科回调正确推进设备订单状态（前进且幂等），回调原文仅 debug 日志。
- 打印成功 → 业务订单 1 配送中，并调用配送占位接口。
- 打印失败自动退款，refund_status 0→1→2，主状态 -2，failureReason 已记录。
- 后台「打印任务管理」可查看任务列表/详情（含页数），支持手动查询/取消/重试。

## Assumptions

- 文件上传复用现有 OSS，提交任务用文件 URL + `urlFileExt`。
- 配送平台契约后续另起 feature 接入，本期仅占位。
- 回调地址 `POST /app-api/device/printer/callback` 已加入 yaml 白名单。
- 附件页数解析（方案 B）：PDF 取页数、图片计 1 页，下单时后端校验；Office 文档以链科解析结果为准，提交后回读比对，不符自动退款。
- 链科凭证（ApiKey/deviceId/deviceKey）走环境变量/本地配置，不提交仓库。
