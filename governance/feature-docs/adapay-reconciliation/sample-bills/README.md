## 用于对账开发的关键发现

### 1. 账单文件格式
- CSV 格式，以 `#` 开头的行是注释/元信息
- 每个文件以 `#合计：N笔，共X元` 结束，然后是 `#导出时间`
- 不同文件有不同的列结构

### 2. 分账记录结构 (Div.csv)
每笔分账订单有 2 行：
- 行1：平台收款 (分账用户=0, 手续费承担方=Y)
- 行2：店铺收款 (分账用户=MEMBER_UUID, 手续费承担方=N)
- 两行的 支付对象id + 原订单号 相同
- 交易金额 = 行1分账金额 + 行2分账金额（平台+店铺）

示例：
```
支付对象id=X, 订单号=CF_PC50484, 交易金额=14.90, 分账金额=4.58, 用户=0, 手续费=Y, 手续费金额=0.04
支付对象id=X, 订单号=CF_PC50484, 交易金额=14.90, 分账金额=10.32, 用户=MEMBER, 手续费=N, 手续费金额=0.00
```

### 3. 对账关联 Key
- **Charge.payment_id** = **Div.支付对象id** = **PaymentConfirm.商户支付ID**
- 这是三张表之间的主要关联字段

### 4. 交易状态
- S = 成功
- F = 失败（多为延时模式下未支付被关闭）

### 5. 手续费规律
手续费 = 交易金额 × ~0.25%（约），最低 0.02 元
```
14.90 × 0.25% ≈ 0.037 → 0.04
0.03 × 0.25% ≈ 0.000 → 0.00
```

### 6. 支付模式
所有记录均为「延时」模式（delay），与 ADR-002 一致。
