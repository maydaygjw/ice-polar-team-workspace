# 外卖用户画像

## Scope

### In
- 新建用户画像表，供外部系统导入并持续覆盖最新画像；每个用户仅保留一条当前记录。
- 在管理后台“会员”菜单下新增“用户画像”查询页面。
- 页面支持按会员 ID、新用户、用户阶段和标签筛选，并分页查看画像记录。
- 关联平台会员信息，展示注册时间和最近下单时间，并提供跳转至会员信息页的链接。
- 页面展示用户标签，但不提供标签编辑操作。

### Out
- 不提供后台导入、导出或批量维护功能。
- 不计算订单数或最近下单时间；用户阶段由后台定时任务按本文算法计算并写回。
- 不保留统计日期或历史画像；外部系统每次写入均更新当前画像，旧画像直接覆盖。
- 不提供标签的添加、移除、管理或审计能力。

## Use Cases

- 运营人员打开会员菜单下的用户画像页面，查询当前用户画像。
- 运营人员按新用户、用户阶段或标签筛选画像，并查看近期下单指标。
- 外部系统负责将画像数据导入画像表；页面只查询已导入的数据。

## Business Rules

- 每条记录代表一个用户的最新画像，不记录统计日期，也不保存历史版本。
- 画像字段为 `user_id`、`orders_3d`、`orders_7d`、`orders_30d`、`order_days_3d`、`order_days_7d`、`is_new_user`、`last_order_time`、`user_stage`、`user_tags`、`updated_at` 和内部计算水位 `stage_calculated_at`；会员关联信息另提供注册时间。
- 订单数、是否新用户、最近下单时间和标签由外部数据提供；后台定时任务按本文算法计算 `user_stage`。外部导入方不写 `user_stage`，每次插入或更新画像数据时必须刷新 `updated_at`。
- `user_tags` 为多值标签数组；无标签时以空数组表达。页面仅展示和筛选。
- 数据查询遵循当前租户隔离。

## 用户阶段算法（建议方案）

`is_new_user=true` 表示用户已注册但从未下过单，前台统一显示为“新用户”。订单窗口按导入时最新业务日期对应的 `Asia/Shanghai` 自然日计算；近 3/7/30 天均包含当前业务日。`order_days_3d`、`order_days_7d` 分别表示对应窗口内至少有一笔有效订单的自然日数量，同一天多笔订单只计 1 天。按以下顺序命中第一条规则：

1. `new`：`is_new_user=true`，即已注册但没有下过单。
2. `high_frequency`：`orders_3d >= 2`、`order_days_3d >= 2` 且 `order_days_7d >= 5`。即近 3 天至少 2 单且分布在至少 2 天，近 7 天至少 5 天下过单。
3. `occasional`：`is_new_user=false` 且 `orders_7d > 0`，但未达到高频条件。
4. `at_risk`：`is_new_user=false`、`orders_7d = 0` 且 `orders_30d > 0`。
5. `churned`：`is_new_user=false` 且 `orders_30d = 0`，表示有过下单但近 30 天无订单。

`new` 与原 `never_ordered` 含义合并，不再单独使用 `never_ordered` 阶段；`churned` 对应已流失。若 `is_new_user=true` 但订单窗口数或下单天数非零，仍按新用户阶段展示，同时视为导入数据质量异常；页面不修正输入值。

## Frontend Requirements

- 用户画像入口出现在后台会员菜单下，并遵循系统菜单权限。
- 列表展示会员 ID、注册时间、近 3/7/30 天订单数、近 3/7 天下单天数、最近下单时间、用户阶段、用户标签和更新时间。
- 列表展示是否新用户字段；新用户显示为“是”，其他用户显示为“否”。
- 支持按会员 ID、新用户、用户阶段和标签名称筛选，提供搜索、重置和分页。
- 关联会员展示注册时间和最近下单时间；会员 ID 可点击跳转至后台会员信息页。无关联会员时清晰展示未关联状态且不提供跳转链接。
- 空表显示数据由外部系统导入的说明；筛选无结果时提供清晰的空状态。
- 时间字段按业务时区展示，空的最近下单时间显示为空值占位。

## Edge Cases

- 表尚无导入数据时，页面显示空状态，不显示虚构指标。
- `is_new_user=true` 时 `last_order_time` 应为空，订单数及下单天数应为 0；有过下单的用户 `is_new_user=false`。
- 无标签时 `user_tags` 为空数组。
- `orders_3d <= orders_7d <= orders_30d`、`order_days_3d <= order_days_7d`、`order_days_3d <= orders_3d`、`order_days_7d <= orders_7d` 应由导入方保证；天数分别不超过 3 和 7。违反时不自动更正导入数据。
- 同一租户内每个外部用户仅保留一条画像记录；更新时覆盖旧数据，不保留历史数据。
- 查询不得返回其他租户的数据。

## Acceptance Criteria

- 后台会员菜单显示用户画像页面入口。
- 导入数据可在页面按会员 ID、新用户、用户阶段或标签筛选，并能分页查看画像及关联会员信息。
- 空表和无匹配结果均显示明确状态说明。
- 页面不触发订单统计、不提供画像数据导入，也不能修改画像或标签；阶段更新由后台定时任务触发。
- 同一租户、用户最多存在一条画像记录；不提供统计日期筛选或历史数据查询。
- 阶段规则遵循固定优先级，已注册未下单用户归为 `new`，不再使用 `never_ordered`；高频门槛同时使用近 3 天订单数及近 3/7 天下单天数。

## Assumptions

- 第一版数据导入由外部系统和页面外流程负责。
- 标签作为当前画像字段导入；本版不做标签运营编辑。
- 订单有效口径由外部数据提供方负责；外部导入方提供 `is_new_user`、订单数和下单天数，并在每次写入时更新 `updated_at`；后台定时任务异步生成用户阶段。
