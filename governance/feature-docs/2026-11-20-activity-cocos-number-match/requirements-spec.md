# Cocos 数字消除游戏接入活动的改造需求

活动用户从现有 H5 活动页直接进入全屏 Cocos 游戏，每次进入只玩后端指定的一关。游戏结束后返回活动页，由活动系统提交结果、决定下一关并结算奖品。本需求用于 Cocos 开发与活动 H5 联调。

## 游戏入口配置

管理端游戏配置增加启动类型 `launchType`：`LOCAL` 表示由活动 H5 根据 `gameCode` 选择本地路由；`REMOTE` 表示远程游戏。`number-match` 是数字匹配游戏的 `gameCode` 和远程目录名。远程游戏的基础域名通过系统参数 `game.remote-url` 维护（参数管理中的分类 `url`），游戏配置页面只保存入口类型；活动期次详情和 `POST /app-api/activity/period/game/start` 返回 `launchType` 及后端解析的 `launchUrl`。生成期次时仅快照入口类型，基础域名由系统参数实时提供。H5 将基础域名与 `/games/{gameCode}/index.html` 拼接，对远程入口传入 `mode=activity`、`levelNo`、`attemptId`，`attemptId` 使用 UUID 并按本需求开局/回跳约定存储和提交；本地路由行为保持现状。

## 改造范围

| 负责方 | 交付内容 |
| --- | --- |
| Cocos | 在 Web Mobile 入口增加活动模式，读取开局参数，运行指定关卡，将通过、失败或退出结果带回活动页。提供三关配置和可部署的构建产物。 |
| 活动 H5 | 调用开局和提交接口，管理登录态、活动期次、会话和幂等标识，负责游戏跳转、回跳处理及结果展示。 |
| 活动后端 | 复用现有三关会话、机会扣减和奖品结算。首版沿用客户端上报胜负的接口。 |

游戏以同域独立页面运行。Cocos 的 Web 入口适配层只处理浏览器参数和页面导航，游戏逻辑只接收关卡号和产出结果。Vue Router、登录凭证和活动 API 由活动 H5 管理。

## 开局与回跳契约

### 活动 H5 跳转到 Cocos

```text
/games/number-match/index.html?mode=activity&levelNo=2&attemptId=8f8cf016-42c6-4d46-a90d-12ea4b400cab
```

| 参数 | 规则 |
| --- | --- |
| `mode` | `activity` 表示活动模式。普通预览入口省略此参数，沿用原有玩法。 |
| `levelNo` | 必填，只接受 `1`、`2`、`3`，与活动关卡一一对应。 |
| `attemptId` | 必填，由 H5 生成的 UUID。Cocos 只校验格式并原样回传。每次正常进入一关时由 H5 生成，结果提交重试时复用。 |

活动 H5 调用 `game/start` 后，以 `attemptId` 为索引把 `periodId`、可选的 `templateId`、`sessionId` 和 `levelNo` 保存在当前标签页的 `sessionStorage`，再跳转。Cocos 只读取 URL 中的三个开局参数。必填参数缺失或无效时显示提示并停止开局，提供返回活动页的操作。

### Cocos 返回活动 H5

使用 `window.location.replace()` 跳到当前域名下固定的 `/activity.html`，以 `URLSearchParams` 构造查询参数。

```text
/activity.html?gameAttemptId=8f8cf016-42c6-4d46-a90d-12ea4b400cab&gameOutcome=pass
```

| `gameOutcome` | 触发条件 | H5 处理 |
| --- | --- | --- |
| `pass` | 当前关盘面清空，达到游戏通关条件。 | 按 `passed=true` 提交。 |
| `fail` | 当前关超时，或收集槽满且无法消除。 | 按 `passed=false` 提交。 |
| `exit` | 用户主动退出，或初始化失败后选择返回。 | 回到原活动，保留当前关进度。 |

回跳只携带 `gameAttemptId` 和 `gameOutcome`。如果开局时没有有效的 `attemptId`，返回不带游戏结果的 `/activity.html`。H5 在加载活动数据前，通过 `gameAttemptId` 恢复原期次和关卡，再复用现有提交逻辑，直接将该 UUID 用作 `requestId`。提交失败时保留结果和标识供重试。提交成功或收到 `exit` 后清理回跳参数和本地记录。结果值无效或无法匹配本地记录时，提示重新进入活动。浏览器或微信返回键直接离开游戏时，活动页按未收到关卡结果处理。

## Cocos 改造要求

1. **从指定关开始。** 在活动模式先解析参数，准备好盘面后再开始倒计时。用户进入第 2 或第 3 关时，直接显示并运行对应关卡。
2. **配置三关难度。** 为三关提供盘面和时限配置，按关卡逐步提高难度，可复用现有布局。活动盘面使用已验证可解的配置或题库，交付时记录各关的配置和通关验证结果。
3. **一关只产生一次结果。** 清盘、超时和槽满统一进入结束处理，停止计时和输入，锁定首次结果。胜负页的操作统一为返回活动，活动模式关闭游戏内的自动进关和重开。普通预览继续支持现有的开局、自动进关和重开。
4. **交付 Web Mobile 构建。** 提交 Cocos 源码和 Web 构建模板改动，提供构建版本、完整产物和预览步骤。产物应部署在 `/games/number-match/` 下，资源使用相对路径。以上路径和参数作为本次联调约定。

## 验收

- 用活动入口分别打开第 1、2、3 关，关卡标识、盘面和时限与配置一致。
- 清盘、超时、槽满各自回传正确结果。连续点击或结束动画与倒计时同时触发时，只回跳一次，结果保持一致。
- 主动退出和初始化失败返回活动后，活动 H5 不提交胜负。无效参数显示可返回的提示。
- 现有活动接入三关后，前两关通过时由活动页进入下一关。任一关失败或第三关通过时，由活动系统结算。提交重试复用同一 `requestId`。
- 在 iOS 和 Android 的微信小程序 WebView 中验证开局、触控、切后台返回及回跳。直接打开普通预览入口，原有玩法可运行。

首版以测试期次联调为目标。当前后端接受客户端上报的胜负，正式奖品所需的玩法过程校验另行设计。
