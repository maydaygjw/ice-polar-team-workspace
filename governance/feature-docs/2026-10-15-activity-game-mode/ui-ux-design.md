# 活动游戏模式 UI/UX 设计

## Admin 游戏管理（复用活动模板管理）

- 不新增独立导航菜单或管理页面；在现有活动模板列表页增加“游戏配置”入口，并复用现有 Dialog、表格和表单样式维护游戏目录。
- 列表列：游戏名称、内置类型、启用状态、更新时间、操作。无记录时显示空状态；分页、加载和接口错误沿用现有活动管理页模式。
- 游戏配置记录与活动模板记录共用活动模板表，通过记录类型区分。新建弹窗选择后端 `type-list` 返回的内置游戏代码并填写展示名称、启用状态。编辑时类型只读，可修改名称和启停；不显示脚本、源码或关卡编辑控件。
- 启停前说明：停用仅阻止新模板使用，不影响已生成期次。

## Admin 活动模板

- 在现有三步模板弹窗“活动信息/活动条件/活动奖品”保留布局，仅在活动模式单选组增加“游戏”。
- 选择游戏模式后显示内置游戏选择器；奖品配置区固定展示“第 1 关奖品”“第 2 关奖品”“第 3 关奖品”三行，使用现有奖品库选择控件。
- 游戏模式隐藏开奖时间和抽奖概率；开奖/抽奖模式保持现有控件和校验。
- 游戏停用后，已保存模板编辑页仍回显当前游戏及停用标记；用户切换到其他游戏模式时才要求选择新的可用游戏。
- 缺少游戏或某关奖品时，在对应表单项下显示校验错误；保存失败保留已填数据。

## H5 游戏参与

- 活动页按 `drawMode` 展示入口：“开奖”与“抽奖”保持现有流程；游戏模式在报名有效且期次开放时显示“开始闯关”。未报名、未开放或无效报名时入口不可开始，并沿用现有状态提示。
- `/game.html` 接收活动期次参数并请求后端开始/恢复会话；不将访问令牌放入 URL。会话加载失败显示重试和返回活动页操作。
- 游戏画面显示游戏名称、当前关卡（1/3 到 3/3）、当前关奖品名称、玩法说明和清晰的暂停/退出入口。
- 通过当前关后显示短暂成功状态和下一关入口；失败后显示“闯关结束”及上一关奖品；首关失败显示“本次未获得奖品”。三关通过时显示第 3 关奖品。
- 终局中奖结果复用现有中奖卡片展示及兑奖状态。自动发放奖品显示“立即兑奖”，调用现有兑奖接口；失败后保留可重试状态。线下兑奖显示“联系企业微信客服兑奖”，不显示自动兑奖操作。库存耗尽或单人限中时展示明确未获得奖品状态，不显示领奖按钮。
- 网络重试后恢复后端返回的当前会话状态；终局会话不可重新开始。关键操作使用按钮禁用和处理中反馈防止重复提交。
