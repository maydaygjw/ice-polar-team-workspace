# 活动游戏模式需求规格

## Scope

### In

- 活动模板新增“游戏”模式，与现有“开奖”“抽奖”模式并列。
- 后台用户在现有活动模板管理中维护可供活动选择的内置游戏配置；游戏配置记录与活动模板记录共用活动模板表，并通过记录类型区分。
- 游戏活动固定 3 关；活动模板奖品设置为每一关分别关联一个奖品。
- backend 提供游戏配置和活动模板所需接口，admin 提供游戏维护和模板配置界面，H5 提供游戏参与流程。
- 游戏模式活动沿用现有活动报名、期次生成、中奖记录和兑奖管理能力；具体接入规则在设计阶段明确。

### Out

- 管理员自行上传或编写游戏程序、脚本和关卡逻辑。
- 本期新增小程序端游戏页面。
- 改变现有“开奖”“抽奖”模式的玩法和历史期次行为。

## Use Cases

### UC1：维护内置游戏

活动管理员在游戏管理中查看可用内置游戏，维护游戏名称及活动可选状态。管理员不能上传或修改游戏程序本身。

### UC2：配置游戏活动模板

活动管理员创建或编辑活动模板时选择“游戏”模式，选择一个可用游戏，并为第 1、2、3 关分别选择一个奖品。模板保存后可回显完整游戏及逐关奖品配置。

### UC3：用户参加游戏活动

用户按现有活动流程查看游戏活动并报名。活动开放后，用户进入所选游戏，按 3 关顺序参与；每关对应模板配置的奖品。用户通过一关后继续挑战下一关，游戏结束时只结算最高已通关关卡对应的奖品。某一关失败后本次游戏立即结束，因此获得上一关奖品；第一关失败时没有上一关奖品。

## Business Rules

1. 活动模式包含“开奖”“抽奖”“游戏”；新建活动的默认模式仍为“开奖”。
2. 游戏来自后端内置的游戏类型集合，管理员维护的是可用于活动的游戏配置，不创建自定义游戏程序。
3. 游戏配置记录与活动模板记录共用活动模板表；活动模板只能选择当前租户可用的游戏配置记录。
4. 游戏活动固定 3 关，不允许活动管理员更改关卡数。
5. 游戏模式活动的奖品配置必须恰好包含 3 项，并按关卡顺序一关对应一个奖品；同一奖品能否用于多关由设计阶段确认。
6. 玩家通过当前关卡后可继续挑战下一关；游戏失败或成功通关全部 3 关时结束，并只结算最高已通关关卡对应的一个奖品。任一关失败即结束本次游戏，获得上一关（最近一次成功通关）的奖品；第一关失败不获得奖品。
7. 非游戏模式不要求选择游戏或提供逐关奖品配置，既有奖品配置行为保持不变。
8. 已生成期次使用生成时的游戏及逐关奖品配置；后续模板或游戏维护变更不追溯修改已生成期次。
9. 游戏配置和游戏活动模板受当前租户隔离；用户只能参与当前租户下有效、已开放的期次。

## Frontend Requirements

### Admin

- 增加游戏配置管理入口，展示游戏名称、内置游戏类型和启用状态，并支持维护名称及启停。
- 活动模板的模式选项增加“游戏”。
- 选择游戏模式后展示游戏选择器和固定 3 关的奖品配置项，清晰标记第 1 至第 3 关。
- 保存时明确指出缺失或无效的游戏、关卡奖品；编辑时完整回显已保存配置。
- 历史非游戏模板不因新增模式丢失既有字段或关联数据。

### H5

- 游戏模式活动在报名及开放状态满足时显示进入游戏的入口。
- 游戏体验按配置游戏进入并呈现 3 关及对应奖品信息；通过一关后进入下一关，失败或通关全部 3 关后结束并结算最高已通关关卡的奖品。
- 展示报名、未开放、游戏进行中、单关成功/失败、失败结束、通关完成或中断状态。
- 认证继续使用现有登录态；客户端不能自行决定奖品结果或向其他用户写入进度。

## Edge Cases

- 游戏被停用或不可用，但已被模板或期次引用：历史配置仍须可查看；新期次是否允许生成需在设计阶段明确。
- 游戏模式模板缺少游戏、关卡数不为 3 或某一关未配置奖品：拒绝保存并指出具体字段。
- 模板编辑期间所选游戏被停用：保存结果不得静默清空所选游戏或奖品。
- 用户重复进入、刷新、网络重试或切换设备：游戏进度和奖励不能重复生成或错误覆盖，具体恢复策略在设计阶段明确。
- 第一关失败没有上一关奖励；第二或第三关失败时，只结算最近一次已成功通关关卡的奖品，不得结算失败关卡或重复发放已结算奖品。
- 用户未报名、报名无效或期次未开放时进入游戏：拒绝开始游戏并返回明确提示。
- 期次配置快照与模板后续更新不同：用户参与已生成期次时仍按期次快照执行。

## Acceptance Criteria

1. 活动模板可以选择“游戏”模式；现有“开奖”和“抽奖”模板仍可正常编辑和使用。
2. 管理员可以维护内置游戏配置的名称和可用状态，不能创建自定义游戏程序。
3. 游戏模式模板要求选择一个可用游戏，并为固定的 3 关各配置一个奖品；缺项时保存失败并定位提示。
4. 非游戏模式模板不受游戏配置字段影响，原有奖品配置和校验保持有效。
5. 期次生成后能回显当时选择的游戏及每关奖品；模板或游戏配置后续变更不改变已生成期次。
6. H5 用户只能从有效报名和开放的游戏期次开始游戏，并能看到三关对应奖品及当前进度。
7. 通过某关后继续下一关；游戏结束时只结算最高已通关关卡的一个奖品，失败时该奖品属于上一关，首关失败不产生奖品。
8. 重复请求、重新进入和网络重试不会重复授予同一关奖励。
9. 游戏配置、模板、期次和用户进度遵循租户隔离，用户不能读取或操作其他租户的数据。

## Assumptions

- “闯关书”指“闯关数”；按用户确认，首期固定为 3 关。
- “用户维护游戏”指活动管理用户维护内置游戏配置（如名称、是否可选），不提供游戏程序编辑能力。
- 首期计划复用现有 H5 跳跃闯关演示作为一个候选内置游戏；其他首批内置游戏名称和玩法由设计阶段确认。
- 奖品暂按每关一个既有活动奖品配置；游戏结束时只结算最高已通关关卡对应的一个奖品，失败时对应失败关卡的上一关。
