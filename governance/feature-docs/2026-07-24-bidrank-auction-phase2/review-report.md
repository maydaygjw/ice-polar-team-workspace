# 商圈排名竞价（二期）— Review Report

## 结论

实现符合本期“先完成主体功能、暂不处理并发竞争”的范围，评审结论为通过，允许进入交付准备；真实支付沙箱、浏览器 E2E 和全量测试基线修复不作为本次实现阻塞项，但不能据此视为生产资金链路已验收。

## 已核查项

- 一个 `cycle + store` 只有一张出价单；首次选择档位后，后续加价必须使用同一档位。
- 加价要求上一笔预付已支付，并只支付预付差额，避免覆盖未完成支付单。
- 门店存在、商圈归属和当前用户门店管理员关系均由 store API 校验。
- 支付通过 pay API 分流 `bizType=bidrank`，商城订单消费者不会误处理竞价支付通知。
- 结算按出价、尾款支付时间和出价单 ID 排序，写入 store 通用排序接口；未中标全款单和已付预付但未付尾款单均进入退款/作废处理。
- admin 仅提供出价单与结算结果只读查询，不提供人工改价、人工改中标或退款重试。
- SQL 包含周期、出价单字段/唯一约束、支付来源字段和菜单迁移；租户字段沿用现有框架。

## 残余风险

1. 出价、支付通知和结算没有分布式锁、请求幂等号或可重入状态机；本期按用户确认暂不处理，必须进入 Phase3。
2. 退款失败目前记录日志并将订单置为作废，没有自动重试、对账或人工补偿入口。
3. 未执行真实支付沙箱和支付回调乱序/重复场景；支付渠道配置与退款结果仍需联调。
4. 管理端 `ts:check` 受仓库现有 4 个缺失类型声明阻断，生产构建已通过；建议单独修复前端基线依赖声明。
5. 全量 Maven 测试受既有 `DesensitizeTest` 失败阻断，失败与本次 bidrank 改动无关。

## 处理意见

- 本期保留简化实现，不扩大并发、实时竞争、退款补偿和运营干预范围。
- Phase3 必须优先补齐并发/幂等、支付状态机、退款重试对账和支付沙箱 E2E，再开放正式运营。
