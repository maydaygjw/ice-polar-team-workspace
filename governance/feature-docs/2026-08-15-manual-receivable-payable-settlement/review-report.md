# Review：手工触发应收应付结算

## 审查结论

实现符合本次调整：订单确认收货只调用通用 `calculate` 生成应收应付；配送回调不再触发分账；管理端按应收应付记录逐单结算；日终任务也从成功应收应付记录取数并复用同一结算服务。

服务端按当前租户校验主记录、支付记录和分账记录；仅允许 `SUCCESS`、`SUCCESS_WITH_DIFFERENCE` 且支付方式为 Adapay 的记录结算。已有分账状态机继续负责幂等、失败重试和收入回退。日终任务在结算失败且无法回退时停止当前批次，避免同一失败记录导致死循环。

## 剩余风险与验证缺口

- 尚未连接真实数据库和 Adapay 沙箱验证金额、外部状态回调及重复点击行为。
- 管理端生产构建通过，但未执行浏览器端 E2E；权限菜单需要随升级 SQL 部署后验证。
- 旧的店铺级分账配置校验仍存在于支付落库流程，用于兼容既有支付模式；本次移除的是确认收货/配送状态路径上的自动分账，不改变支付入口兼容逻辑。
- 日终任务对已经存在旧分账记录的历史数据不做应收应付回填；历史记录继续由原有历史页面和状态机制管理。
