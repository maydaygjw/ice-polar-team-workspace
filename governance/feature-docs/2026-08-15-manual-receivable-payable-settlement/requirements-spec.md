# 需求规格：手工触发应收应付结算

## Scope

本功能调整订单计费模板后的财务流程：订单确认收货只生成通用应收应付事实，AdaPay 分账由财务在应收应付管理页面逐单点击“结算”触发。

## Business Rules

1. 配送回调推进订单状态时不得创建或执行 AdaPay 分账。
2. 用户确认收货时，已支付订单仅调用通用计费 `BillingSettlementApi.calculate(orderId)`；计费失败不得阻断订单状态变更。
3. 应收应付记录为 `SUCCESS` 或 `SUCCESS_WITH_DIFFERENCE` 时，财务可发起结算。
4. 当前仅 Adapay 支付订单支持 AdaPay 结算；非 Adapay 订单仍可生成应收应付，但不可发起 AdaPay 分账。
5. 结算操作必须幂等：重复点击不得重复创建分账订单或重复调用已完成的分账。
6. 结算前校验应收应付主体及收款人配置；不满足条件时不执行分账，并保留可重试的失败结果。
7. 日终 Job 以应收应付成功记录为唯一的新订单来源；历史旧分账记录保留原数据，不由新应收应付流程回填。

## Acceptance Criteria

- [ ] 配送状态 `DLVRD/CMPL -> businessStatus=2` 只更新订单状态，不调用分账或 Adapay API。
- [ ] 用户确认收货只生成一条幂等应收应付记录，不自动创建 `yshop_adapay_profit_sharing_order`。
- [ ] 应收应付页面每条记录展示“结算”按钮；只有可结算记录可点击。
- [ ] 点击“结算”后，成功订单生成并执行 AdaPay 分账，页面刷新后显示分账状态。
- [ ] 重复点击、并发点击和已结算订单不会重复分账。
- [ ] 非 Adapay、失败计费、收款人缺失或主体金额不完整的记录不会执行分账，并返回明确结果。
- [ ] 租户隔离和结算权限生效。
