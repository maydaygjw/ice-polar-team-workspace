## Feature: 商品选项加价模式

来源：`governance/BACKLOG/BACKLOG-004-product-option-pricing.md`

### Scope

**In-scope**

- 商品新增「选项加价」能力：基础规格定价 + 属性/小料独立加价，不再依赖笛卡尔积穷举 SKU。
- 门店级小料库（`store_topping`）：门店统一维护小料的名称/价格/库存/排序/状态。
- 商品选项组（属性组 + 小料组）：组名、必选/可选、单选/多选、重复选、限购份数、默认选项、排序。
- 商品详情接口按 `spec_type` + `has_options` 返回规格 + 选项组。
- 下单价格计算：规格价 + Σ 属性加价 + Σ 小料加价 × 份数。
- 库存扣减：规格 SKU 库存 + 门店小料库库存（按份数）；属性默认不扣库存。
- 订单/购物车记录所选规格、属性、小料的快照及加价合计。
- admin 后台配置门店小料库与商品选项组。

**Out-of-scope**

- 小程序点单页改造（本期不交付，后续迭代；本期由后端接口保证可对接）。
- 不改动现有单规格（`spec_type=0`）与多规格笛卡尔积（`spec_type=1`）的既有逻辑。
- 不改变已支付历史订单的金额、佣金、快照（历史数据不可变）。
- 不引入新的支付方式或结算/分账规则变化。
- 小料跨门店共享、平台级小料库（本期仅门店维度）。
- 属性级独立打包费（打包费仅规格层 `pack_fee`）。

### Use Cases

- 门店运营：维护门店小料库（珍珠、椰果等），统一改价/补库存，关联商品自动生效。
- 门店运营：为奶茶商品配置杯型（规格）、甜度/温度（属性组）、加料（小料组）。
- 顾客：在小程序点单页选杯型、甜度、加料（可多份），实时看到加价后的价格。
- 系统：下单按选项计算价格、扣减规格与小料库存、写入订单选项快照。
- 管理员：在订单详情查看所选规格/属性/小料快照。

### Business Rules

- 价格：商品单价 = 选中规格 price + Σ 选中小料 price_delta × 份数。**属性不加价**。
- 属性仅作选择维度（如甜度、温度），不产生费用、不维护库存。
- 属性组支持单选/多选；**单个属性组可配置是否多选，默认单选（`multiple=0`）**。
- 必选组必须满足 `min_select`；多选组受 `max_select` 限制。
- 小料支持可选份数：同一小料可选多份（受 `max_quantity` 限制），按份数计费并扣库存。
- 小料在门店维度统一维护；小料改价/改名后，门店内所有引用商品同步生效（快照仅作用于下单时点）。
- 库存：只维护规格 SKU 库存与小料库存（按份数扣减）。**属性不维护库存**。
- 历史订单金额、佣金、快照不可变。

### Frontend Requirements

- admin：
  - 门店小料库 CRUD（名称/价格/库存/状态/排序）。
  - 商品编辑：开启 `has_options` 后配置属性组与小料组及其选项。
- 小程序点单页：本期不改造，仅由后端接口预留对接能力（返回 `specs` + `option_groups`、计价与扣库存规则）。

### Edge Cases

- 必选属性组未选或低于 `min_select` 时禁止下单并提示。
- 小料库存不足所选份数时下架/置灰该小料或提示。
- 规格 SKU 缺货但小料充足：整商品不可下单（按规格库存为准）。
- 小料被门店停用/删除：已关联商品下单时不可用；历史订单快照不受影响。
- 购物车中小料/规格后续被改价：以加入购物车快照 vs 下单实时价的一致性策略。

### Acceptance Criteria

- [ ] 商品新增 `has_options`，不影响现有单/多规格逻辑。
- [ ] 新增门店级 `store_topping`，支持名称/价格/库存/排序/状态。
- [ ] 新增 `product_option_group` 与 `product_option`，支持属性组与小料组。
- [ ] 属性组支持单选/多选（组级可配，默认单选）、必选/可选、默认选项、排序；属性不加价、不维护库存。
- [ ] 小料组支持多选、可选份数（限购份数）、排序；小料按份数加价并扣库存。
- [ ] 商品详情接口按 `spec_type` + `has_options` 返回 `specs` + `option_groups`。
- [ ] 下单价格 = 规格价 + 小料加价 × 份数（属性不加价）。
- [ ] 库存扣减 = 规格 SKU 库存 + 门店小料库库存（属性不扣库存）。
- [ ] 订单/购物车记录所选规格、属性、小料快照。
- [ ] admin 支持配置门店小料库与商品选项组。
- [ ] 小料门店维度统一维护，修改后关联商品同步生效。

### Assumptions

- 选项加价模式与笛卡尔积多规格互斥：同一商品同一时刻只用一种定价模式。
- 小料库为门店维度，暂不做平台级共享。
- 属性不加价、不维护库存，仅作选择维度。

### Open Questions

1. **购物车价格一致性策略**（非阻塞）。加入购物车后小料/选项改价，下单时用实时价还是快照价？默认：下单时按实时价重新计算，快照仅记录所选内容。
