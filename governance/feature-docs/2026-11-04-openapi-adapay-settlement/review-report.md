# Review Report

## 结论

代码审查通过，未发现阻止合并的实现问题。需要在 AdaPay 沙箱中完成支付、退款回调、主动结算与自动任务的端到端验证后再上线。

## 审查重点

- OpenAPI 请求以租户和 OAuth client 共同隔离；客户端不能指定店铺、模板或收款人。
- 支付创建时冻结商圈、店铺、计费项及收款人快照；支付成功回调只按该快照生成应收应付。
- 主动结算、自动结算、退款和支付/退款回调会锁定同一 OpenAPI 支付行。退款处理中阻止结算；退款失败恢复资格；退款成功将仍待结算记录标为 `CANCELLED`。
- 退款前检查分账状态，PROCESSING/SUCCESS 时拒绝；对账数据源通过 `biz_type=open_api` 接入 AdaPay 成功支付记录，不依赖商城订单行。
- 商圈配置只接受本商圈启用店铺，显式清除与历史支付快照互不影响。
- 迁移只增加 nullable 列与索引，无历史数据回填；未包含密钥或环境文件。

## 遗留验证

- AdaPay 沙箱下验证退款失败重试、回调幂等、主动/自动并发及 Payment/PaymentConfirm/Div 对账。
- 管理端全仓 `pnpm ts:check` 被既有全局类型错误阻断；本次管理端 `pnpm build:prod` 通过。
