# OpenAPI AdaPay 结算与对账需求规格

## Scope

### In-scope

- 按商圈代码为 OpenAPI 支付请求定位该商圈配置的 OpenAPI 默认店铺。
- OpenAPI 支付成功后，按该店铺的现有计费模板及分账收款人配置生成应收应付事实。
- 支持第三方客户端按其 `clientOrderNo` 主动请求 AdaPay 结算；授权沿用现有 `payment` scope。
- OpenAPI AdaPay 应收应付事实进入现有每日自动结算流程；客户端主动结算与系统自动结算共用幂等规则。
- 将 OpenAPI AdaPay 支付记录及其成功分账纳入现有 AdaPay 日终支付、分账确认和分账流水对账。
- 使 OpenAPI AdaPay 全额退款与分账互斥，并在退款完成后更新待结算应收应付资格。
- 在商圈管理中配置 OpenAPI 默认店铺。

### Out-of-scope

- 微信支付分账、微信支付账单下载及微信账单对账；OpenAPI 微信支付仍按现有支付能力处理。
- AdaPay 退款账单对账、分账差异自动调账，以及第三方订单在商城中的履约、商品或库存管理。
- 新增 OpenAPI 专属分账收款人管理；继续使用系统现有店铺分账收款人和平台收款人配置。

## Use Cases

### UC-1：第三方创建 AdaPay 支付

- **角色**：已授权的第三方 OAuth2 客户端。
- **目标**：用商圈代码、客户端订单号和金额创建 AdaPay 支付。
- **主流程**：平台校验客户端及租户权限、商圈代码、商圈 OpenAPI 默认店铺和支付配置，创建支付单并返回支付参数。`clientOrderNo` 是该客户端的外部订单标识，不代表商城订单。

### UC-2：按计费模板形成应收应付

- **角色**：系统。
- **目标**：为成功支付形成可结算的分账事实。
- **主流程**：支付请求时解析并保存商圈默认店铺及当时适用的计费上下文；AdaPay 确认支付成功后，以请求金额全额作为计费基数生成应收应付事实。历史事实不随模板或收款人后续变更而改变。

### UC-3：第三方主动结算

- **角色**：创建该支付单的第三方客户端。
- **目标**：在日终自动结算前主动触发该 AdaPay 支付的分账结算。
- **主流程**：客户端提交自身的 `clientOrderNo`，平台校验记录归属、AdaPay 支付成功状态、退款状态和结算资格，返回本次结算结果。
- 若支付成功后的应收应付主生成未完成，接口可按支付时保存的计费上下文幂等补生成，再尝试分账。

### UC-4：系统日终自动结算

- **角色**：系统。
- **目标**：自动结算 OpenAPI AdaPay 待处理应收应付记录。
- **主流程**：现有每日 00:05 分账任务处理符合条件的 OpenAPI AdaPay 记录；已由客户端主动成功结算的记录不重复执行。

### UC-5：AdaPay 日终对账

- **角色**：系统及财务管理员。
- **目标**：核对 OpenAPI AdaPay 支付和分账事实与渠道账单。
- **主流程**：现有日终对账任务将 OpenAPI AdaPay 成功支付纳入支付交易核对，将其成功分账纳入支付确认及分账流水核对；记录按现有能力查询和审计。

### UC-6：OpenAPI AdaPay 全额退款

- **角色**：创建支付单的第三方客户端。
- **目标**：在允许退款时原路全额退款，不与分账并发或冲突。
- **业务规则**：退款请求处理中时阻止主动和自动结算；退款成功后待结算应收应付失去结算资格；退款失败后恢复结算资格；分账处理中或成功时拒绝退款。

## Business Rules

1. OpenAPI 支付请求必须提交商圈代码；平台从当前租户下解析商圈及其唯一 OpenAPI 默认店铺，不允许客户端传店铺 ID 或分账收款人。
2. 同一商圈最多配置一个 OpenAPI 默认店铺；所选店铺必须属于该商圈且可用。商圈及店铺配置缺失或不匹配时拒绝创建新支付。
3. 请求金额继续使用人民币分的正整数；对 AdaPay OpenAPI 支付，整个请求金额等于计费基数，无优惠、无平台补贴。没有商城订单属性可供计费，默认店铺模板若引用订单属性则不能用于 OpenAPI 支付。
4. 商城订单不存在；`clientOrderNo` 仅标识同一客户端的外部订单。OpenAPI 支付、结算和对账不得依赖 `yshop_store_order` 记录。
5. 客户端只能查询或主动结算自身租户和 OAuth2 客户端范围内的 `clientOrderNo`。结算接口沿用 `payment` scope，不要求新增独立结算 scope。
6. 应收应付主生成时点是 AdaPay 支付确认成功；客户端主动结算接口仅负责幂等补生成缺失事实并执行分账。补生成必须使用支付请求时保存的计费上下文快照，不能按调用时的当前配置重算。
7. 主动结算只适用于 AdaPay 且支付成功、未退款、应收应付可结算的支付记录。微信支付不进入分账结算。
8. 主动结算与日终自动结算可以并发或重复触发，但同一支付只能产生一次有效结算；重复成功请求返回已有结算结果，不重复确认分账。
9. 系统自动结算沿用现有每日 00:05 任务；主动结算不改变该定时任务。
10. AdaPay 支付交易对账按 AdaPay 支付 ID 匹配 OpenAPI 本地支付记录；支付确认和分账流水按现有支付确认 ID、支付 ID 与收款人匹配规则核对。
11. OpenAPI AdaPay 全额退款继续使用现有退款接口和状态；如分账处于处理中或成功则拒绝退款。
12. 退款进入处理中后，系统不得发起该支付的分账；退款成功后取消待结算应收应付的结算资格，退款失败后可重新结算。
13. 退款与分账并发时必须串行化裁决，不能同时成功发起 AdaPay 退款和支付确认。
14. 所有新增或扩展的业务事实均按租户隔离；配置变更不得重写已生成的历史计费及收款人快照。

## Frontend Requirements

- 商圈新增/编辑表单可选择该商圈下的 OpenAPI 默认店铺，并在商圈列表展示其配置状态或店铺名称。
- 选择器仅提供属于该商圈的店铺；清除或停用已绑定店铺时提供明确提示，避免新支付请求静默落入无配置状态。
- 不新增 OpenAPI 收款人维护页面；复用已有店铺分账收款人和计费模板配置页面。

## Edge Cases

- 商圈代码不存在、停用或不属于当前租户：拒绝支付创建。
- 商圈未配置默认店铺、店铺已停用或归属关系不符：拒绝支付创建并返回可诊断业务错误。
- 同一客户端以相同 `clientOrderNo` 和相同请求重试：返回原支付单；金额、商圈代码或其他关键支付内容变化：返回冲突。
- 支付创建时模板或收款人配置不可用或包含订单属性规则：不得创建支付单。
- 支付已成功但应收应付生成暂时失败：保留成功支付，按请求时保存的计费快照幂等重试或由主动结算补偿，不得重复收款。
- 主动结算时支付仍待确认、已退款、使用微信渠道、或无可结算计费事实：返回明确的不可结算结果且不调用 AdaPay 分账。
- 主动结算和日终任务同时处理同一支付：只允许一次有效外部确认；外部结果未知时先查询/对账确认，不得盲目重复提交。
- 退款与结算并发：以唯一互斥结果处理；退款先进入处理中时结算拒绝，分账先进入处理中或成功时退款拒绝。
- 退款成功时，将仍待结算的应收应付标记为 `CANCELLED`；退款失败后保留原应收应付状态并恢复可结算资格。
- AdaPay 账单有 OpenAPI 交易而本地没有，或本地有交易而账单没有：按现有 `BILL_ONLY` / `LOCAL_ONLY` 规则记录差异。
- 商圈修改默认店铺或店铺更换计费模板/收款人：仅影响后续支付，不改写历史应收应付及结算记录。

## Acceptance Criteria

1. 管理员可为商圈配置一个属于该商圈的 OpenAPI 默认店铺；跨商圈店铺不能保存为该商圈默认店铺。
2. OpenAPI AdaPay 创建请求可携带商圈代码并解析到正确默认店铺；缺少或无效配置时不会创建可扣款支付单。
3. AdaPay 支付成功后，生成计费基数等于支付请求金额的应收应付事实，优惠和平台补贴均为零，并使用当时有效模板及收款人快照。
4. 使用 `clientOrderNo` 可在客户端自身权限范围内主动触发 AdaPay 结算；其他客户端不能结算或探测该订单。
5. 主动结算成功后，日终任务重跑不会生成重复分账；日终任务成功后，重复主动请求返回已有结果。
6. OpenAPI AdaPay 待结算事实由现有 00:05 自动结算任务处理。
7. OpenAPI AdaPay 支付及成功分账可在现有 AdaPay 日终对账结果中正确匹配；不依赖商城订单表。
8. 微信 OpenAPI 支付不触发分账；本 feature 不新增微信账单下载或账单对账。
9. 租户隔离、客户端隔离、历史财务快照和现有商城订单支付行为保持正确。
10. 退款处理中不会触发分账；退款成功的待结算记录不会被日终或主动结算执行；分账处理中/成功的支付不能退款。

## Assumptions

- 每个商圈只需要一个 OpenAPI 默认店铺；一个店铺归属一个商圈。
- 商圈代码在当前租户内唯一，第三方仍通过当前 OAuth2 token 的租户上下文隔离。
- 系统现有每日 00:05 的 AdaPay 分账任务和 02:00 的 AdaPay 日终对账任务继续启用；本 feature 只扩展其 OpenAPI 数据覆盖。
- OpenAPI AdaPay 使用现有计费模板、分账收款人及 AdaPay 渠道账户；不新增 OpenAPI 专属结算规则。
- 默认店铺所用计费模板必须能在无商城订单属性的情况下按支付金额计算；引用订单属性的规则对 OpenAPI 不适用，支付创建前应明确拒绝或阻止该配置生效。
- OpenAPI AdaPay 退款继续为全额原路退款；分账回退能力不在本 feature 内。
