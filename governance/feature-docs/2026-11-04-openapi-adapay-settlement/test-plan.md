# E2E 与 API 测试计划

## 环境前置

- 本地或 dev 环境，启用 AdaPay 沙箱/模拟服务；不得使用生产密钥、生产租户或真实客户支付。
- 测试租户包含一个启用商圈、同商圈 OpenAPI 默认店铺、仅按金额计算的有效模板及有效分账收款人。
- 测试 OAuth2 client 已授权 `payment` scope；另准备无此 scope 和不同 client 的令牌。

## 场景

1. Admin 配置默认店铺：同商圈启用店铺可保存；跨商圈或停用店铺被拒绝；编辑回显正确。
2. OpenAPI AdaPay 支付创建：按商圈代码解析默认店铺；金额全额计费；不存在商圈/默认店铺、属性型模板或收款人无效时拒绝创建。
3. 支付成功回调：重复回调仍只生成一份应收应付事实；快照保留店铺、模板和收款人版本。
4. 主动结算：创建该订单的 client 可触发；其他 client 无法查询或结算；未支付/微信/退款中的记录拒绝；重复请求不重复分账。
5. 自动结算：待处理 OpenAPI AdaPay 事实进入每日 Job 查询；主动结算成功的记录不会再次执行。
6. 退款互斥：退款处理中阻止主动和自动结算；退款成功后不再结算；退款失败后恢复资格；分账处理中/成功时退款被拒绝；并发退款和分账最多一个外部动作可发出。
7. 日终 AdaPay 对账：OpenAPI 成功支付进入 PAYMENT 对账；OpenAPI 成功分账进入 PROFIT_SHARING 对账；账单匹配/仅本地/仅账单/金额差异均按现有规则展示。

## 断言

- 所有金额严格到分；OpenAPI 订单无需对应商城订单行。
- 每个测试至少断言租户、client、paymentId 和 AdaPay payment_id 关联不串户。
- 测试结束清理本次创建的模拟支付、商圈关联、应收应付和分账测试数据。
