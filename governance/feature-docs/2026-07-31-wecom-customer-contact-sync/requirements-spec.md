# 企业微信客户联系人同步

## Scope

### In

- 租户管理员复用已有企业微信配置，手动同步该配置当前授权范围内的客户联系人。
- 同步联系人基本信息、企业微信外部联系人 ID、UnionID（可为空）及其跟进员工关系。
- 使用 UnionID 匹配现有会员；匹配成功时展示对应会员，未匹配联系人仍保留为企业微信联系人。
- 支持联系人分页查询、按企业微信配置、联系人名称、外部联系人 ID、UnionID 和会员匹配状态筛选。
- 重复同步同一企业微信配置时，已有联系人更新，不产生重复记录；同一联系人被多个员工跟进时保留全部关系。
- 同步完成后返回新增、更新、匹配、未匹配和失败数量。

### Out

- 不自动创建会员、不修改会员手机号、OpenID 或已有 UnionID。
- 不实现企业微信客户标签、客户画像、欢迎语和其他客户运营动作；本次增量仅支持单联系人文本群发任务。
- 不实现企业微信实时事件回调；本期只提供管理后台手动同步。
- 不修改小程序、公众号和企业微信客户端行为。

### Deferred

- 客户新增、删除、变更事件驱动同步。
- 定时增量同步、同步任务进度和失败重试队列。
- 联系人与订单、优惠券、门店或营销活动的业务关联。

## Use Cases

### UC-1 同步客户联系人

租户管理员在企业微信配置列表点击“同步客户联系人”。系统读取该配置可见范围内的联系人及详情，完成新增或更新，并返回同步汇总结果。外部接口失败时显示可理解的失败原因，不清空已有联系人数据。

### UC-2 识别已有会员

联系人详情包含 UnionID 时，系统使用 UnionID 查询当前租户会员。唯一匹配时显示会员编号、昵称和手机号脱敏信息；没有匹配或 UnionID 为空时显示“未关联”。

### UC-3 查询联系人

租户管理员进入客户联系人页面，可按配置、名称、外部联系人 ID、UnionID 和关联状态分页查询，并查看联系人基本信息、跟进员工、最近同步时间和会员关联结果。

### UC-4 发送联系人消息

租户管理员在联系人详情中选择该联系人已同步的跟进成员，输入文本并创建企业微信群发任务。任务创建成功后，由跟进成员在企业微信客户端确认发送。

## Business Rules

- 企业微信联系人以“当前租户 + 企业微信配置 + externalUserId”作为业务身份；不同企业微信配置中的相同 externalUserId 不视为同一联系人。
- UnionID 仅作为跨微信生态匹配依据；只有非空且唯一匹配当前租户会员时才建立关联。
- 联系人同步不得覆盖会员已有的 UnionID、手机号、OpenID 或其他登录身份字段。
- 同一联系人被多个企业微信员工跟进时，系统必须保留全部跟进关系，不得因重复同步丢失已有关系。
- 联系人详情未返回 UnionID 时，联系人仍需保存并标记为未关联，不得用手机号或昵称推断会员身份。
- 同步以新增或更新联系人为主；本次接口未返回的历史联系人不立即物理删除，保留历史记录并标识为非当前可见或待核验。
- 同步失败时保留已有联系人数据；局部联系人失败不影响其他成功结果，并在汇总中计数。
- 企业微信配置、联系人和会员关联查询均按当前租户隔离，不允许跨租户读取或匹配。
- 企业微信 Secret、access token 和外部接口原始敏感凭证不得返回管理端。
- 发送消息只能使用当前联系人已同步的跟进成员，发送目标使用 `externalUserId`，不使用 `unionId`。
- 发送接口成功只代表企业微信已创建群发任务；企业微信返回失败联系人时，本次请求不得提示发送成功。

## Frontend Requirements

- 在现有企业微信管理下增加“客户联系人”页面，并复用已有配置选择、权限和分页模式。
- 企业微信配置列表提供“同步客户联系人”操作；同步期间按钮禁用，完成后刷新最近同步时间并展示新增、更新、匹配、未匹配和失败数量。
- 联系人列表展示名称、头像、外部联系人 ID、UnionID 脱敏值、跟进员工、会员关联状态和最近同步时间。
- 联系人详情展示会员关联结果及未关联原因；手机号只展示脱敏值。
- 联系人详情提供“发送消息”入口，展示可选跟进成员、文本输入框和企业微信确认发送提示。
- 页面提供配置、联系人名称、外部联系人 ID、UnionID 和关联状态筛选，并支持空数据、加载中、部分失败和无权限提示。
- 不在前端保存或展示企业微信 Secret 和 access token。

## Edge Cases

- 企业微信配置无客户联系权限、凭证失效或微信开发者账号未正确绑定，导致无法返回 UnionID。
- 联系人列表或详情接口分页，联系人数量较大或单次同步超过后台请求时限。
- 同一联系人由多个员工跟进，或联系人在多个企业微信配置中出现。
- 联系人类型为企业微信用户、普通微信用户或其他类型，返回字段不完整。
- UnionID 为空、无法匹配会员、匹配到多个会员或联系人已被企业微信侧删除。
- 同一配置被并发点击同步，或同步期间部分详情接口超时。
- 租户管理员使用其他租户的配置编号或联系人编号查询、同步或查看关联会员。
- 联系人没有跟进成员、跟进成员不属于该联系人或消息内容为空时，禁止发送。

## Acceptance Criteria

- 管理员使用有效企业微信配置同步后，能够分页获取当前授权范围内的客户联系人，并保存联系人基本信息及跟进员工关系。
- 联系人详情返回 UnionID 时，系统能够与当前租户中 UnionID 相同的会员建立唯一关联；UnionID 为空或无匹配时不误关联。
- 同一配置重复同步不会产生重复联系人；多员工跟进关系不会被覆盖或丢失。
- 同步结果能区分新增、更新、已匹配、未匹配和失败数量；局部失败不会清空已有数据。
- 联系人列表支持配置、名称、外部联系人 ID、UnionID 和关联状态筛选及分页查看。
- 系统不会因联系人同步修改会员既有登录身份字段，也不会自动创建会员。
- 管理员能够从联系人详情创建文本群发任务，且任务只绑定当前联系人和其跟进成员。
- 不同租户之间无法通过接口或管理页面读取联系人、会员匹配结果或企业微信配置。
- Secret、access token 和会员手机号不会以明文出现在管理端响应或页面中。
- 后端目标模块编译/测试通过，管理端类型检查和目标构建通过；结果记录在 `test-notes.md`。

## Assumptions

- 本期复用 `mp_wecom_account` 中已有企业微信配置，不新增第二套 CorpID/Secret 配置入口。
- 企业微信侧已配置客户联系权限；要获取与小程序一致的 UnionID，企业微信绑定的微信开发者账号与小程序属于同一主体。
- 本期以手动全量同步作为可验收行为；实时回调和定时同步在后续需求中处理。
- 未匹配联系人只保存企业微信侧数据，不自动创建会员；后续如需人工绑定，另行定义绑定权限和审计规则。
- 本期消息仅支持文本，单次不超过 2000 个字符；不新增消息历史表。
