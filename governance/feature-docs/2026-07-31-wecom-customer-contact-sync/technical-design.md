# 技术设计

## 模块影响

- `backend/yshop-module-mp`：新增客户联系人领域对象、联系人查询/同步管理端接口、企业微信联系人 API 调用和会员 UnionID 匹配。
- `backend/sql`：新增联系人快照、跟进员工关系和菜单/权限的幂等升级脚本。
- `admin`：在现有企业微信管理下新增客户联系人列表、详情抽屉和同步入口。
- 不影响 `miniapp`、`icepolar-dms`、既有会员登录流程和客户群同步接口；消息发送复用现有企业微信配置，不新增表。

## 关键决策

1. **联系人与会员分离建模**：企业微信联系人是外部系统快照，不把 `external_userid` 写入 `yshop_user`，避免改变会员登录身份和跨企业 ID 语义。
2. **跟进关系独立保存**：一个联系人可能由多个员工跟进，使用独立关系记录保证重复同步不会覆盖其他员工关系。
3. **UnionID 只读匹配**：以联系人详情返回的 UnionID 查询当前租户会员；只记录匹配结果，不反向修改会员 UnionID，也不使用昵称/手机号兜底匹配。
4. **手动全量同步**：复用客户群同步的同步按钮、租户校验、锁和汇总响应模式；本期不引入 MQ、定时任务或事件回调。
5. **局部容错**：联系人详情逐条失败时保留旧快照并继续其他联系人；列表阶段失败则结束本次同步，避免形成不完整的“全量成功”假象。
6. **敏感字段最小暴露**：UnionID 管理端只返回脱敏值；会员手机号只返回脱敏值；企业微信扩展属性只作为受控详情数据展示。
7. **消息发送边界**：发送入口只接收联系人 ID、其跟进成员 UserID 和文本；服务端重新校验跟进关系后调用企业微信客户群发接口，返回任务 ID，不伪装成已送达。

## 必要流程

```text
后台选择企业微信配置并点击同步
  -> 校验当前租户与同步锁
  -> 获取 access_token
  -> 获取可见的客户联系员工
  -> 分页获取各员工 external_userid 并去重
  -> 获取每个联系人详情，读取 unionid 和 follow_user
  -> upsert 联系人快照与跟进关系
  -> 按 tenant_id + union_id 查询会员并更新匹配状态
  -> 返回新增/更新/匹配/未匹配/失败汇总
```

```text
联系人详情发送消息
  -> 校验当前租户联系人和已同步跟进成员
  -> 使用联系人 external_userid、跟进成员 userid 创建企业微信群发文本任务
  -> 返回企业微信 msgid，提示跟进成员在客户端确认发送
```

同步当前可见结果时，只新增或更新本次返回的数据；不可见或接口未返回的历史联系人不物理删除，避免一次权限变化造成数据丢失。跟进关系只对本次明确返回的员工做 upsert，不删除应用不可见的历史关系。

## 查询与匹配

- 联系人分页查询只返回当前租户数据，默认按最近同步时间倒序。
- `MATCHED` 联系人展示 `member_id` 对应的会员摘要；`UNMATCHED` 和 `AMBIGUOUS` 只展示状态和原因。
- 同一 UnionID 在当前租户存在多个会员时不自动选择，标记为 `AMBIGUOUS`，避免错绑。
- 会员被删除或失效时，联系人快照保留；查询时会员摘要按当前状态展示。

## 复用与依赖

- 复用现有 `WecomAccountDO`、Secret 加密、access token 获取、HTTP 错误转换、租户拦截器和 Redisson 同步锁。
- 复用客户群页面的企业微信配置筛选、权限菜单、分页组件和同步结果提示模式。
- 不新增 Maven、npm 或外部服务依赖；不跨模块新增业务依赖。

## 迁移与回滚

- 使用 `upgrade-2026-07-31-wecom-customer-contact-sync.sql`，脚本可重复执行并包含标准租户、逻辑删除字段和业务索引。
- 回滚只删除本功能新建的数据表和菜单权限，不触碰 `mp_wecom_account`、`mp_wecom_customer_group` 或 `yshop_user`。

## 风险

- 客户数量乘以详情请求可能导致同步耗时较长；通过分页、请求超时、并发锁和失败汇总控制影响，后续规模上升再演进异步任务。
- UnionID 返回依赖企业微信后台绑定和主体一致性；缺失时仍能完成联系人同步，但不能完成会员匹配。
- 企业微信接口只返回当前应用可见的跟进关系，不能将“未返回”直接解释为客户已解除关系。
- 当前 `external_userid` 受企业微信配置/调用方影响，不能跨配置直接合并联系人；跨配置统一只能依赖 UnionID。
- 企业微信客户群发接口创建的是待成员确认的发送任务，不保证调用成功后客户立即收到消息；失败联系人由接口返回的 `fail_list` 判断。
