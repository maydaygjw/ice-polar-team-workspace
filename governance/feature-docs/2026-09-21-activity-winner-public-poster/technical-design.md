# 活动中奖公示长图技术设计

## 模块影响

- `backend` 活动模块新增管理端公示数据接口和用户端中奖名单接口。
- `admin` 活动中奖管理页新增海报预览和 PNG 下载能力。
- `h5` 活动页中奖名单区域改为加载用户端真实接口。
- 不新增数据库表、字段、MQ、外部系统或运行时依赖。

## 关键决策与权衡

1. 后端返回已排序且最多 100 条的公示数据，保证租户隔离、历史快照和截断规则不会被前端绕过。
2. 管理端使用 Canvas 生成单张动态高度长图，复用现有海报 Canvas 实现，不引入服务端图片合成依赖。
3. 公示接口只返回脱敏展示名，不返回兑奖码和内部用户标识，降低误导出敏感信息的风险。
4. 无数据库迁移；历史活动使用已有期次快照和中奖记录，不改变业务数据。
5. 用户端复用同一套排序、脱敏和最多 100 条规则，但使用独立响应 DTO，仅返回公示所需字段。

## 必要流程

中奖管理页按当前 `periodId` 请求公示数据；活动 H5 按当前期次请求中奖名单。后端查询有效中奖记录、期次快照、期次奖品和会员展示信息，排序后截取前 100 条并返回 `truncated`；后端只输出脱敏 `displayName`。管理端按奖品分组绘制动态高度长图，H5 展示列表并提示截断状态。

## 风险

- 远程图片加载可能受跨域策略影响；前端对背景和奖品图片加载失败使用占位样式，不阻断整张海报生成。
- 租户会员资料可能缺少可展示字段；后端必须提供稳定的脱敏兜底文本。
