# 需求规格：应收应付批量结算

## Scope

### In

- 应收应付管理列表支持勾选多条可结算记录并一次发起结算。
- 批量操作逐条复用现有结算规则，返回本次批量操作的成功数、失败数和逐条结果。
- 失败记录不影响同批次其他记录继续处理；处理完成后刷新列表。

### Out

- 不改变 AdaPay 按订单分账的业务语义，不合并多个订单为一个外部分账请求。
- 不提供跨页选择、按筛选条件全量结算或异步任务编排。

## Use Cases

财务人员在应收应付列表中勾选多条可结算记录，确认批量结算；系统逐条执行并展示结果。

## Business Rules

1. 批量请求最多包含 100 条应收应付主记录 ID，服务端按当前登录租户校验。
2. 只有计算成功、Adapay 支付、未退款且没有已成功/处理中/已回退分账记录的记录可执行。
3. 单条记录执行失败时继续处理同批次其他记录；已成功或幂等完成的记录计入成功数。
4. 重复 ID 只处理一次；空 ID 列表被拒绝。

## Frontend Requirements

- 列表增加仅允许选择可结算记录的选择框。
- 选择一条或多条记录后显示“批量结算”按钮；未选择时禁用。
- 操作前二次确认，完成后显示成功/失败汇总并刷新列表。
- 单条结算按钮与批量按钮共用结算权限和可结算状态。

## Edge Cases

- 选中后记录状态被其他操作改变：服务端重新校验并将该项返回失败，不影响其他项。
- 跨租户或不存在的 ID：该项返回失败，不泄露其他租户数据。
- 外部接口异常：该项返回失败，其他项继续执行。

## Acceptance Criteria

- [ ] 可结算记录可被多选，非可结算记录不能被选中。
- [ ] 批量结算最多提交 100 个 ID，空列表不能提交。
- [ ] 批次内成功、失败记录均有逐条结果，失败不阻断其他记录。
- [ ] 重复点击和重复 ID 不会重复创建或执行已完成的分账。
- [ ] 当前租户隔离、结算权限和现有退款/支付校验继续生效。

## Assumptions

- 批量结算为当前列表页选择模式；分页切换不会保留跨页选择。
