# 技术设计 — AdaPay 对账单管理

## 模块影响

| 模块 | 变更 | 说明 |
|---|---|---|
| `yshop-module-pay-biz` | 修改 | 新增对账单下载任务、ZIP 归档、三类 CSV 解析入库和查询接口 |
| `admin/` | 修改 | 新增“对账单管理”页面、API client、日历、明细页签和 ZIP 版本列表 |
| `yshop-module-pay-biz/pom.xml` | 修改 | 增加 `yshop-module-infra-api` 依赖，通过 `FileApi` 使用主 OSS |
| 数据库 | 新增 | 一张下载记录表和三张原始明细节表 |
| 外部系统 | 复用 | 继续使用 `holuntech pay-java-adapay 2.14.14-SNAPSHOT` 的标准账单下载接口 |

## 关键决策

1. **独立原始账单能力**：新能力放在 `pay-biz` 的 `adapaybill` 包内，不复用日终对账明细表。对账表保存业务匹配结果，本功能保存原始账单字段；两者生命周期和语义不同。
2. **只归档 ZIP**：AdaPay 下载内容在内存中解压并解析，三类 CSV 不单独上传 OSS。每次成功下载生成一个不可变 ZIP 版本；解析明细只保留最新成功版本。
3. **异步下载任务**：创建接口只持久化任务并立即返回任务 ID，由现有 `@Async + TenantUtils` 模式执行。这样远端下载和解压不会长期占用管理端 HTTP 请求，也便于页面展示“下载中”。
4. **任务与版本共用一张下载记录表**：每次发起下载产生一条记录和 `attempt_no`；成功记录即一个 ZIP 版本，失败记录保留状态和错误信息。公开展示的历史版本只筛选成功记录。
5. **同日单活动任务**：下载记录使用可空的 `active_key = tenantId:billDate` 唯一约束。任务开始时写入，终态时清空，数据库层保证同一租户同一日期只有一个活动任务。
6. **明细原子替换**：ZIP 上传 OSS 并解析成功后，在一个数据库事务中物理删除该租户、该日期三类旧明细并批量插入新明细，同时更新任务为成功。任一步失败则事务回滚，旧明细继续可查询。
7. **原始字段以字符串保存**：这些明细是账单原文展示数据，不是财务事实，金额、日期、状态均不转换成业务类型，避免 `14.90` 被序列化成 `14.9` 等展示变化。
8. **固定列 + 扩展列**：三类 CSV 的已知表头映射为固定字段；AdaPay 未来追加的尾部列按原顺序存入 `extra_fields`，原始整行保存到 `raw_line`，满足原文审计。
9. **不做 AppId 过滤**：标准账单 ZIP 属于当前租户支付配置下载结果，解析和入库保留返回的全部数据行，不按 `app_id`、交易状态或业务规则过滤。
10. **CSV 解析使用现有 Hutool 能力**：使用项目已有的 `CsvUtil` 读取 UTF-8 CSV，支持引号转义；不新增 CSV 依赖。首条非 `#` 行必须是表头，后续 `#` 汇总和导出行忽略。
11. **文件读取经 infra-api**：通过 `FileApi.createFile` 保存 ZIP、通过 `FileApi.getFileContentByUrl` 下载 ZIP，不直接依赖 OSS SDK，也不向前端暴露 OSS 内部地址。
12. **本期不重构日终对账下载代码**：现有 `reconciliation` 包中的下载、解压实现继续服务原模块；新包实现相同协议，避免本功能混入对账行为重构。若后续出现第三种账单消费者，再提取共享的 AdaPay 账单文件支持组件。

## 处理流程

```text
POST 创建下载
  ├─ 校验历史日期、当前租户
  ├─ 回收超过 30 分钟的活动任务并标记失败
  ├─ 计算 attempt_no，写入 active_key，插入 RUNNING 任务
  └─ 异步执行并返回 taskId

异步执行
  ├─ 读取当前租户 AdaPay 配置并调用 downloadBill(STANDARD)
  ├─ 校验 ZIP，提取 Charge_ / PaymentConfirm_ / Div_
  ├─ 解析表头、数据行、原始行号和扩展列
  ├─ 保存 ZIP 到主 OSS，计算 SHA-256 和文件大小
  ├─ 短事务：将 ZIP 文件名、URL、大小和摘要写入下载记录
  ├─ 单事务：删除该日三类旧明细 → 批量插入新明细 → 任务标记成功
  └─ 任何异常：任务标记失败、清空 active_key；明细替换事务回滚
```

ZIP 保存先于数据库替换。OSS 上传后立即用短事务记录 ZIP 元数据；若随后的明细替换事务失败，失败任务仍保留 `zip_file_url`，避免形成无归属文件；该文件不出现在成功版本列表。

## CSV 结构处理

三类文件都按以下规则处理：

- 文件必须以 `Charge_`、`PaymentConfirm_`、`Div_` 文件名前缀命中，三个文件缺一不可。
- 第一条非 `#` 行作为表头；必需表头缺失或重复时整个任务失败。
- `#` 开头的说明、合计和导出时间行不写入明细。
- 数据行少于必需字段数时整个任务失败；多余字段按顺序写入 `extra_fields`。
- `row_no` 保存 CSV 文件中的原始物理行号，包含注释行。
- Charge 固定保存 18 列，Confirm 固定保存 8 列，Div 固定保存 11 列；字段映射见 `contract-changes.md`。

## 本地商家关联与查询筛选

- Charge 查询支持按账单支付ID、商户订单号精确筛选；PaymentConfirm 支持按商户支付ID筛选；Div 支持按商户支付ID、MemberId筛选。筛选条件由服务端执行并参与总数统计和分页。
- 门店信息（`shop_id`、`shop_name`）作为冗余快照落在三类明细表，由迁移 `V2026111103__adapay_bill_detail_shop_snapshot.sql` 追加：导入解析后，Charge 以账单支付ID批量匹配订单 `transactionId` 取得门店快照；PaymentConfirm、Div 以商户支付ID关联同版本 Charge 继承门店信息；未匹配则留空。
- 填充只发生在导入落库时，分页查询直接读取冗余字段，不实时关联订单表；关联不过滤或改写账单原始行。订单查询保持租户隔离，异步任务在 `TenantUtils` 租户上下文内执行。

## 查询与替换规则

- 页面按 `billDate` 查询时，服务端先查该日期最新成功任务，再按 `tenant_id + bill_date` 查询对应三类明细；不依赖前端传下载 ID。
- Div 明细的 MemberId 条件直接映射到 `member_id` 字符串字段，使用等值条件；其余筛选字段见“本地商家关联与查询筛选”。
- 明细表无逻辑删除，成功重拉时按租户和日期物理删除旧行。删除只发生在同日期 ZIP 已完整解析并上传之后。
- 日历状态优先级为 `RUNNING` > `SUCCEEDED` > `FAILED` > `NONE`。同一日期曾成功、当前又正在重拉时展示 `RUNNING`。

## 数据库迁移与回滚

- 新增 Flyway migration：`V2026111102__adapay_bill_management.sql`（下载记录、三类明细、菜单权限）与 `V2026111103__adapay_bill_detail_shop_snapshot.sql`（三类明细冗余 `shop_id`、`shop_name`）。版本号不与现有迁移冲突。
- 迁移创建一张下载记录表、Charge/Confirm/Div 三张明细表、日期查询索引和 Div MemberId 查询索引，并初始化“对账单管理”菜单及查询、下载按钮。
- 菜单挂在现有“日终对账记录”同级；迁移通过现有对账菜单动态解析父级，兼容不同环境的菜单 ID。
- 回滚时移除页面与权限数据并删除四张新表（含 V2026111103 追加列）。四张表均为新增表且没有旧业务外键，删除不影响订单、支付、分账和现有对账数据。

## 风险与权衡

| 风险 | 处理 |
|---|---|
| 下载进程异常导致任务停留在 RUNNING | 创建新任务时回收超过 30 分钟的活动任务并标记失败；Redis 不作为唯一并发依据 |
| OSS 上传成功但数据库替换失败 | 已上传 ZIP 先落短事务元数据；明细事务回滚，失败任务保留 OSS 地址供追踪；成功版本列表只展示事务成功的任务 |
| AdaPay 追加 CSV 尾部列 | 固定字段外的列进入有序 `extra_fields`，原始 ZIP 保证完整原文 |
| AdaPay 修改必需表头 | 解析显式失败并保留旧明细，不把无法识别的数据写入页面 |
| 原始金额以字符串保存不便统计 | 本版本明确不做统计和业务对账；后续如需要应另建结构化财务投影，不回改原始明细语义 |
| 连续重拉产生多个 ZIP | 成功版本只追加不删除；解析明细只关联最新成功任务 |

## 验证要求

- 单测覆盖 ZIP 缺文件、表头缺失、注释行、尾部空列、0 行 CSV、Div MemberId 精确匹配和重拉替换。
- 集成测试覆盖同日期并发、失败不删除旧明细、租户隔离、ZIP 内容回读和菜单权限。
- 后端执行 pay-biz 相关测试和构建；管理端执行 `pnpm ts:check` 与目标构建。
- 不允许在测试中调用真实 AdaPay；AdaPay SDK 和 `FileApi` 均使用测试替身。
