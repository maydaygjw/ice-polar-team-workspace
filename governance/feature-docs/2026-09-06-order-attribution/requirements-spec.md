# 需求规格：订单渠道与推荐人记录

## Scope

### In-scope

- 在普通订单创建时接收并记录渠道标识 `channelCode`。
- 在普通订单创建时接收并记录推荐人用户 ID `referrerUserId`。
- 两个字段均为可选字段，未传值时不影响现有下单流程。
- 覆盖 `yshop_store_order` 体系下的所有订单类型，包括自取、外卖、扫码点餐、设备、预约、拼单、加餐及家政服务订单。
- 后端模块通过统一订单 API 创建订单时，完整透传两个字段。
- 推荐人校验当前租户归属，且不得为订单下单用户本人；用户不具备商圈归属概念，不校验商圈。

### Out-of-scope

- 积分订单及其独立订单表。
- 返佣金额计算、返佣规则、返佣结算和提现。
- 用户端订单列表和详情展示、查询和筛选这两个字段；管理端通过独立的订单推广页面查询。
- 修改已有订单的渠道或推荐人归属。

### Deferred

- 渠道编码字典、渠道管理后台和渠道统计报表。
- 多级推荐关系及推荐链路。
- 退款后是否返佣、返佣回退等财务规则。

### 管理端订单推广页面

在“订单管理”下新增“订单推广”页面，用于查看已记录推广信息的普通订单：

- 默认只展示渠道标识或推荐人至少有一个非空的订单。
- 支持按渠道标识、推荐人用户 ID、下单用户 ID、订单号和创建时间筛选。
- 列表展示订单号、渠道标识、推荐人、下单用户、门店、支付金额、支付状态、订单类型和下单时间。
- 页面不展示积分订单，不提供修改订单归因字段的能力。

## Use Cases

### UC-1 用户通过渠道下单

- **角色**：C 端用户或业务调用方
- **目标**：创建订单时记录订单来源渠道。
- **主流程**：调用下单接口并可选传入 `channelCode`；订单创建成功后，渠道标识与订单关联保存。

### UC-2 用户通过推荐关系下单

- **角色**：C 端用户或业务调用方
- **目标**：创建订单时记录推荐人。
- **主流程**：调用下单接口并可选传入 `referrerUserId`；系统校验推荐人归属后创建订单并保存推荐关系。

### UC-3 后端业务模块创建订单

- **角色**：家政、设备等后端业务模块
- **目标**：通过统一订单服务创建订单时保留渠道和推荐人信息。
- **主流程**：业务模块将字段传入统一订单 DTO；订单模块继续透传至订单创建流程并保存。

## Business Rules

- `channelCode` 可为空；传入时按字符串记录，不参与价格、库存、支付或订单状态计算。
- `referrerUserId` 可为空；传入时必须属于当前租户，且不能等于下单用户 ID。
- 推荐人校验失败时订单不得创建，并返回明确的参数校验失败信息。
- 渠道和推荐人信息属于订单创建时的历史归属信息；订单创建后不因普通订单更新而改变。
- 加餐更新已有未支付订单时，沿用原订单归属信息，不覆盖已有渠道或推荐人。
- 积分订单不接收、不保存这两个字段。
- 现有未传字段的客户端必须保持兼容。

## Frontend Requirements

- 现有客户端无需改造即可继续下单。
- 如调用方需要归因，可在下单请求中传入两个可选字段。
- 订单列表和订单详情不展示这两个字段。

## Edge Cases

- 未传两个字段：订单正常创建，字段为空。
- `channelCode` 为空字符串：按未传处理。
- 推荐人不存在或属于其他租户：拒绝创建订单。
- 推荐人等于下单用户：拒绝创建订单。
- 内部业务模块透传字段缺失：按字段为空处理，不影响其他订单创建。
- 历史订单没有归因信息：不回填、不猜测来源或推荐人。

## Acceptance Criteria

- [ ] 不传两个字段时，现有非积分订单创建行为不变。
- [ ] `/app-api/order/create` 可接收可选 `channelCode` 和 `referrerUserId`。
- [ ] 传入有效渠道标识后，订单保存对应值。
- [ ] 传入当前租户且非下单人的推荐人后，订单保存对应用户 ID。
- [ ] 推荐人不满足租户归属或自推荐条件时，下单失败且不产生订单。
- [ ] 自取、外卖、扫码点餐、设备、预约、拼单、加餐和家政服务订单均不丢失字段。
- [ ] 积分订单不受本次变更影响。
- [ ] 订单详情和列表响应不新增这两个字段。
- [ ] 订单创建后的普通更新不会改变两个归因字段。
- [ ] “订单管理 → 订单推广”页面可查询渠道或推荐人非空的普通订单。
- [ ] 页面支持按渠道、推荐人用户、下单用户、订单号和创建时间筛选，且不包含积分订单。

## Assumptions

- 推荐人不需要绑定商圈，推荐关系仅校验用户所属租户及非自推荐条件。
- 下单用户以订单创建流程最终确定的用户 ID 为准，包括后端代用户创建订单的场景。
- 渠道标识暂不建立枚举字典；最大长度按 64 个字符设计。
