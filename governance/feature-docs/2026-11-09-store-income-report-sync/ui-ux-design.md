# UI/UX 设计 — 店铺收入报表独立数据源与打款指标

## 页面结构

- 保留现有「财务管理 → 店铺收入报表」路由、导航、筛选区、汇总表和明细弹窗。
- 筛选区保留日期范围、店铺、查询和重置；在筛选操作区增加「同步数据」按钮。
- 表格保留原字段，在店铺收入列后增加「预测打款收入」「预测打款笔数」「打款金额」；查看明细仍固定在最右操作列。
- 不增加图表或新 Tab。继续使用当前 Element Plus 表单、表格、分页、空状态和 Dialog 组件风格。

## 同步交互

1. 「同步数据」复用当前筛选出的店铺和日期范围，但要求三者均已选择；否则按钮禁用并提供就近说明“请选择店铺和完整日期范围”。
2. 点击后弹出二次确认，显示店铺名称、开始日和结束日，并说明“将按本地业务数据重算并覆盖该店铺所选期间的报表汇总”。
3. 确认后按钮进入 loading/disabled，避免当前页面重复提交；仍允许用户查看其他页面内容，但同步完成前不触发同店铺重复操作。
4. 成功后提示重建的日汇总行数；若管理员响应中有未关联店铺的成功打款流水，提示该数量。同步成功后将当前列表回到第 1 页并重新查询。
5. 失败后显示服务端错误信息，保留页面当前筛选与原列表数据，按钮恢复可用；允许用户修改条件后重新同步。

此 API 同步执行，因此不显示虚构的百分比进度或后台任务状态；请求 loading 表示正在处理，成功提示表示事务已提交。

## 汇总表

| 列 | 展示 |
|---|---|
| 结算日期、店铺、结算订单数 | 沿用现有展示 |
| 订单金额合计、店铺收入合计 | 沿用现有金额格式和强调样式 |
| 预测打款收入 | 金额右对齐，显示两位小数，空值显示 `0.00` |
| 预测打款笔数 | 整数右对齐，无数据显示 `0` |
| 打款金额 | 金额右对齐，显示两位小数；语义为净到账 |
| 操作 | 保留「查看明细」，仅展示原有分账订单明细 |

表格列数增加后保持横向可读：金额和计数列使用适当固定宽度，店铺列可伸缩，操作列固定右侧；中小视口允许表格内部横向滚动，不挤压金额或裁切列名。桌面端优先保持一行表头；必要时允许列标题自然换行。

## 状态与适配

- 列表请求使用表格 loading；无投影数据时显示“暂无数据，可选择店铺和日期范围后同步”。
- 查询失败保留筛选条件并提供重试；同步失败不得清空当前展示。
- 货币金额统一两位小数和右对齐，避免靠颜色单独表达财务数值。
- 所有按钮有可见文本、键盘焦点和禁用/加载状态；确认弹窗初始焦点和关闭行为沿用共享 Dialog 组件。
- 视口宽度在 1024px 以下，筛选项可换行，表格容器横向滚动；不要求移动端重排成新卡片视图。
- 复用项目现有亮色后台主题和 Element Plus 设计 token，不引入新字体、配色或图标风格。

## 设计依据

- `ui-ux-pro-max` 对“financial table filters sync progress”的检索提示：多步骤处理需提供进度反馈，宽表在窄视口需内部横向滚动。
- Vue 栈专属检索在两次尝试后没有匹配结果；组件实现遵循仓库既有 Element Plus 页面的筛选、loading、空状态和弹窗模式。
