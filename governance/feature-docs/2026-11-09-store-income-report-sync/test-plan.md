# 测试计划 — 店铺收入报表独立数据源与打款指标

## 范围

覆盖后端同步事务与租户/店铺权限、独立投影汇总查询、管理端同步交互和端到端数据展示。所有结算流水 fixture 使用本地数据库；E2E 不访问 AdaPay。

## 场景

1. **混合来源合并**：同店铺同日分别准备成功分账、预计打款订单和成功收款人结算流水；校验各金额/笔数按各自日期汇总到同一日行。
2. **日期归属**：设置 T+1、D+1；覆盖普通工作日、周末和连续非工作日，确认预测收入及笔数落入预计日期，而旧分账收入和实际到账分别按 `sharing_time`、`settle_date` 落日。
3. **金额口径**：确认预测/原有收入只累加店铺角色金额；实际打款使用 `net_settle_amount`，排除平台主体、失败/处理中和非活动版本。
4. **去重**：同订单存在多条历史分账记录时预测笔数最多一笔，并遵循订单结算管理的当前有效记录规则。
5. **幂等覆盖**：对同店铺同区间连续同步两次，结果完全一致；修改源数据后再同步，投影更新为新结果。
6. **清除旧数据**：先同步出日行，再移除该范围的全部源事实并重同步；旧日行消失，范围外行保留。
7. **事务失败**：注入批量写入失败，确认旧投影不变且无部分结果。
8. **权限和隔离**：普通用户不能查询/同步未授权店铺；其他租户数据不可见、不可被覆盖；租户管理员可操作本租户店铺。
9. **并发同步**：同店铺并发请求由分布式锁串行化或按冲突错误拒绝；不同店铺可独立执行。
10. **无远端依赖**：汇总、同步和订单明细的应用路径没有 AdaPay 客户端调用。
11. **管理端 E2E**：校验未选择完整范围时按钮禁用；确认弹窗明确覆盖范围；loading、成功、带异常数量提示、失败保留旧数据及重试行为正确。
12. **查询分页**：汇总结果按周期倒序、店铺 ID 升序；分页总数和日期闭区间筛选正确。
13. **周期汇总**：校验日/周/月分组、周一开周、自然月边界、部分周期日期筛选、分组后分页，以及各金额和笔数按日投影加总。
14. **费率与对账图标**：综合费率按周期收入总和除以订单金额总和计算，零分母显示 `—`；打款金额相等/不等和均为零的图标、提示正确。
15. **结算日历标记**：法定假日显示假期名，普通周末显示「周末」，调休补班日和工作日不显示非工作日标签；周/月含休息日时显示周期标签。
16. **聚合行明细和同步**：周/月行打开覆盖整个显示周期的明细；行同步只覆盖该行与日期筛选相交的部分。

## 验收门禁

- 后端 pay-biz 指定模块测试/编译通过；新增 SQL XML 可被 MyBatis 加载。
- 管理端 `pnpm ts:check`、`pnpm build:prod` 通过。
- E2E 完成混合来源、同步覆盖/失败和权限三个主路径；所有 E2E 请求均使用本地服务数据。
