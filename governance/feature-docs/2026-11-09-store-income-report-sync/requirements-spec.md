# 店铺收入报表独立数据源与打款指标

## Scope

### In Scope

1. 重构财务管理中的「店铺收入报表」，报表查询读取本地独立报表数据源；页面查询不得调用 AdaPay 等远端服务。
2. 保留现有结算日期、店铺、交易订单数、交易订单金额、交易订单收入等列和既有统计口径，并增加综合费率。
3. 增加「预测打款收入」「预测打款笔数」「打款金额」「打款金额核对」列。
4. 报表汇总按日期、店铺、收款人拆分行；纳入店铺主收款人和有效对账收款人，无效对账收款人不纳入。管理端展示收款人姓名、银行卡后四位和 MemberId 后四位。
5. 支持按天、周、月汇总查看；周以周一至周日为周期，月按自然月，筛选范围首尾日期包含在统计内。
6. 提供按店铺和期间发起数据同步的操作；同步从现有本地业务表汇总数据，重算并覆盖所选店铺和期间的数据。
7. 保留现有店铺/日期筛选、分页及 Adapay 分账订单明细查看能力；新增打款金额只作为店铺日汇总，不与订单建立虚假关联。
8. 保持租户隔离及当前管理端店铺数据权限。

### Out of Scope

- 页面实时查询或同步时调用 AdaPay。
- 修改订单、分账、收款人结算事实的业务状态或金额。
- 将实际打款流水分摊到订单，或把平台级收款人/平台商户流水分摊到店铺。
- 自动定时同步、导出、退款冲销及手工调整报表金额。

## Income Definitions

报表按「店铺 + 日期 + 收款人」形成汇总行。订单及预测指标为店铺级，只放在主收款人行，避免多收款人重复累计；实际打款金额为收款人级。按金额核对在主收款人行使用全部纳入收款人的到账总额。各项分别按其自身业务日期聚合。

| 字段 | 业务口径 | 归属日期 |
|---|---|---|
| 现有结算订单数、订单金额、店铺收入 | 沿用现有口径：Adapay 成功分账记录及店铺角色（`role=2`）明细，店铺收入取本地分账明细固化金额；订单金额取关联订单实付金额 | 分账时间 `sharing_time` 的自然日 |
| 预测打款收入 | 订单结算管理中该店铺预计打款日期为当日的成功结算订单，其店铺角色收入之和 | 按现有结算模式根据实际分账日期计算出的预计打款日期 |
| 预测打款笔数 | 对应「预测打款收入」所包含的有效店铺结算订单数；同一订单最多计一笔 | 同预测打款收入 |
| 打款金额 | 分账收款人结算本地明细中，该收款人当日成功到账净额；无效对账关系不纳入 | 本地结算明细的 `settle_date` |

金额按分币精度汇总。打款金额采用成功明细的净到账金额（结算金额扣除手续费），与「实际到账收入」语义一致；不成功或非活动版本的数据不计入。预测收入只计入订单结算管理中有有效成功分账、且有店铺角色金额的订单；预测日期规则与订单结算管理一致。

日期按系统统一业务时区解释为自然日。期间筛选两端均包含。

## Use Cases

### UC-1：财务查看店铺日收入

1. 用户进入「财务管理 → 店铺收入报表」。
2. 系统从独立的本地报表数据源分页读取数据，不实时查询外部支付平台或重算其他业务表。
3. 用户按店铺和日期期间筛选，查看原有指标及三项新增指标。
4. 用户可沿用现有入口查看 Adapay 分账订单明细；实际打款金额只在日汇总展示，不伪造订单明细关联。

### UC-2：按店铺和期间同步报表数据

1. 有权限的用户选择一个店铺和同步期间，发起同步。
2. 系统读取该租户本地订单/分账表和本地收款人结算明细，重算目标店铺、期间内的日汇总。
3. 同步完成后，目标范围内的报表数据以本次重算结果为准；无来源数据的日期旧汇总也应被清除，避免保留过期金额。
4. 用户获得成功、失败或执行中的明确反馈；查询期间只读取已落地的本地报表数据。

## Business Rules

1. 报表查询数据源与源业务表隔离：列表查询只访问独立的报表数据集；源业务表只在同步计算时读取。
2. 同步必须限定当前租户、所选店铺及日期期间，不得覆盖范围外数据。
3. 对相同租户、店铺和期间重复同步应幂等，结果等于当前本地源数据的重算值。
4. 同步结果完整写入后才对查询可见；失败时不得留下部分汇总或清空上一版完整结果。
5. 现有 Adapay 收入仅统计成功分账记录的店铺角色明细；待分账、处理中、失败、回退记录不计入。
6. 预测打款收入和笔数必须采用订单结算管理相同的有效订单、成功分账和预计日期规则，不能按订单支付日或创建日推断。
7. 预测打款笔数以订单为计数单位。同一订单重试或存在历史分账记录时最多计一次。
8. 实际打款金额仅统计店铺级收款人、成功且当前活动版本的本地结算明细；按租户、收款人、Member ID 和结算账户匹配店铺当前主绑定和有效对账绑定，不关联订单。
9. 同一结算目标绑定多家店铺时，成功净到账金额完整展示在每一家当前有效绑定店铺的对应收款人行，并标注「(共享)」；不按店铺拆分，跨店汇总会重复，且不计入店铺级金额核对总额。
10. 打款金额使用净到账金额；手续费不重复计入实际收入。平台级收款人和平台商户流水不计入店铺打款金额。
11. 同一店铺同一自然日只呈现一行。任一指标有数据时该日应出现；其他指标没有来源时显示 0。
12. 所有数据按租户隔离，并执行管理端现有店铺数据权限。同步范围超出用户权限时拒绝执行。
13. 现有报表只读属性保持不变；同步是唯一的数据刷新入口，不允许直接编辑汇总金额。

## Frontend Requirements

| 区域 | 要求 |
|---|---|
| 查询筛选 | 店铺、日期期间；查询和重置操作 |
| 数据同步 | 独立的「同步数据」按钮；发起前须选择店铺和期间；展示执行中、成功、失败及错误摘要 |
| 汇总表 | 保留原结算日期、店铺、交易订单数、交易订单金额、交易订单收入、查看明细；新增预测打款收入、预测打款笔数、打款金额及打款金额核对 |
| 查看周期 | 支持按天、周、月切换；周按周一至周日，月按自然月，边界周期按所选日期范围截取 |
| 综合费率 | 按交易订单收入除以交易订单金额计算；交易订单金额为 0 时显示 `—` |
| 金额显示 | 货币金额保留两位小数；无来源金额和笔数显示 0 |
| 日期显示 | 以店铺自然日为行日期；查询期间起止日期均包含 |
| 节假日标记 | 使用汇总响应提供的中国日历非工作日标签；普通周末显示「周末」，法定节假日显示假期名 |
| 明细 | 保留现有 Adapay 分账订单明细；不将无订单关联的打款流水伪装为订单明细 |
| 共享到账 | 同一结算目标关联多家店铺时，每家店铺的收款人行展示完整到账金额和「(共享)」标记；说明该金额跨店重复，不参与单店核对 |
| 状态反馈 | 同步期间需防止重复触发；加载、空数据、同步失败和权限错误均有明确反馈 |

## Edge Cases

- 同一店铺/日期只存在预测金额或实际打款金额时，仍显示该日，并将其他指标显示为 0。
- 所选范围在新源数据中已无记录时，同步需清除该范围过期汇总；范围外数据不变。
- 同步重试或重复触发不得重复累计金额或笔数。
- 同一订单存在多条历史分账记录时，沿用订单结算管理的当前有效记录规则，预测笔数最多计一。
- 收款人结算数据存在重拉版本时，只取活动版本，避免历史版本重复计入。
- 结算明细店铺快照缺失或店铺已无法识别时，不得归入其他店铺；同步状态需暴露异常数量或错误摘要。
- 同步过程中源数据读取或写入失败时，查询继续展示上一版完整数据。
- 用户对目标店铺无数据权限时，不得通过接口直接同步或查询该店铺数据。
- 预测打款日期由当前已配置的结算策略计算；策略发生变化时，后续同步按当前策略重算目标范围。
- 实际打款流水不含订单标识，因此无法展示订单级明细或和订单金额作逐笔核对。

## Acceptance Criteria

- [ ] 页面保留交易订单收入统计口径，并新增综合费率、预测打款收入、预测打款笔数、打款金额和打款金额核对。
- [ ] 支持天、周、月汇总；周从周一开始、月按自然月，首尾周期按筛选日期范围截取，周期聚合后分页。
- [ ] 综合费率为周期交易订单收入总额除以交易订单金额总额；分母为零时显示 `—`。
- [ ] 汇总响应按统一中国日历标记非工作日，调休补班日不标记；周/月周期含休息日时显示标记。
- [ ] 打款金额核对按分比较预测金额和实际金额，图标同时提供可读提示。
- [ ] 预测收入按订单结算管理的预计打款日期、有效成功分账订单及店铺角色金额汇总。
- [ ] 预测打款笔数与预测收入使用相同记录范围，按订单去重。
- [ ] 打款金额按店铺和本地结算日期汇总成功活动版本的店铺级净到账金额，不关联订单。
- [ ] 同一店铺和自然日合并显示，日期按各指标各自的业务日期确定。
- [ ] 页面列表请求仅读取独立本地报表数据源，不访问 AdaPay 或其他远端服务。
- [ ] 同步操作必须按店铺和期间执行，并只读取本地业务表。
- [ ] 重复同步结果幂等；成功时完整覆盖所选范围，无源数据时清除范围内旧汇总。
- [ ] 同步失败不会破坏此前完整报表结果，并能向用户显示失败信息。
- [ ] 同步范围外数据保持不变；租户隔离和店铺数据权限对查询及同步均生效。
- [ ] 日期期间起止日均包含，金额按两位小数展示；缺少某项数据时显示 0。
- [ ] 打款金额不生成订单关联或订单级打款明细。

## Assumptions

1. 预测收入沿用订单结算管理所用的成功分账店铺角色收入，不使用订单实付金额推算收入。
2. 「打款金额」按成功收款人结算明细的净到账金额理解；如财务需要展示扣费前结算金额，需在后续设计阶段调整口径。
3. 本地收款人结算明细已由既有采集流程保存；本功能的同步只在这些本地数据上重算，不触发外部拉取。
4. 「期间」指开始日和结束日均包含的自然日范围；前端同步操作需要一个目标店铺。
5. 本阶段仅冻结业务需求；独立数据集的表结构、同步事务/并发方案、API/权限及迁移回滚在设计阶段定义。
