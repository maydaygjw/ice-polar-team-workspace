# 企业微信客户管理员与统一内部标签

## Scope

### In

- 新增“客户管理员”管理模块，名称不再使用“客户联系成员”。
- 同步当前企业微信配置下具备客户联系权限的跟进成员，展示客户管理员基础信息。
- 客户管理员支持查看、筛选、单个和批量绑定内部标签。
- 所有管理端可选择企业微信成员的业务输入统一改为下拉选择客户管理员；不得要求管理员手工填写成员 UserID。
- 客户群标签迁移到内部标签体系；客户群和客户管理员共用同一套内部标签库。
- 内部标签按租户级共享，同一租户下的企业微信配置可以使用同一套内部标签。
- 将管理端“客户标签”改为一级菜单“标签管理”，下设“客户标签”和“内部标签”。
- 客户标签继续使用企业微信客户标签库，仅服务客户联系人。
- 客户联系人继续展示企业微信同步的客户标签，不改为内部标签。

### Out

- 不把客户联系人标签并入内部标签库。
- 不使用内部标签替代企业微信客户标签，也不改变客户联系人标签的企业微信绑定来源。
- 不新增小程序或 DMS 功能。
- 不将全部企业通讯录成员默认视为客户管理员；客户管理员范围以企业微信客户联系权限成员为准。
- 部门 ID 不是成员 UserID，本期不纳入客户管理员下拉；如联系我仍支持按部门配置，部门字段保持独立语义。

## Use Cases

- **同步客户管理员**：管理员选择企业微信配置并同步其客户联系权限范围内的成员；重复同步更新已有成员，不产生重复记录。
- **查看客户管理员**：管理员查看成员标识、名称、状态、最近同步时间和内部标签。
- **维护内部标签**：管理员在“标签管理 → 内部标签”中创建、修改、删除租户级内部标签。
- **给客户管理员打标签**：管理员对一个或多个客户管理员绑定或解绑一个或多个内部标签。
- **选择客户管理员**：新增/编辑“联系我”、客户联系人发送、客户群群发和定时推送中的成员字段均从客户管理员下拉列表选择；客户联系人发送仅展示该客户实际跟进成员的交集。
- **给客户群打标签**：现有客户群标签迁移后，继续使用内部标签进行客户群标记和群发筛选。
- **维护客户标签**：管理员在“标签管理 → 客户标签”中继续实时维护企业微信客户标签库。

## Business Rules

- 客户管理员底层身份使用企业微信 `userid`；同一租户、同一企业微信配置下 `userid` 唯一。
- 客户管理员同步来源为企业微信客户联系权限范围；同步结果以企业微信当前返回为准。
- 内部标签为本地标签库，按租户级共享，不绑定单一 `accountId`。
- 客户群和客户管理员只能绑定当前租户的内部标签；任何跨租户对象或标签操作必须拒绝。
- 删除内部标签时解除其全部客户群和客户管理员关联；删除前需要二次确认。
- 现有客户群标签迁移时保留标签名称、客户群关联及可追溯的迁移结果；迁移完成后不再维护独立的客户群标签库。
- 如果迁移后存在同名内部标签，按明确的合并规则保留一个标签，并保留全部客户群关联。
- 客户联系人标签仍以企业微信客户标签库为唯一外部来源；客户联系人标签与内部标签即使同名也属于不同标签。
- 客户标签的创建、修改、删除继续调用企业微信接口；企业微信失败时不得显示本地操作成功。
- 所有业务查询和写操作遵守租户隔离、权限校验和现有企业微信配置边界。
- Secret、access token 和企业微信原始敏感响应不得返回管理端或写入普通日志。

## Frontend Requirements

- 企业微信目录下新增“客户管理员”页面。
- 页面提供同步、分页、标签筛选、批量打标签和单个成员标签维护能力。
- 客户管理员提供可复用的下拉选项接口，至少返回 `id`、`userid`、展示名称和当前范围状态。
- 一级菜单显示“标签管理”，其下包含“客户标签”和“内部标签”。
- “客户标签”页面保留企业微信配置选择和实时标签组/标签管理能力。
- “内部标签”页面不要求选择企业微信配置，展示当前租户共享的内部标签。
- 客户群页面原有标签筛选、批量打标和群发筛选改用内部标签，用户可见名称统一为“内部标签”。
- “新增联系我/编辑联系我”的“成员 UserID”改为可搜索、多选下拉；编辑旧数据时必须保留无法再次同步的历史 UserID 展示。
- 客户群群发、定时推送和客户联系人发送均使用客户管理员下拉数据，不允许退回为自由文本输入。
- 页面具备加载中、空数据、无权限、同步失败、企业微信凭证失效和网络异常状态。

## Edge Cases

- 企业微信客户联系 Secret 无效、权限范围为空、接口超时或返回非零错误码。
- 同一 `userid` 在多个同步任务中重复出现，或成员已离开客户联系权限范围。
- 企业微信成员改名、停用或从客户联系权限范围移除。
- 内部标签被多个客户群和客户管理员使用后删除。
- 迁移过程中出现同名客户群标签、空标签、已软删除记录或重复关联。
- 同一租户下多个企业微信配置使用相同内部标签；对象关联不得串到其他租户。
- 客户标签与内部标签同名时，页面必须明确区分来源和适用对象。
- 同步、打标签和群发筛选并发执行时，不得产生重复关联或错误租户数据。

## Acceptance Criteria

- 管理员能够同步并查看当前企业微信配置下的客户管理员。
- 重复同步不会产生重复客户管理员，并能更新成员基础信息和同步时间。
- 管理员能够创建、编辑、删除租户级内部标签。
- 客户管理员和客户群能够使用同一内部标签库进行筛选和打标签。
- 现有客户群标签迁移后，历史标签和客户群关联保持可用。
- 同一租户下不同企业微信配置能够使用同一套内部标签；不同租户完全隔离。
- 客户联系人仍使用企业微信客户标签，且客户标签页面位于“标签管理 → 客户标签”。
- 客户标签和内部标签的创建、修改、删除不会互相影响。
- 无权限、凭证失效、外部接口失败和迁移失败均有明确错误反馈，不显示虚假成功。
- 后端目标模块测试通过，管理端类型检查和目标构建通过，关键跨对象流程完成 E2E 验证。

## Assumptions

- “客户管理员”是管理端业务名称，企业微信 API 和数据字段继续使用 `follow_user`、`userid` 等官方术语。
- 内部标签使用本地统一标签模块；客户标签继续复用现有企业微信客户标签管理能力。
- 客户群标签迁移在正式启用新内部标签关联前完成，并提供失败记录和可重复执行策略。
- 本功能首期只影响 `backend` 和 `admin`。
