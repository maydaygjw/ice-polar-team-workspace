# 打印订单分隔页管理后台 UI/UX 设计

## 1. 页面范围

复用现有管理后台“设备 → 打印任务”页面：

```text
admin/src/views/mall/device/printJob/index.vue
```

不新增页面、路由或前端依赖。

同时复用现有“基础设施 → 租户参数管理”页面提供租户级快捷开关，不新增路由或独立配置页面。

## 1.1 租户开关

- 展示名称：`打印设备分隔页`。
- 参数键：`printer.separator.enabled`。
- 参数值为 `true` 时显示开启，其他情况显示关闭，缺失时默认关闭。
- 首次开启自动创建租户参数；再次切换更新现有参数。
- 辅助说明：只影响之后提交的打印任务，已开始执行的订单不受影响。
- 配置失败时恢复原开关状态并显示请求错误。

## 2. 列表增量

### 新增列

在现有“状态”列后增加：

| 列 | 展示 |
|---|---|
| 打印阶段 | 正文打印、分隔页排队、分隔页打印、分隔页异常、全部完成 |
| 分隔页状态 | 未开始、排队中、打印中、成功、异常 |

数据来源为 `extraParams.separator`。旧订单没有该对象时显示“未启用”，不显示异常。

### 阶段颜色

- 正文打印：`warning`
- 分隔页排队/打印中：`info` 或 `warning`
- 分隔页异常：`danger`
- 全部完成：`success`
- 未启用/未开始：`info`

失败原因继续使用现有 tooltip 展示；分隔页失败原因优先展示分隔页任务返回原因。

## 3. 行操作

### 正常正文任务

保留现有“查询”“取消”“重试”操作。普通“重试”只用于正文任务失败。

### 分隔页异常

当 `separator.stage=SEPARATOR_FAILED` 时：

- 显示“查询分隔页”。
- 显示“重试分隔页”，权限复用 `device:print-job:retry`。
- 隐藏普通“重试”，避免重新打印正文。
- 取消后的分隔页任务仍显示“重试分隔页”，不出现退款提示。

点击“重试分隔页”前弹出确认框：

> 确认只重新打印分隔页？不会重新打印正文。

请求成功提示：

> 分隔页任务已重新提交，实际结果请等待打印状态更新。

## 4. 详情弹窗

在现有详情信息下增加“分隔页信息”区块：

- 分隔页阶段
- 分隔页任务 ID
- 分隔页状态
- 模板版本
- 分隔页失败原因
- 重试次数
- 快照摘要：订单编号、门店、文件名、正文页数、正文份数

不展示：

- `deviceKey`
- ApiKey
- 文件服务内部凭证
- 完整 HTML 内容
- 临时 OSS 对象 key、签名 URL 和过期凭证

“扩展参数”原始 JSON 可继续保留，但分隔页字段应优先以结构化字段展示，减少管理员阅读 JSON 的需要。

## 5. 状态与反馈

- 查询、取消、重试按钮显示行级 loading，防止重复点击。
- 加载、空数据和请求错误沿用现有打印任务页面规范。
- 分隔页失败不弹出“订单已退款”文案；明确提示“正文已打印，分隔页异常”。
- 分隔页重试成功只代表链科受理，不代表物理打印完成。
- 操作失败使用后端返回的具体原因，避免统一显示“操作失败”。

## 6. 响应式与安全

- 继续按管理后台桌面端布局，不新增移动端适配。
- 长订单号、任务 ID 和失败原因使用省略号 + tooltip。
- 分隔页快照中的文件名按普通文本展示，不当作 HTML 渲染。
- 不在前端日志、弹窗或请求参数中出现设备凭证。
