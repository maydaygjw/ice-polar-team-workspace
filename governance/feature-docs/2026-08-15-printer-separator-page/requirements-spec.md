# 打印订单分隔页需求规格

## 背景

当前一个打印订单对应一份用户打印文档。连续打印多个订单时，打印机输出的纸张之间没有明确的订单边界，门店需要人工判断每组纸张属于哪个订单。

本功能在每个打印订单的正文文档完成后，自动打印一张只包含订单标识的分隔页，用于区分不同订单的打印文档。

## Scope

### In

- 文件打印订单的正文文档全部打印完成后，自动打印一张分隔页。
- 一个订单无论打印多少份，只打印一张分隔页；分隔页位于该订单所有正文份数之后。
- 第一版分隔页显示以下全部信息：订单编号、门店名称、文件名、正文页数、打印份数。
- 分隔页内容采用模板渲染，字段以带标签的订单信息展示。
- 分隔页信息从下单时冻结的订单快照读取，保证历史打印内容不受后续订单数据修改影响。
- 分隔页作为独立打印任务提交到与正文相同的打印机。
- 正文打印成功后才允许提交分隔页任务；分隔页打印成功后，订单才进入完整的打印完成流程。
- 分隔页任务支持状态跟踪、异常标记和后台重试。
- 租户可在“租户参数管理”中设置是否启用打印设备分隔页；参数缺失时默认关闭。

### Out

- 不改变用户打印页数计价规则。
- 不把分隔页计入用户购买的打印页数、打印份数或订单金额。
- 不修改用户上传的原始文件。
- 不在小程序端新增分隔页编辑、预览或配置入口。
- 不为分隔页单独创建用户业务订单。
- 不要求用户在下单时提交分隔页内容。

### Deferred

- 租户或门店自定义分隔页模板。
- 分隔页展示二维码、条形码或其他机器识别内容。
- 每一份副本后分别打印分隔页。
- 分隔页的独立收费和价格配置。

## Use Cases

### UC1：正文完成后打印分隔页

1. 用户创建打印订单并完成支付。
2. 系统向打印机提交正文打印任务。
3. 正文任务成功完成。
4. 系统读取租户参数；开关关闭时直接完成正文流程，不提交分隔页。
5. 开关开启时，系统使用订单快照生成一页分隔页文档。
6. 系统向同一台打印机提交分隔页任务，打印一份。
7. 分隔页任务成功完成后，订单进入现有打印完成及后续配送流程。

### UC2：分隔页内容扩展

1. 业务需要在订单编号之外增加门店名称或文件名。
2. 系统从订单创建时保存的快照中读取对应字段。
3. 分隔页模板渲染新增字段。
4. 正文打印和订单计价流程保持不变。

### UC3：分隔页打印失败

1. 正文已经成功打印。
2. 分隔页任务提交失败或打印失败。
3. 系统不对正文订单自动退款。
4. 系统记录分隔页失败原因，并将订单标记为“分隔页异常”。
5. 管理人员可以重新提交分隔页任务。

### UC4：重复回调或重复支付通知

- 正文任务和分隔页任务的重复回调不得重复提交分隔页。
- 重复支付通知不得重复提交正文任务或分隔页任务。
- 回调乱序时不得将已完成阶段回退到未完成阶段。

## Business Rules

### 分隔页范围

1. 本功能针对文件打印订单；照片打印订单是否需要分隔页不在本期范围内。
2. 一个订单的所有正文份数完成后只打印一张分隔页。
3. 分隔页始终使用与正文相同的打印设备和订单关联纸张规格。
4. 分隔页打印份数固定为 1。
5. 分隔页不参与商品 SKU、Option、页数、份数和订单金额计算。

### 分隔页内容

1. 当前默认模板显示订单编号、门店名称、文件名、正文页数和打印份数，不显示额外标题或营销内容。
2. 订单编号必须使用系统订单的稳定业务编号，不使用临时任务编号替代。
3. 第一版上述五个字段都必须进入订单创建时冻结的快照并渲染到分隔页。
4. 文本字段缺失时显示“-”，数值字段缺失时显示“0”或“-”；单个展示字段缺失不应阻止打印流程。
5. 分隔页内容不得直接使用未经转义的用户输入，避免内容破坏文档布局或引入脚本。
6. 分隔页必须生成单页文档，不能因为字段增加而意外生成多页。

### 任务顺序与状态

1. 正文任务未成功完成时，不得提交分隔页任务。
2. 正文任务成功后，系统只允许为该订单创建一个有效的分隔页任务。
3. 分隔页任务成功后，订单才视为“正文和分隔页均打印完成”。
4. 分隔页任务失败不改变正文已经打印的事实，不触发正文订单自动退款。
5. 分隔页失败必须保留失败原因和可重试状态。
6. 分隔页重试不得重新打印正文。
7. 已完成的分隔页不得因为重复、延迟或乱序回调重新提交。

### 租户开关

1. 参数键名固定为 `printer.separator.enabled`。
2. 参数值严格为字符串 `true`（忽略大小写）时开启；参数不存在、为空或其他值均视为关闭。
3. 开关在正文打印任务提交时读取并固化到订单快照；订单开始执行后修改租户参数不改变该订单的既定流程。
4. 开关关闭时，文件打印订单仍正常打印正文，但不提交分隔页。

### 历史数据

1. 新增的分隔页信息属于打印订单的私有快照，不改变用户原始文件和订单金额。
2. 历史订单的分隔页内容应以订单创建时的快照为准，不重新读取已变化的商品名称、门店名称或用户信息。
3. 已经完成正文打印但尚未生成分隔页的订单，按照系统可识别的任务阶段执行补充打印；无法安全识别阶段时不得盲目重复打印正文。

## Frontend Requirements

- 本期不新增小程序页面或用户操作。
- 管理后台应能在打印订单或打印任务详情中区分正文任务和分隔页任务。
- 管理后台应展示分隔页状态、失败原因，并提供仅重试分隔页的操作。
- 管理后台重试操作不得触发正文任务重试。

## Edge Cases

- 正文任务成功回调重复到达：只允许生成一个分隔页任务。
- 分隔页任务成功回调重复到达：不重复推进订单完成流程。
- 正文任务失败：不生成分隔页，并沿用现有正文打印失败处理。
- 分隔页文件生成失败：正文不退款，记录分隔页异常并保留重试入口。
- 分隔页任务提交成功但本地保存任务信息失败：不得再次盲目提交，应保留可人工核对的第三方任务信息。
- 分隔页任务提交失败：不重新提交正文，允许后续仅重试分隔页。
- 分隔页打印失败后收到成功回调：按有效的前进状态处理，最终只完成一次。
- 订单编号包含特殊字符：生成文档时必须正确转义，不能改变页面结构。
- 门店名称、文件名缺失或过长：显示“-”或截断展示，但仍保持单页布局。
- 分隔页临时 OSS 文件已过期：根据订单快照重新生成并上传，不重新打印正文。
- 分隔页内容较长：模板必须限制布局，确保内容不溢出且保持单页。
- 设备离线或凭证失效：记录链科返回的失败信息，不触发正文退款。

## Acceptance Criteria

- [ ] 一个订单打印 1 份或多份正文后，均只打印 1 张分隔页。
- [ ] 分隔页位于该订单所有正文份数之后，并使用同一台打印机。
- [ ] 第一版分隔页显示正确的订单编号、门店名称、文件名、正文页数和打印份数。
- [ ] 分隔页为单页文档，订单编号不会被截断、乱码或导致额外分页。
- [ ] 分隔页不增加订单页数、打印份数或订单金额。
- [ ] 正文未成功时不会产生分隔页任务。
- [ ] 正文成功后只会产生一个分隔页任务，重复支付通知和重复回调不会重复打印。
- [ ] 分隔页成功后订单才进入完整的打印完成流程。
- [ ] 分隔页失败不自动退款正文订单，能够记录失败原因并在后台仅重试分隔页。
- [ ] 分隔页重试不会重新打印正文。
- [ ] 分隔页展示字段均来自下单时冻结的快照，后续订单数据变化不影响历史分隔页。
- [ ] 分隔页临时文件过期后可以根据快照重新生成，不重新打印正文。
- [ ] 分隔页生成或提交异常不会造成正文任务状态回退或重复提交。
- [ ] 租户参数缺失或关闭时不提交分隔页；开启后新提交的文件打印订单才产生分隔页任务。

## Assumptions

- “订单编号”指用户业务订单号；设备任务 ID 仅用于任务跟踪，不直接展示在分隔页上。
- 一个订单的所有正文份数由同一个正文任务按照现有 `copies` 参数完成。
- 分隔页使用订单正文所选纸张；颜色固定为黑白，打印份数固定为 1，其他具体打印参数由技术设计阶段根据链科能力确定。
- 分隔页 HTML 使用 OSS 临时文件；链科读取期间 URL 必须有效，文件在任务终态后按保留策略清理。
- 分隔页失败后的后台重试入口沿用现有打印任务管理能力扩展，不新增用户端操作。
- 本期不开放租户或门店自定义模板，模板由系统统一维护。
- 租户分隔页开关通过现有租户参数管理设置，不新增小程序端配置入口。
