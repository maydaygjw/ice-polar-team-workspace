# E2E 测试方案 — 通用设备平台与制冰机迁移

## 范围

覆盖设备核心规范、状态维度、通用设备订单、制冰机迁移、旧接口兼容、DMS/MQTT 转发、租户隔离和幂等。

## 环境前置条件

| 项 | 要求 |
|---|---|
| 后端 | 已部署本功能 backend 分支并启用 device-core/device-ice |
| 数据库 | 已执行设备平台迁移脚本 |
| DMS | 测试环境可访问现有 DMS/MQTT 平台 |
| 测试数据 | 至少两个租户，存在历史 `imei` 设备和新通用设备记录 |
| 权限 | 准备平台管理员、门店管理员和无权限用户 |

## 关键断言

### DEVICE-CORE-E2E-002 状态组合

1. 设备处于在线且空闲时，返回 `ONLINE + IDLE`。
2. 创建设备操作后，返回 `ONLINE + OCCUPIED`，不把占用误判为离线。
3. 设备离线时，连接状态变为 `OFFLINE`，占用状态不被无依据重置。

### DEVICE-CORE-E2E-003 通用设备订单

1. 创建订单并断言记录设备号、类型、操作类型和可选业务关联号。
2. 依次验证 `CREATED → QUEUED → RUNNING → SUCCEEDED`。
3. 验证失败、取消和重复完成请求均保持幂等。

### DEVICE-ICE-E2E-006/007 制冰机回归

1. 通过旧 `/app-api/device/status/{imei}` 查询历史设备，断言响应结构不变。
2. 通过旧 `/app-api/device/command/{imei}/{commandType}` 下发原有命令，断言 DMS 路径和结果映射不变。
3. 验证 DMS 异常不会产生重复设备订单。

### DEVICE-ICE-E2E-010 兼容性

1. 使用迁移前数据调用旧接口。
2. 使用新 core/ice API 查询同一设备和订单。
3. 断言设备、订单和状态只对应一份业务记录。

## 回归与清理

- 每个用例使用独立设备订单，避免状态串扰。
- 保留一组历史数据用于重复迁移和回滚验证。
- 清理新增测试设备和订单，历史迁移样本只在测试租户中使用。
