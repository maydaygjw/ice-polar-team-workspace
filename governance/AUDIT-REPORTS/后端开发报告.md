## 二、P0 级问题（阻塞发布，必须立即修复）

### P0-01：application-dev.yaml 包含大量生产级敏感配置

- **位置**：`backend/yshop-server/src/main/resources/application-dev.yaml`
- **问题**：开发环境配置文件中硬编码了数据库密码、Redis 密码、微信 Secret、钉钉 Secret、DMS 地址等敏感信息
- **代码片段**：
  ```yaml
  password: admin123456          # 数据库密码
  password: redisdev@0803        # Redis 密码
  secret: 2a7b3b20c537e52e74afd395eb85f61f   # 微信公众号 secret
  secret: 6f270509224a7ae1296bbf1c8cb97aed   # 小程序 secret
  client-secret: i8E6iZyDvZj51JIb0tYsYfVQYOks9Cq1lgryEjFRqC79P3iJcrxEwT6Qk2QvLrLI  # 钉钉 OAuth
  tencent-lbs-key: TVDBZ-TDILD-4ON4B-PFDZA-RNLKH-VVF6E  # 腾讯地图密钥
  dms:
    host: https://dms.holuntech.com  # DMS 生产地址
  ```
- **影响**：配置文件若被误用于生产环境，或仓库权限配置不当导致泄露，所有凭证直接暴露
- **修复**：
  1. 所有敏感字段改为 `${ENV_VAR:default}` 占位符格式
  2. 提供 `.env.example` 模板文件
  3. 启动时检测默认值，输出 WARN 日志提醒

### P0-02：订单状态枚举存在三套不一致定义

- **位置**：
  - `yshop-module-order-api/.../OrderStatusEnum.java` — STATUS_0(0,"未支付"), STATUS_2(2,"待收货")
  - `yshop-framework/yshop-common/.../OrderInfoEnum.java` — STATUS_0(0,"默认"), STATUS_2(2,"已收货")
  - `yshop-module-merchant/.../OrderStatusEnum.java` — STATUS_0(0,"待出单"), STATUS_3(3,"待退款")
- **影响**：同一状态值在不同模块语义完全相反，极易导致状态判断错误、订单流程异常
- **修复**：
  1. 统一为一套 `OrderStatusEnum`，定义在 `yshop-common`
  2. 其他模块通过 `@Deprecated` 逐步迁移
  3. 增加状态机校验：定义合法状态转换矩阵

### P0-03：icepolar-dms 硬编码弱密码和密钥

- **位置**：`icepolar-dms/app/config.py`
- **问题**：
  ```python
  DB_PASSWORD: str = "dms_password"
  SECRET_KEY: str = "change_this_to_a_random_secret_key"
  ADMIN_PASSWORD: str = "admin123"
  ```
- **影响**：生产环境若未通过环境变量覆盖，存在严重安全隐患，弱管理密码可被暴力破解
- **修复**：无环境变量时启动失败（fail-fast），增加密码强度校验

### P0-04：大量模块直接引用其他模块的 DAO/Mapper/DO

- **位置**（部分列举）：
  - `order-biz` → `desk.dal.dataobject.ShopDeskDO`、`product.dal.mysql.StoreProductAttrValueMapper`
  - `member-biz` → `store.dal.mysql.StoreShopMapper`、`shop.dal.mysql.RechargeMapper`
  - `merchant-biz` → `order.dal.mysql.StoreOrderMapper`、`product.dal.dataobject.StoreProductDO`
  - `system-biz` → `store.dal.mysql.StoreShopMapper`（基础设施层反向依赖业务层）
- **影响**：模块边界模糊，schema 变更波及面广，无法独立部署
- **修复**：
  1. 建立规范：模块间仅通过 `-api` 模块交互
  2. 优先处理 `system → store`、`message → member` 的引用
  3. CI 中增加架构守卫，禁止 biz 模块 import 其他模块的 dal 包

## 三、P1 级问题（高优先级，限期修复）

### P1-01：@TenantIgnore 在业务代码中使用缺乏文档说明

- **位置**：
  - `UserBillServiceImpl.java:50` — 账单查询
  - `AppStoreOrderServiceImpl.java:797` — 订单查询
- **影响**：后续维护人员难以理解为何需要忽略租户，可能引入安全隐患
- **修复**：为每个 `@TenantIgnore` 添加详细注释，说明忽略原因和场景

### P1-02：CONTRACTS.md 严重不完整

- **位置**：`governance/CONTRACTS.md`
- **问题**：仅覆盖 Admin API Prefix、Commission Contract 等基础内容，Device API、Order API、Payment API、DMS API 等核心契约全部缺失
- **影响**：前后端开发缺乏统一契约参考，跨仓库变更容易不一致
- **修复**：补充 Device/Order/Payment/Member Auth/DMS 五大核心契约

### P1-03：order 模块同时混用 OrderStatusEnum 和 OrderInfoEnum

- **位置**：`OrderApiImpl.java`、`AppStoreOrderServiceImpl.java`
- **影响**：同一模块内混用两套语义不一致的枚举，维护困难
- **修复**：order 模块内部统一使用 `OrderStatusEnum`，清理 `OrderInfoEnum` 引用

### P1-04：DMS 调用缺乏熔断/重试/超时配置

- **位置**：`yshop-module-device-biz/.../HttpClientUtils.java`
- **影响**：DMS 服务异常时会拖垮下单链路
- **修复**：引入 Resilience4j 或 Sentinel 实现熔断降级

### P1-05：RevenueJob 中 @TenantIgnore 被注释掉

- **位置**：`yshop-module-store-biz/.../RevenueJob.java:33`
- **影响**：收入统计定时任务可能仅统计当前租户数据，若系统触发则结果为空
- **修复**：确认执行方式，若需跨租户统计则取消注释

### P1-06：测试覆盖率不足

- **现状**：backend 共 ~62 个测试文件，但核心模块（order/pay/device）覆盖率可能低于 60%
- **DMS**：23 个测试文件，需验证是否达到 80% 要求
- **修复**：为核心业务逻辑补充单元测试，尤其是支付回调、订单状态机、佣金计算
