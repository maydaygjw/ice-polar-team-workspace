# 前端开发质量报告

**报告日期**：2026-06-02
**报告人**：frontend-agent + miniapp-agent（联合审查）
**范围**：admin/ (yshop-drink-vue)、miniapp/ (icepolarminiapp)

## 一、执行摘要

本次审查覆盖 Vue3 Admin 后台（~831 个文件）和原生微信小程序（13 个页面）。共发现 **P0 级问题 7 个、P1 级问题 13 个、P2 级问题 12 个**。Admin 侧核心风险是**硬编码 RSA 私钥**和**XSS 攻击面**；小程序侧核心风险是**DMS 直连违规**和**Mock 登录代码残留**。

## 二、Admin 后台 (Vue3) 问题

### P0-01：硬编码 RSA 私钥（严重安全漏洞）

- **位置**：`admin/src/utils/jsencrypt.ts:5-17`
- **问题**：RSA 私钥直接硬编码在前端源码中
- **代码片段**：
  ```typescript
  const privateKey =
    'MIIBVAIBADANBgkqhkiG9w0BAQEFAASCAT4wggE6AgEAAkEAqhHyZfSsYourNxaY...'
  ```
- **影响**：任何人从构建产物中提取此密钥即可解密所有用它加密的密码，前端加密完全失效
- **修复**：
  1. 立即轮换生产环境 RSA 密钥对
  2. 私钥绝对不允许放在客户端，仅服务端持有
  3. 如需客户端加密，运行时从服务端获取公钥
  4. 优先使用 HTTPS 传输安全，而非客户端加密

### P0-02：dangerouslyUseHTMLString 渲染后端错误消息

- **位置**：`admin/src/config/axios/service.ts:162`
- **代码片段**：
  ```typescript
  ElMessage.error({
    message: errorMessage,
    dangerouslyUseHTMLString: true
  })
  ```
- **影响**：后端错误消息直接作为 HTML 渲染，攻击者可注入恶意脚本（XSS）
- **修复**：移除 `dangerouslyUseHTMLString`，或使用 DOMPurify  sanitize 后再渲染

### P0-03：17 处表单校验未检查 validate() 返回值

- **位置**：分散在 17 个 Vue 组件中
- **问题**：`await formRef.value.validate()` 未捕获或未检查返回值，无效表单可能继续提交
- **修复**：统一封装校验方法：
  ```typescript
  const valid = await formRef.value.validate().catch(() => false)
  if (!valid) return
  ```

### P1-01：255 处 `any` 类型滥用

- **位置**：全仓库散布，核心在 `config/axios/index.ts`、`hooks/web/useTable.ts`
- **影响**：完全绕过 TypeScript 编译期检查，字段拼写错误、类型不匹配均无法发现
- **修复**：
  1. 为 `request()` 定义严格接口：`interface RequestOption<T> { url: string; method?; data?: T; ... }`
  2. `useTable` 泛型默认从 `any` 改为强制传参 `<T>`
  3. 逐步清理 255 处 `any`，优先处理 API 层和表单层

### P1-02：手动 Tenant Header 注入散落多处

- **位置**：`MerchantDetailsForm.vue` 等
- **问题**：tenant-id 在业务组件中手动拼接，而非统一 interceptor 注入
- **修复**：所有 API 请求统一走 axios interceptor，禁止业务代码手动构造 tenant-id header

### P1-03：Permission Store 静默吞没错误

- **位置**：`admin/src/store/modules/permission.ts:34-57`
- **问题**：Promise constructor 内使用 async executor，错误被静默吞没
- **修复**：改为标准 async/await + try/catch

### P1-04：User Store 直接修改缓存对象

- **位置**：`admin/src/store/modules/user.ts:67-79`
- **问题**：`wsCache.get()` 获取的对象被直接修改后 set 回缓存，存在共享引用风险
- **修复**：cloneDeep 后再修改，增加 null check

### P2-01：189 处 console.log 生产环境泄漏信息

- **位置**：全仓库，包括 `console.log('tenantId:', tenantId.value)` 泄漏租户信息
- **修复**：Vite 构建配置 `esbuild.drop: ['console']` 自动移除生产环境日志

## 三、微信小程序 问题

### P0-04：DMS 直连违规（架构红线）

- **位置**：`miniapp/pages/device-detail/device-detail.js:67-68, 164-165`
- **代码片段**：
  ```javascript
  wx.request({
    url: `${DMS_BASE_URL}/api/v1/devices/${imei}/status`,
    method: 'GET',
  })
  wx.request({
    url: `${DMS_BASE_URL}/api/v1/commands/${imei}/${type}`,
    method: 'POST',
  })
  ```
- **影响**：绕过 backend 权限校验、审计日志、租户隔离，攻击者可直接操控设备
- **修复**：
  1. 删除 device-detail.js 中所有 DMS 调用
  2. backend 新增 `/app-api/device/status/{imei}`、`/app-api/device/command/{imei}/{type}`
  3. 小程序改为调用 backend API
  4. 从 app.js 中移除 `dmsUrl`

### P0-05：Mock 登录代码存在于生产环境

- **位置**：`miniapp/pages/select-cup/select-cup.js:410-455`
- **代码片段**：
  ```javascript
  const mockPhone = '138' + Math.floor(Math.random() * 100000000).toString().padStart(8, '0');
  const userInfo = {
    phone: mockPhone,
    openid: 'mock_openid_' + Date.now(),
    sessionKey: 'mock_session_key'
  };
  app.login(userInfo);
  ```
- **影响**：可绕过微信授权直接"登录"，严重违反安全规范
- **修复**：**立即删除** Mock 登录逻辑

### P0-06：HTTP 明文传输头像

- **位置**：`miniapp/pages/profile/profile.js:390`
- **代码片段**：`url: 'http://yshop-api.holuntech.com/app-api/infra/file/upload'`
- **影响**：头像上传走明文 HTTP，存在中间人攻击风险
- **修复**：统一使用 `config.api.baseUrl`（HTTPS）

### P1-05：27 处 API 请求缺少 fail 处理

- **位置**：payment.js、scan.js、processing.js、orders.js、wallet.js 等
- **影响**：网络异常时用户无感知，页面可能卡死，支付流程尤为危险
- **修复**：所有 `wx.request` 必须添加 fail 回调，或统一使用封装后的 `app.request()`

### P1-06：Token 刷新机制缺失

- **位置**：`miniapp/app.js:179-183`
- **问题**：存储了 refreshToken 但从未使用，401 时直接登出
- **修复**：401 时调用 `/app-api/member/auth/refresh-token`，刷新成功后重试原请求

### P1-07：敏感数据明文存储

- **位置**：`miniapp/app.js:115-126`
- **问题**：accessToken、refreshToken、userInfo 通过 `wx.setStorageSync` 明文保存
- **修复**：AES 加密后再存储，或设置合理过期时间

### P1-08：Tenant ID 多处硬编码

- **位置**：`config/config.js:14`、`profile.js:394`、`refund.js:138`
- **修复**：config.js 统一定义 `tenantId`，`getAuthHeaders()` 自动注入

### P1-09：登录逻辑在 4 个页面重复

- **位置**：scan.js、map.js、profile.js、select-cup.js
- **重复代码**：handleGetPhoneNumber、completeLoginWithPhone、handleLoginSuccess 约 150 行
- **修复**：提取为 `utils/login.js` 统一模块

### P2-02：样式文件过大且重复

- **统计**：scan.wxss 1250 行、orders.wxss 759 行、payment.wxss 731 行
- **修复**：提取通用组件样式到 app.wxss，使用微信小程序 Component 封装

### P2-03：过度依赖 app.globalData

- **统计**：36 处直接访问，userInfo 12 次、deviceImei 11 次
- **修复**：引入 mobx-miniprogram 或自研 Store
