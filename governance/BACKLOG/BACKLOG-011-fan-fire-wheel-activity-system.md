## Problem / Need

当前霸王餐、红包、新店试吃和优惠等校园活动缺少统一的承接方式。活动入口、参与资格、福利群引导和中奖兑奖之间缺乏连续体验，导致：

- 用户难以快速理解活动规则、参与条件和当前状态；
- 不同渠道带来的用户和活动效果难以统一追踪；
- 多个活动可能重复引导用户加入同一校区的福利群，群资源也不易持续运营；
- 中奖用户需要在活动、订单和客服之间反复说明情况，兑奖和退款进度不透明；
- 运营人员缺少统一管理活动、福利群、兑奖审核和活动效果的能力；
- 为了处理潜在兑奖需求，普通参与用户可能被迫提前进入客服流程，增加参与门槛。

需要建设饭火轮统一的活动能力，使用户能够直接进入活动页面，清楚了解并参与活动；运营人员能够持续管理活动和长期福利群；中奖用户能够通过客服完成材料提交、审核和退款，并能查询处理进度。

## Context

- 活动具有短期性，福利群具有长期性；同一校区的多个活动应能够复用长期福利群资源。
- 活动页面需要根据活动状态、用户是否满足下单条件、是否已加入福利群以及兑奖状态，展示合适的下一步行动。
- 参加活动不应强制用户提前绑定微信客服；客服主要承接中奖兑奖、订单售后和活动异常处理。
- V1 以人工开奖和人工审核为主，自动中奖判定、截图识别和复杂营销自动化可后续规划。
- 群成员状态、退款渠道和跨校区参与规则等细节仍需在需求评审阶段确认。

## Acceptance Criteria (Optional)

- [ ] 不同活动入口能够进入统一的饭火轮活动页面，并正确展示对应活动内容和来源。
- [ ] 活动未开始、进行中、已结束或失效时，页面均展示明确状态和可理解的提示。
- [ ] 页面能够根据用户参与资格和福利群状态，提供去下单、加入/查看福利群、去兑奖或查看进度等合适操作。
- [ ] 同一校区的多个活动能够复用长期福利群；群满员或失效时，用户不会继续被引导至不可用群。
- [ ] 用户无需提前绑定客服即可参加活动；中奖后能够进入客服完成身份识别和兑奖处理。
- [ ] 用户能够提交订单信息和中奖材料，并查看审核、退款成功或失败等处理状态。
- [ ] 审核人员能够查看材料、通过或驳回申请并说明原因；同一中奖资格不会被重复退款。
- [ ] 运营人员能够创建、复制、预览、发布和下线活动，管理福利群，并查看访问、下单、入群、兑奖和退款等关键效果。
- [ ] 关键操作和异常处理均可追溯到操作人员和处理时间。
