# Backlog Item Template

## Metadata

| Field | Value |
|-------|-------|
| ID | BACKLOG-{nnn} |
| Title | 一句话描述需求 |
| Status | `draft` / `ready` / `scheduled` / `deferred` |
| Priority | `P0` / `P1` / `P2` / `P3` |
| Created | YYYY-MM-DD |
| Author | 提出者 |
| Tags | 标签，逗号分隔 |

## Problem / Need

描述遇到的问题、痛点或需求。用业务语言，不需要技术细节。

- 当前遇到了什么问题？
- 谁受到了影响？
- 这个问题在什么场景下出现？

## Context (Optional)

帮助理解需求的背景信息。可以是：
- 触发这个需求的业务场景
- 相关的系统现状
- 用户反馈或观察到的行为

## Acceptance Criteria (Optional)

如果需求已经比较清晰，可以列出期望的结果。如果不清晰，留空。

- [ ] 期望结果1
- [ ] 期望结果2
