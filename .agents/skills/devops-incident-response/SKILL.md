# DevOps 故障诊断

本技能供 DevOps Agent 诊断环境故障时使用。执行步骤见下文，具体操作说明和命令见技能内的[故障诊断参考](references/incident-response.md)；不要依赖工作区的其他运维脚本。部署执行不属于本技能范围，按[部署与交接手册](../../../governance/PLAYBOOKS/deployment.md)执行。

基础依赖为 Bash、Git、SSH 客户端和 curl；数据库查询使用技能内 `scripts/query-readonly-db.py`，Python 依赖由技能内 `requirements.txt` 管理。容器排查需要 Docker CLI，Arthas 观测要求目标镜像已包含 Arthas。环境配置仍从工作区 `governance/ENVIRONMENTS/` 加载，不复制到技能目录。

## 诊断流程

1. **界定故障。** 记录环境、请求时间及时区（Asia/Shanghai）、域名、方法和路径、租户及业务标识、客户端状态、脱敏响应和影响范围。信息不足时先用现有证据推进，并说明限制。
2. **确认目标链路。** 使用技能内的 `scripts/load-env.sh` 仅加载目标环境。不要打印环境文件或已加载变量。核实 DNS/入口、代理或 Nginx upstream、进程/容器、健康接口和数据源；必要时排除本机代理影响。不能只凭域名或环境文件名判断环境。
3. **限量采集证据。** 从运行实例确认日志位置，只检索相关时间、URL、业务标识和消息，并覆盖当前及轮转日志。业务异常可能记为 INFO，HTTP 200 也可能包装业务错误，因此不能只筛 ERROR 或仅凭 HTTP 状态判断成功。脱敏凭据、Token、Cookie、个人信息及无关报文。
4. **必要时临时调高日志级别。** 仅限 dev，确认目标实例后通过本机 Actuator 对单个 logger 调级；按技能内参考执行，勿经公网访问，并在结束后将 `configuredLevel` 恢复为 `null`。设置仅对该实例生效，重启后失效。生产诊断不调整日志级别。
5. **证据对齐运行版本。** 确认实际进程/容器、启动参数、profile、制品或镜像摘要、内嵌 commit 和外置配置。确认已部署 commit 后，再对照对应版本代码分析。
6. **只读查询数据库。** 只连接运行实例实际使用的数据源；使用技能内只读查询脚本，查询复现所需字段并保留租户、逻辑删除、状态和权限条件。诊断期间不得执行写操作、DDL、repair 或数据修复。不得在命令行、输出、日志或报告中暴露凭据。
7. **日志不足时观测运行分支。** 有限度使用 Arthas，指定具体类和方法并限制采样次数。不得 redefine 类或改变业务状态。采集后执行 reset 并停止 Arthas。
8. **分类、移交并复验。** 区分已证实事实、假设和缺失证据。Java 后端移交 `backend-agent`，管理后台/H5 移交 `frontend-agent`，DMS 移交 `dms-agent`；路由、网络、进程托管和部署由 DevOps 处理。经授权处置后，按原始请求复验并检查相关日志和副作用。

## 操作边界

- 生产诊断只读。不得触发部署、回滚、迁移、数据修复、凭据轮换、重启或运行期配置变更；整理证据交由有权限的人员处理。
- 诊断时不编写业务代码、跨仓契约或迁移定义；将这些变更交给所属 Agent。
- 不要 `cat` 环境文件，也不要运行 `env`、`printenv`、`set`、完整的 `docker inspect` 或读取 `/proc/<pid>/environ`。
- 未按原始请求复验前，不得报告“已恢复”。

## 移交格式

简要记录以下内容：

- 环境、故障时间及时区
- 影响范围和复现信息
- 已确认的请求链路、运行版本和相关配置
- 脱敏日志证据及只读数据观察
- 已证实事实、待验证假设和缺失证据
- 负责的 Agent 或操作人员及建议后续步骤
- 复验结果和未解决事项

不得包含密码、Token、Cookie、完整密钥或未脱敏个人信息。
