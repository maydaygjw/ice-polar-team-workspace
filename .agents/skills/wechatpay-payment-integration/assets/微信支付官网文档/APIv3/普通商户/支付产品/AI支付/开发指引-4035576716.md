## 2、详细开发指引

商户侧的核心开发工作包括两部分：

下单流程开发：按序进行传统微信支付下单和 x402 协议下单

Skill 开发：声明所用的 AI 支付插件，并根据智能体类型做差异化处理

### 2.1、下单流程说明

#### 2.1.1、 传统微信支付下单

商户需先完成传统微信支付下单流程（Native 或 JSAPI），获取预支付交易会话标识，作为后续 x402 下单的前置依赖。

参考：微信支付标准下单文档（[Native](https://pay.weixin.qq.com/doc/v3/merchant/4012791877.md) / [JSAPI](https://pay.weixin.qq.com/doc/v3/merchant/4012791856.md)）

#### 2.1.2、x402 协议下单

完成传统下单步骤后，需使用x402方式向微信AI支付后台下单，以在智能体内拉起微信AI支付。详见API接口文档。

### 2.2、Skill开发注意事项

#### 2.2.1、判断当前智能体是否支持AI支付

目前推荐在 Skill 中由大模型来判断当前 Agent 是否支持AI支付。

在 SKILL.md 中，需要求大模型先自查本次会话实际可调用的工具列表，判断是否支持微信 AI 支付，若存在任意一个名称包含 weixinpay\_ 的工具即视为支持。

建议直接复制下方示例。如需改写，必须保留「按子串匹配 \+ 存在任意一个即可」的判定条件——不同智能体暴露的支付工具集合与命名前缀不同，若检查某个特定的完整工具名（如 weixinpay\_pay），会在部分智能体上把"支持"误判为"不支持"。

注意

大模型存在幻觉，分支判断无法保证 100% 准确。

SKILL 的 prompt 提示词示例：

```
## 前置检查：当前智能体是否支持微信 AI 支付

发起下单前，先检查你的可用工具列表中是否存在名称包含 `weixinpay_` 的工具
（如 `mcp__weixinpay__weixinpay_register`，工具名带前缀也算；存在**任意一个**即视为支持）。

只以你的工具列表为证据，本文档中提到的工具名不算；无法确认时按「不支持」处理。

- 支持：静默继续本 Skill 的后续流程，不向用户提及本检查。
- 不支持：终止流程且不要发起下单。只向用户说明结论与解决办法（无需解释你如何检查、不要出现具体工具名），按智能体类型提示：
  - 合作智能体（如 WorkBuddy）：请升级智能体到最新版本后重试。
  - 开放智能体（如 OpenClaw / DeepSeek Harness）：请根据 https://skillhub.cn/install/skillhub.md，安装 @tencent-adm/weixinpay-installer。
  - 无法判断类型：请升级智能体或安装微信AI支付插件后重试。
```

#### 2.2.2、根据当前智能体类型，处理分支情况

对于不同的智能体，需要分类处理未安装AI支付工具的情况。

| 智能体类型 | 处理方式 |
| --- | --- |
| 合作智能体（WorkBuddy） | 提示用户升级智能体版本 |
| 开放智能体（OpenClaw/DeepSeek Harness） | 提示将从 SkillHub 下载 微信AI支付 的 Skill |
| 无法判断智能体类型 | 兜底提示：请升级智能体或安装微信 AI 支付插件后重试 |
