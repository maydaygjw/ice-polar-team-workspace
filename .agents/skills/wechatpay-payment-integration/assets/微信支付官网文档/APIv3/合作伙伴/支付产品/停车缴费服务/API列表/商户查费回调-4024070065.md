## 一、回调描述

当微信支付需要获取某笔停车的实时计费信息时，会向商户预先配置的查费接口地址发起查询请求。商户需根据请求中的停车单信息，返回当前费用、停车状态、支付状态等交易信息。

回调地址设置方式：回调地址通过商户进件信息的「查询缴费信息接口url」（parking\_info\_scv\_url）设置，回调地址的设置规范和回调IP列表请参考文档：[回调通知注意事项](https://pay.weixin.qq.com/doc/v3/partner/4012082570.md)。

注意

- parking\_info\_scv\_url 字段在服务商进件时配置，不在查费 API 里，签名时需要使用该字段；

- 连接超时 2 秒、读写超时 3 秒、code 非 SUCCESS 均视为查费失败；

- 返回的 parking\_state、pay\_state 及费用字段须与商户系统内该停车单的真实状态一致。


## 二、回调处理步骤

### 1、服务商接收回调通知报文

微信支付会通过POST的方式向回调地址发送回调报文，回调通知的请求主体中会包含JSON格式的通知参数，具体的通知参数列表如下：

通知参数

| 参数名 | 类型 | 必填 | 描述 |
| --- |  --- | --- | --- |
| id | string(36) | true | 【通知ID】回调通知的唯一编号。 |
| create_time | string(32) | true | 【通知创建时间】回调通知创建的时间，遵循rfc3339标准格式，格式为yyyy-MM-DDTHH:mm:ss+TIMEZONE，yyyy-MM-DD表示年月日，T出现在字符串中，HH:mm:ss表示时分秒，TIMEZONE表示时区(+08:00表示东八区时间，领先UTC 8小时，即北京时间)。例如2015-05-20T13:29:35+08:00表示，北京时间2015年5月20日13点29分35秒。 |
| event_type | string(32) | true | 【通知类型】固定为 PARKING\_FEE.QUERY\_TRANS\_INFO。 |
| resource_type | string(32) | true | 【通知数据类型】固定为 encrypt-resource。 |
| resource | object | true | 【通知资源数据】通知资源数据，json格式，见示例 |
| resource.algorithm | string(32) | true | 【加密算法类型】回调数据密文的加密算法类型，目前为AEAD\_AES\_256\_GCM，开发者需要使用同样类型的数据进行解密。 |
| resource.ciphertext | string(1048576) | true | 【数据密文】Base64编码后的回调数据密文，商户解密时需用Base64解码，参考[如何解密证书和回调报文](https://pay.weixin.qq.com/doc/v3/merchant/4012071382.md)。 |
| resource.associated_data | string(16) | false | 【附加数据】参与解密的附加数据 |
| resource.nonce | string(16) | true | 【随机串】参与解密的随机串。 |
| resource.original_type | string(64) | true | 【原始回调类型】加密前的对象类型为 parking\_fee。 |
| summary | string(64) | true | 【回调摘要】固定为 停车缴费查询交易信息。 |

查费请求通知示例

```
{
  "id": "EV-2018022511223320873",
  "create_time": "2015-05-20T13:29:35+08:00",
  "resource_type": "encrypt-resource",
  "event_type": "PARKING_FEE.QUERY_TRANS_INFO",
  "summary": "停车缴费查询交易信息",
  "resource": {
    "algorithm": "AEAD_AES_256_GCM",
    "ciphertext": "...",
    "associated_data": "parking_fee",
    "nonce": "...",
    "original_type": "parking_fee"
  }
}
```

### 2、回调验签与应答

服务商接收到回调通知报文后，需在5秒内完成对报文的验签，并应答回调通知。

#### 2.1、对回调通知进行验签

回调报文的HTTP请求头中会包含报文的签名信息，用于后续验签，具体如下：

| 参数 | 描述 |
| --- | --- |
| Wechatpay-Serial | 验签的[微信支付平台证书](https://pay.weixin.qq.com/doc/v3/partner/4012073044.md)序列号/[微信支付公钥](https://pay.weixin.qq.com/doc/v3/partner/4012925323.md)ID |
| Wechatpay-Signature | 验签的签名值 |
| Wechatpay-Timestamp | 验签的时间戳 |
| Wechatpay-Nonce | 验签的随机字符串 |

验签需使用请求头中的【Wechatpay-Timestamp】、【Wechatpay-Nonce】以及请求主体中JSON格式的通知参数构建出验签串，然后使用【Wechatpay-Serial】对应的[微信支付平台证书](https://pay.weixin.qq.com/doc/v3/partner/4012073044.md)/[微信支付公钥](https://pay.weixin.qq.com/doc/v3/partner/4012925323.md)对验签串和【Wechatpay-Signature】进行验签，确保接收的回调内容是来自微信支付。

商户可通过HTTP头"Wechatpay-Serial"中的证书序列号判断选择对应的证书验签，微信支付公钥的序列号固定采用"PUB\_KEY\_ID\_数字串"格式（例如：PUB\_KEY\_ID\_3000000001），若请求头中的序列号不符合该格式，则应使用平台证书进行验签。

详细验签步骤请参考：[如何验证签名](https://pay.weixin.qq.com/doc/v3/partner/4012365870.md#2.-%E4%BB%80%E4%B9%88%E6%97%B6%E5%80%99%E9%9C%80%E8%A6%81%E9%AA%8C%E7%AD%BE%EF%BC%9F%E5%A6%82%E4%BD%95%E9%AA%8C%E7%AD%BE%EF%BC%9F)

微信支付会在极少数通知回调中返回以“WECHATPAY/SIGNTEST/”开头的错误【Wechatpay-Signature】，以检测商户系统是否正确验证签名。服务商请参考：[如何应对签名探测流量](https://pay.weixin.qq.com/doc/v3/partner/4013059017.md#%EF%BC%881%EF%BC%89%E8%AF%B7%E5%90%88%E7%90%86%E5%BA%94%E5%AF%B9%E7%AD%BE%E5%90%8D%E6%8E%A2%E6%B5%8B%E6%B5%81%E9%87%8F)进行处理。

#### 2.2、对回调通知进行应答

商户处理查费请求后，须返回 HTTP 状态码 200，响应包体为 JSON，且须在响应头 `Authorization` 中携带商户签名（ `WECHATPAY2-SHA256-RSA2048`）。

签名步骤可参考：[如何签名](https://pay.weixin.qq.com/doc/v3/partner/4012365864.md)。

查费成功时，除 code、message 外，标注为「必填」的字段均须返回。

| 参数名 | 类型 | 必填 | 描述 |
| --- |  --- | --- | --- |
| code | string(32) | true | 【返回码】成功返回 SUCCESS，失败返回 FAIL |
| message | string(254) | true | 【返回信息】失败时返回具体失败原因；成功时可返回空字符串或固定成功文案 |
| total_amount | int64 | true | 【当前入场单的总费用】单位为分 |
| parking_timestamp | uint64 | true | 【已停时长】秒级时间戳，如 1 小时传 3600 |
| parking_state | string | true | 【停车状态】停车状态<br><ul><li>`PARKING_STATUS_PARKING`（停车中）</li><li>`PARKING_STATUS_NOT_PARKING`（非停车中）</li></ul> |
| pay_state | string | true | 【支付状态】支付状态<br><ul><li>`PAY_STATUS_UNPAID`（未支付）</li><li>`PAY_STATUS_PAID`（已支付）</li></ul> |
| allowed_exit_timestamp | uint64 | false | 【免费待出场时间】秒级时间戳 |
| next_raise_price | int64 | false | 【下一次跳价的价格】单位为分 |
| next_raise_timestamp | uint64 | false | 【下一次跳价的时间】秒级时间戳 |
| payable_amount | int64 | true | 【当前应付费用】单位为分 |
| paid_amount | int64 | true | 【已支付费用】单位为分 |

查费成功应答示例

```
{
  "code": "SUCCESS",
  "message": "",
  "total_amount": 1500,
  "parking_timestamp": 3600,
  "parking_state": "PARKING_STATUS_PARKING",
  "pay_state": "PAY_STATUS_UNPAID",
  "allowed_exit_timestamp": 900,
  "next_raise_price": 2000,
  "next_raise_timestamp": 1719132575,
  "payable_amount": 1500,
  "paid_amount": 0
}
```

查费失败应答示例

```
{
  "code": "FAIL",
  "message": "停车单不存在"
}
```

多笔支付场景说明

同一停车单可能存在多次部分支付（例如场内预缴、出场前补缴）。商户返回费用字段时须遵循：

| 字段 | 多笔支付时的含义 |
| --- | --- |
| paid\_amount | 该停车单已累计支付的总金额（所有支付渠道合计） |
| payable\_amount | 当前仍需支付的金额，一般为 total\_amount - paid\_amount（已触达封顶或全免场景可为 0） |
| total\_amount | 按当前计费规则算出的累计应收总额（含已付 \+ 未付部分） |
| pay\_state | 当 paid\_amount >= total\_amount（或商户侧判定已结清）时返回 PAY\_STATUS\_PAID，否则返回 PAY\_STATUS\_UNPAID |

#### 2.3、微信支付回调处理机制说明

商户系统不能仅依赖接口返回结果获取查费结果，需结合查询接口使用，避免遗漏或延迟问题。

微信支付接收到商户的应答后，会根据应答结果做对应的逻辑处理：

若商户应答处理成功，微信支付将不再重复发起该查费请求。若因网络或其他原因，商户收到了重复的请求，请做好幂等设计。

对后台请求交互时，如果微信收到商户的应答不符合规范、3 秒内未返回有效应答或 code 不等于 SUCCESS，微信认为查费失败。

本接口为同步查费，单次 HTTP 等待应答，不会重复重试，重复请求可按 id 或 out\_serial\_number 做幂等处理，返回当前最新查费结果。处理请求须先验签，再解密 resource.ciphertext 获取业务参数。

### 3、对回调通知内容进行解密

为了保证业务信息的安全性，微信支付将业务信息进行了AES-256-GCM加密，并通过参数resource将加密信息回调给服务商，服务商需要进行解密后才能获取到业务信息。

解密步骤如下：

1. 获取服务商平台上设置的APIv3密钥，设置APIv3密钥可参考文档：[APIv3密钥设置方法](https://kf.qq.com/faq/180830E36vyQ180830AZFZvu.html)；

2. 通过回调通知参数resource.algorithm确认加密算法（目前仅支持AEAD\_AES\_256\_GCM，算法的接口细节，请参考：[rfc5116](https://datatracker.ietf.org/doc/html/rfc5116)）。

3. 使用APIv3密钥与回调通知参数resource.nonce和resource.associated\_data，对数据密文resource.ciphertext进行解密，最终可得到JSON格式的业务信息。


解密示例代码可参考文档：[如何解密回调报文](https://pay.weixin.qq.com/doc/v3/partner/4012082320.md)

注意

- 使用Java进行回调解密，取JSON串内的参数值时，只需取引号内的内容进行解密。例："nonce":"123"，只需取值123，不用取加上引号的"123"。


resource中ciphertext解密后字段

| 参数名 | 类型 | 必填 | 描述 |
| --- |  --- | --- | --- |
| out_serial_number | string(64) | true | 【商户停车单号】与同步入场时传入的 out\_serial\_number 一致。 |
| plate_number | string(16) | false | 【车牌号】国内车牌,省份简称 \+ 6~7 位字母或数字（新能源绿牌 8 位）。 |
| out_parking_id | string(64) | false | 【商户停车场ID】车场内部自己的停车场 ID，不是微信分配的 parking\_id。 |

对resource中ciphertext进行解密后，得到查费的业务参数示例

```
{
  "out_serial_number": "PARK20260423001",
  "plate_number": "粤B12345",
  "out_parking_id": "lot_sz_tencent_001"
}
```
