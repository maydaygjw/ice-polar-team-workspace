## 1、开发前准备

### 1.1、设置安全联系人

微信支付日常安全监测发现技术异常时，会向安全联系人和超级管理员发送风险提醒。请商户超级管理员尽快设置技术同事为安全联系人，确保能及时接收异常信息评估业务风险，详见[安全联系人设置指引](https://pay.weixin.qq.com/doc/v3/partner/4012083124.md)。

### 1.2、熟悉微信支付接口规则

正式进入开发前，开发者需要先阅读[基本规则](https://pay.weixin.qq.com/doc/v3/partner/4012081726.md)、[开发参数申请和配置](https://pay.weixin.qq.com/doc/v3/partner/4012081990.md)了解调用微信支付接口的基本规则和签名规则。

### 1.3、准备开发参数

在发起接口请求时，开发者还需传入一些必要参数，如服务商商户号、子商户号（也叫特约商户号）、sp\_appid、证书私钥、公钥等，获取方式详见：[服务商模式开发必要参数说明](https://pay.weixin.qq.com/doc/v3/partner/4013080340.md)。

## 2、整体业务开发流程概览

- 服务商在后端调用[Native合单支付下单](https://pay.weixin.qq.com/doc/v3/partner/4012758240.md)接口获取二维码链接(code\_url)后，然后由前端将二维码链接转换为二维码图片展示给用户，用户微信扫描二维码拉起支付收银台。

- 当用户在收银台完成支付后点击完成按钮，微信支付会给服务商后端发送[合单订单支付成功回调通知](https://pay.weixin.qq.com/doc/v3/partner/4013462250.md)，如果服务商后端未收到支付回调可以调用[查询合单订单API](https://pay.weixin.qq.com/doc/v3/partner/4013462240.md)，并根据查询的订单状态进行相应的业务逻辑处理（在前端向用户展示查询到的订单支付状态、在服务商内部系统更新订单状态等）。具体的支付回调和查单的实现方案，服务商可以参考[支付回调和查单实现指引](https://pay.weixin.qq.com/doc/v3/partner/4012082568.md)。

- 最后服务商可通过[下载交易账单](https://pay.weixin.qq.com/doc/v3/partner/4013462343.md)进行对账。需要退款的订单，也可调用[申请退款接口](https://pay.weixin.qq.com/doc/v3/partner/4013462256.md)完成退款。

## 3、详细步骤说明

### 3.1、商户下单

服务商通过调用[Native合单支付下单API](https://pay.weixin.qq.com/doc/v3/partner/4012758240.md)接口生成订单并获取二维码链接 `code_url`，随后将该 `code_url` 传递至前端，由前端将其转换为二维码图片展示给用户。

```mermaid
sequenceDiagram
  autonumber
  actor p0 as 用户
  participant p1 as 服务商前端
  participant p2 as 微信支付系统
  participant p3 as 服务商后端
  p0->>p1: 用户下单
  p1->>p3: 发送下单请求
  p3->>p2: 调用Native合单支付下单接口
  p2-->>p3: 下单成功返回code_url
  p3-->>p1: 转换为二维码图片前端展示
```

下单接口关键参数说明：

`combine_appid`：合单服务商商户号 `combine_mchid` 绑定的 `appid`，具体参考[合单支付-商户号绑定APPID操作说明](https://pay.weixin.qq.com/doc/v3/partner/4013462628.md)。

`combine_mchid`：合单服务商商户号，具体请参考[服务商模式开发必要参数说明](https://pay.weixin.qq.com/doc/v3/partner/4013080340.md)。

`sub_order.mchid`：服务商商户号，此处与 `combine_mchid` 保持一致。

`sub_order.sub_mchid`：子商户号(子单参与方)，由服务商为子商户进件后获取，具体请参考[服务商模式开发必要参数说明](https://pay.weixin.qq.com/doc/v3/partner/4013080340.md)。

`sub_order.sub_appid(非必填)`：服务商为子商户 `sub_order.sub_mchid` 配置的 `appid`，具体参考[合单支付-商户号绑定APPID操作说明](https://pay.weixin.qq.com/doc/v3/partner/4013462628.md)。

`time_expire`：支付结束时间。若传递该参数，则用户只能在订单设置的支付结束时间 `time_expire` 之前进行支付，超过支付结束时间后，用户支付将收到："订单已超过商户设置的最晚支付成功时间，请重新发起支付"的提示，服务商需对订单进行关单处理。若不传该参数，默认订单支付有效期为7天，用户可在7天内进行支付，超出7天，订单将被关闭。

`code_url`：二维码链接。此URL用于生成支付二维码，然后提供给用户扫码支付。 `code_url` 有效期为2小时，超过2小时，服务商需要使用原下单参数重新请求下单接口，获取新的 `code_url`。

`profit_sharing`：订单分账标识，如果订单在支付成功后需要进行分账，必须传参数值为 `true`。如果无需分账，可以不传该参数，或传 `false`。

### 3.2、用户扫码调起支付

用户通过微信扫一扫，扫服务商前端展示的支付二维码图片来调起微信收银台。具体请参考[Native调起支付](https://pay.weixin.qq.com/doc/v3/partner/4012166843.md)

注意：

二维码不支持通过相册识别或长按识别二维码的方式完成支付

```mermaid
sequenceDiagram
  autonumber
  actor p0 as 用户
  participant p1 as 服务商前端
  participant p2 as 微信支付系统
  participant p3 as 服务商后端
  p0->>p2: 用户打开微信扫一扫
  p2->>p1: 扫描商户前端展示的二维码图片
  p1->>p2: 拉起微信收银台
```

### 3.3、用户支付

用户在微信收银台完成支付/取消支付，服务商后端则需要轮询调用[查询合单订单API](https://pay.weixin.qq.com/doc/v3/partner/4013462240.md)接口获取订单状态，并根据订单状态向用户展示支付结果。

同时，如果用户支付成功，微信支付系统会向服务商发送[合单订单支付成功回调通知](https://pay.weixin.qq.com/doc/v3/partner/4013462250.md)。未收到回调时，服务商也可调用[查询合单订单API](https://pay.weixin.qq.com/doc/v3/partner/4013462240.md)接口确认订单状态。具体实现方案商户可以参考[支付回调和查单实现指引](https://pay.weixin.qq.com/doc/v3/partner/4012082568.md)。

若服务商需要限制用户支付的时间，有以下两种方式：

1、下单时通过 `time_expire` 参数，设置订单的支付结束时间，超过设置的结束时间后，服务商进行关单处理。

2、服务商在自己的系统内进行倒计时，超过有效期，进行关单处理。

若因特殊原因需在用户可支付时间范围内关闭订单，服务商可通过调用[查询合单订单API](https://pay.weixin.qq.com/doc/v3/partner/4013462240.md)接口确认订单状态（请勿使用非合单支付的查单接口查询合单订单），若订单仍是未支付状态，服务商可以调用[关闭合单订单API](https://pay.weixin.qq.com/doc/v3/partner/4013462247.md)接口关单（关闭整个合单订单，而非关闭单个子单），关单后可以将订单当作失败终态处理。

```mermaid
sequenceDiagram
  autonumber
  actor p0 as 用户
  participant p1 as 服务商前端
  participant p2 as 微信支付系统
  participant p3 as 服务商后端
  p1->>p3: 轮询获取订单状态
  p3-->>p1: 订单状态
  p1->>p0: 给用户展示订单支付结果
  alt 支付成功
    p2->>p3: 支付成功回调通知
  end
  alt 未收到支付成功回调
    p3->>p2: 调用查询合单订单接口轮询查单
    p2-->>p3: 订单状态
    alt 超过一定时间查单仍是未支付状态
      p3->>p2: 调用关闭合单订单接口
      p2-->>p3: 关单结果
      p3->>p3: 订单当作失败终态处理
    end
  end
```

### 3.4、商户对账

合单支付的订单账单是以子单为维度，每笔子单都会记录在账单内。详细参考：[账单产品介绍](https://pay.weixin.qq.com/doc/v3/partner/4013080592.md)

### 3.5、订单退款

合单支付的订单退款，无法通过合单商户订单号 `combine_out_trade_no` 退款，只能根据单个子单进行退款。详细参考：[退款产品介绍](https://pay.weixin.qq.com/doc/v3/partner/4013080622.md)

## 4、合单支付订单状态流转图

```mermaid
stateDiagram-v2
  state "sub_orders.trade_state:NOTPAY (未支付)" as S0
  state "sub_orders.trade_state:SUCCESS (支付成功)" as S1
  state "sub_orders.trade_state:CLOSED (已关闭)" as S2
  [*] --> S0 : 服务商调用Native合单支付下单接口生成订单
  S0 --> S1 : 用户支付成功
  S0 --> S2 : 7天内服务商可对未支付的订单调用关闭合单订单接口
  S0 --> S2 : 订单超过7天未支付，微信侧进行自动关单
  S0 --> S0 : 用户支付失败
  S1 --> [*]
  S2 --> [*]
  note: 常见支付失败原因有：余额不足、用户风控、支付密码错误、超过服务商设置的最晚支付时间(即下单设置的time_expire)等
```

1、服务商调用[Native合单支付下单](https://pay.weixin.qq.com/doc/v3/partner/4012758240.md)接口下单成功后，服务商可以调用[查询合单订单](https://pay.weixin.qq.com/doc/v3/partner/4013462240.md)接口来确认订单状态，详情请参考[支付回调和查单实现指引](https://pay.weixin.qq.com/doc/v3/partner/4012082568.md)。

2、当订单状态处于未支付(sub\_orders.trade\_state：NOTPAY)时，用户可对订单进行支付，若用户支付失败，订单状态不变。

3、7天内服务商可对无需继续支付的订单（例如用户超过服务商系统内部规定的支付时间，或超过服务商下单设置的最晚支付时间（time\_expire）的订单）调用[关闭合单订单接口](https://pay.weixin.qq.com/doc/v3/partner/4013462247.md)，使订单关闭，或超过7天后由微信侧自动关单。关单后，订单状态会从未支付(sub\_orders.trade\_state：NOTPAY)流转为已关闭(sub\_orders.trade\_state：CLOSED)。

4、当用户成功支付订单时，订单状态会从未支付(sub\_orders.trade\_state：NOTPAY)流转为支付成功(sub\_orders.trade\_state：SUCCESS)。

5、当订单状态为支付成功(sub\_orders.trade\_state：SUCCESS)时，如果用户需要退款，服务商可调用[申请退款接口](https://pay.weixin.qq.com/doc/v3/partner/4013462256.md)(仅支持支付成功后1年内的订单)，退款申请成功后，退款状态可通过[查询退款单接口](https://pay.weixin.qq.com/doc/v3/partner/4013462260.md)进行确认。

6、以下两个状态为终态

- sub\_orders.trade\_state：CLOSED

- sub\_orders.trade\_state：SUCCESS
